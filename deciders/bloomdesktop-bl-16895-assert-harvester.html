What this PR is about

Problem

BL-16895 (PR #8376, already merged) gave a failed Debug.Assert in a Debug-build Bloom a dialog instead of an instant process kill. That change also kept the dialog away from harvester-mode runs and command-line verbs, treating them as automated runs with nobody to answer it. After the merge a reviewer pointed out that the harvester runs a Release build, where the listener does not exist at all. The same is true of the command-line verbs in production. So those two exclusions only ever silenced asserts for a developer debugging one of those modes, who is exactly the person who wants to see them.

What the PR does

  • Removes the harvester-mode and console-mode exclusions from the assert listener. Only end-to-end test runs, the one Debug-build scenario with nobody at the keyboard, still log the assert and carry on without a dialog.
  • In console mode, also writes the assert message and stack to the terminal's error stream before showing the dialog, so a command that has stopped to wait on the dialog does not look like a hang.
  • Rewrites the class comment to say why those modes are not excluded.

Harvester mode is not covered separately: it is only ever set inside two of the command-line verbs, so a harvester run is a console run and gets the same echo and dialog.
