What this PR is about

Problem

The UI language menu at the top right of Bloom is supposed to show a check mark beside the language currently in use. For most languages it shows none. It works for English, español and Bahasa Indonesia, and fails for every language whose display name carries a parenthetical, such as ไทย (Thai) or አማርኛ (Amharic), which is most of the list. Check marks were added in 6.4 and have never worked for these languages, so nothing that once worked is broken.

Cause

The menu button's text is deliberately shortened at the first  ( so it fits, but the menu decided the check mark by comparing that shortened text against each entry's full label. ไทย never equals ไทย (Thai), so nothing was marked.

What the PR does

One line in the React menu (UiLanguageMenu.tsx:78–86): an entry is also checked when its full label is the button text followed by  (. This mirrors the C# shortening in WorkspaceView.cs:1199 exactly, needs no API or backend change, and is deliberately the minimal, low-risk patch for 6.4 just before release. The code comment says so and names the proper fix (compare language tags), which is parked on branch BL-16894-ui-language-checkmark-tag-plumbing for a later version.
