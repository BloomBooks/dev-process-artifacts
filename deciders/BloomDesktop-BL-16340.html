What the change does

Pressing Cancel asks the upload to stop; it notices between stages, which is why a long stage like making the PDF still finishes first. The screen greys out UPLOAD BOOK the moment you press Cancel, and the only thing that un-greys it is C# reporting how things ended. The bug was that sometimes that report never came: the upload ran to completion, published the book, and left the button dead with no way back.

  • The Cancel request queued behind the work it was interrupting. It ran on the UI thread and took Bloom’s global API lock — both busy for minutes during an upload. It now jumps that queue, like Bloom’s other cancel endpoints.
  • A cancel during the two set-up round trips was discarded, because the upload request began by clearing the flag. It is cleared at the true start of an attempt now, and a late upload request declines to run.
  • The screen is always told how things ended, on every route out — success, failure, exception, or the book being rejected before it started.

Two things the review added: a cancel that lands after the book is genuinely on BloomLibrary now reports success rather than claiming cancellation, and the collision dialog’s “different book” button no longer rewrites the book’s identity on disk for an upload it then declines.
