What this PR is about

Problem

App Building and the AI image editor each needed the user to opt in twice. A collection had to be on the Pro subscription tier, and then the user separately had to find Collection Settings → Advanced → Experimental Features and tick a checkbox before the feature appeared anywhere. Until that box was ticked, the Publish tab's Apps button and the picture menu's Edit with AI… command were invisible. Both features are now considered ready, so that second opt-in is just an obstacle — the subscription tier was already doing the real gating.

What the PR does

  • ExperimentalFeatures no longer defines the two flags, and the startup migration clears them out of users' stored settings — the same treatment webView2 got when it went mainstream.
  • The two features' registry entries no longer carry an experimental token, so they are always visible and gated only by the Pro tier. The generic mechanism stays in place for whatever is experimental next.
  • The two checkboxes are gone from the Advanced settings panel, along with the pending-value plumbing that carried them between the WinForms dialog, the settings API, and the React panel.
  • Their two English label strings get opposite treatment in the XLF, because only one will ever be translated. App Builder is marked Obsolete as of Bloom 6.5 and kept — 6.4 has since made that string translatable, so it goes to Crowdin and deleting the id from master would destroy those translations. Edit Images with AI does not exist on Version6.4 at all, has always been translate="no", and appears in no translated file, so it is deleted.
  • The tests that exercised the experimental-token mechanism were written against the App Builder flag; they now use a locally-built FeatureInfo with a token no real feature uses, plus a new test pinning that both features are unconditionally visible.

Net effect for users

The two checkboxes disappear from Collection Settings. The Publish tab's Apps button and the “Edit with AI…” image command now show for everyone, with the existing subscription overlay and badge handling the Pro requirement below that tier.

Worth knowing

  • Nothing here was exercised in a running Bloom. The Advanced tab lost two blocks from the middle of a Config-r group, and two entry points became visible to tiers that never saw them. Both are plausible places for a purely visual defect that no test would catch. This is what the second question opposite is about.
  • The generic ExperimentalFeatureToken mechanism now has no production user — it is kept deliberately for the next experimental feature, and the tests cover it with a synthetic feature. A reviewer may reasonably flag it as dead code; that is the intended answer.
  • For the same reason, PublishTabPane's hidden: !visible check and the aiImageEditingAvailable plumbing into the canvas menu now always evaluate to “shown”. They were left in place on purpose — unwinding them reaches through several files and their tests.
  • The app/enabledExperimentalFeatures API endpoint has no front-end consumer at all. That is pre-existing and untouched here, so the removed tokens broke no caller — worth knowing before someone goes looking.
Should the two entry points stay visible below the Pro tier?
Answered — leave as is. Both entry points stay visible to every tier with the standard subscription overlay and badge, matching how the rest of Bloom's Pro features behave. Recorded for testers in the QA notes on the card, so the greyed “Edit with AI…” entry below Pro is not filed as a bug.

This is the one genuinely user-facing change the card did not spell out. Before: without the experimental checkbox, the Publish tab's Apps button and the picture menu's Edit with AI… command did not exist for anybody, whatever their subscription. Now: both appear for every user; below Pro the Apps screen shows the standard “requires a subscription” overlay, and the menu entry appears greyed with the subscription badge, sending a click to the subscription settings instead of the editor.

So a Basic or Community user who never saw these features will now see two new things they cannot use. That is exactly how every other Pro feature in Bloom already behaves, and it is arguably the point — it is how people discover what a subscription buys. But it is a real change in what non-subscribers see, so it is your call rather than mine.
