2. Devin's one new flag: keeping an app that finished just before you cancelled

FYI — answered

Source: Devin, Investigate — thread on RabProjectService.cs:890–908. Already posted, answered and resolved — listed here only so you can overturn it.

When a build ends abnormally — you cancelled, or it failed — the cleanup keeps a finished app if one was genuinely written, and then records it, so Bloom does not go on telling you a build is needed when a perfectly good app is sitting there. Devin's point is the flip side: that assumes writing the app file is the last thing Reading App Builder does. If RAB ever did more work afterwards, cancelling in that window would leave Bloom saying the app is up to date when it is not quite.

I answered that this is the deliberate side of a trade-off you already made — it exists precisely to answer Devin's earlier "a late cancel leaves Build still showing as needed" flag — that it is guarded three ways (a deliverable location, a readable archive, and written during this attempt), that a truncated file is deleted rather than kept, and that three tests pin all three directions. Worst case after cancelling at the very last instant is one extra Build.

Do you want anything more here?
