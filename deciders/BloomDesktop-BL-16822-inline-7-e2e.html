What this PR is about

Problem

The PRs below this one let a text block hold a picture that its text flows around. Most of what can go wrong with that only shows in a real Bloom: whether the text actually wraps, whether every language's copy of the picture stays in step, what real keys and a real mouse do, and what happens when a person does ordinary things to a book that has such a picture. Unit tests run in jsdom, which lays nothing out.

What the PR adds

  • 50 Playwright tests in 18 spec files that drive a real Bloom, with their helpers in src/BloomE2E/helpers/inlineImages.ts.
  • The feature itself: insert, choose a picture, select, dock, drag down, resize, the Undo button, delete, every language's copy, a save and reload.
  • What people do to books: page size, layout, Change Layout mode, overflow, duplicate page, a language added later, paste, zoom, letting go outside the page, the cover title, image credits, Flip and Reset Image, a picture's shape.
  • The keyboard: Ctrl+Z and Ctrl+Y on picture changes in every language; Ctrl+A then Delete clears the text and leaves the picture.
  • Cropping: a side bar crops every copy, Flip keeps the crop, Undo takes it back, Reset Image removes it, and it is saved.
  • One product change: BloomButton gets a data-testid from its l10n key.

Should the tests choose a picture the way the real chooser does?

Most specs put a real picture into an inline image with changeInlineImagePicture, which skips the native file chooser. It tells Bloom the change cannot be undone (undoable: "false"), where Bloom's real image chooser says it can. So in every test, choosing a picture empties Bloom's undo stack, which never happens to a person. The undo tests all start from that empty stack, and nothing tests that Ctrl+Z or the Undo button takes back choosing a picture.

Switching to "true" makes the choice an undo entry. Some tests would then see it: a second Ctrl+Z, for one, would take back the picture itself. Those tests would need new expectations, and all 18 specs would need another run.
