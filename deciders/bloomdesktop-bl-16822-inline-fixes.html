What this PR is about

Problem

Steve's testing of the merged inline images found four bugs: Backspace at the start of a block's text deleted the picture (and a second press emptied the block); with the Decodable Reader open, choosing a picture or deleting it did nothing; moving one of several pictures also moved a picture on the other side; and a changed picture was not always saved.

Cause

  • BloomField's Backspace guard looked for embedded images only when the page was set up, and ran after CKEditor, whose first Backspace selects the picture.
  • The reader tools rebuild each block from CKEditor's data when the text loses focus, which detached the picture element that the menu held. Their own Ctrl+Z restores a saved copy of the block in the same way.
  • A CSS float cannot start higher than any float before it in the page, so a pushed picture pulled down whatever came after it, on either side.
  • CKEditor saves its own copy of each image's file name from when the page loaded (data-cke-saved-src).

What the PR does

  • Backspace and Delete guards that work out at each keystroke whether only protected pictures come before or after the paragraph, run before CKEditor, and block both keys while CKEditor has a picture selected.
  • The rebuild from CKEditor's data, and the reader tools' own undo and redo, keep the live picture elements, minus CKEditor's own attributes. The reader tools' history starts again after every picture change, so it cannot put an old picture back in one language.
  • Floating pictures are ordered in the page by the highest point each can reach, counting pushes; a drag or a resize then puts the others back where they were.
  • Changing a picture updates CKEditor's saved copy of its file name.
  • Unit tests for each, and four e2e specs (Test Case ID 815).
