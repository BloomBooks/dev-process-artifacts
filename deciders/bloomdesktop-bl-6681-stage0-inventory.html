What this PR is about

Problem

Bloom's text boxes are edited through CKEditor 4, a 2015-era, hand-patched, 1.5 MB vendored copy. It has featured in bug reports for years (BL-6681, open since 2018): its asynchronous load races Bloom's own edits so highlights vanish, it swallows cut, copy and paste in ways Bloom cannot intercept or recover from, and it runs one of five uncoordinated Undo mechanisms. The plan is to replace it with our own code and give Bloom a single Undo, in stages, over months, against a moving master.

What the PR does

This is Stage 0: the groundwork that writes down what must not break before anything moves, and prepares the one seam that could not be done as a late one-line change. No user-visible behaviour changes and no CKEditor is removed.

  • The staged plan, the behaviour inventory that serves as acceptance criteria for the whole project, the review findings already verified, a progress log so an interrupted session can resume, a resume skill, and a hand-run live-verification harness, all under docs/retire-ckeditor/.
  • Ten characterization tests pinning the selection helpers that the future CKEditor-free caret anchors will be built on; their <br>-stepping behaviour had no coverage at all.
  • The "record the caret, rewrite the markup, put the caret back" bracket in the keystroke pipeline (what runs when you type with a Decodable or Leveled Reader tool active) is moved, unchanged, into a new module, markupSelectionPreservation.ts, so a later stage swaps four function bodies instead of rewriting the most delicate code in the editor. Master's BL-16717 rule (record the caret only when something might rewrite the box) and its BL-16808 note travel with it.
  • One narrow deliberate difference: on the async markup path, if the editor reports no selection when the caret is re-recorded, the pass now abandons cleanly instead of throwing inside an un-awaited async function.
  • Two misleading comments in toolbox.ts corrected.

Tracked by card BL-16878, a subtask of the umbrella card BL-6681. Base is master: this is 6.6 work. Merged with master rather than rebased, and not to be squashed, because these commits are the base of the project's integration branch BL-6681-ckeditor (PLAN.md §5).

Decisions

1. Two unrelated files were reformatted on the way

Every commit on this branch runs the repo's pre-commit hook, which formats every staged file with Prettier. When master was merged in, two of master's own files came out reformatted: crowdin.yml (its list indentation changed from two spaces to four, 24 lines) and src/content/branding/SIL-Niger/branding.less (3 lines). Neither changes meaning; both are whitespace only. Master's copies are not Prettier-clean under the repo's own config, so any commit that stages them will do the same. Leaving them is recommended: they are harmless, a reviewer can see at a glance that they are whitespace, and restoring them needs a commit that bypasses the hook.

2. Stage 1 (PR #8317) still lives on the integration branch

The plan's integration branch BL-6681-ckeditor existed only because nothing could merge to master until Version6.5 was cut. That branch now exists and this Stage 0 PR targets master directly. Stage 1, the undo stack, is a draft PR into the integration branch and is linked only on BL-6681. Nothing here changes it. Retargeting it to master once this PR merges, and giving it its own card, is recommended: stage PRs straight to master are cheaper than the integration branch and its weekly syncs, which is what the plan did before the constraint.
