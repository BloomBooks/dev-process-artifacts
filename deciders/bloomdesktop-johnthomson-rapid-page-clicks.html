Preflight: a page click made while another page loads

Clicking quickly through the page list could leave the Edit tab on an earlier page than the one clicked last (BL-17173). Fixed, with e2e tests that make a click land during a load on any machine. Bloom now carries no test hook for them: the tests hold the page's load report themselves. Nothing waits on you but your own review.

What this PR is about

Problem

Clicking quickly through the page list can leave the Edit tab on an earlier page than the one clicked last. The nightly e2e test "clicking quickly through five pages in the page list ends on the last one (All Pages)" fails this way from time to time, and a user clicking fast can lose their last click the same way.

Cause

A page click is a save of the page being left, then a page change. While a page is still loading there is no settled page to save, so the Edit tab declined the click, and nothing sent it again.

What the PR does

  • A click declined because another page is loading is remembered (only the latest), and once that page has loaded Bloom goes there through the ordinary save-then-change-page path (JumpToPage).
  • The load under way is never abandoned: an abandoned load could report itself late and be taken for a later load of the same page, whose edits Bloom would then refuse (Devin found this in a simpler version).
  • The click is dropped if the user has left the tab or clicked another page since, and when the AI image editor is about to open on the page that loaded. It survives a reload of that page after a book rename.
  • The page list is told the click is on its way, so All Pages keeps its wait cursor.
  • New e2e spec page-clicks-while-a-page-loads.spec.ts: leaving the Edit tab while a click is remembered, and a click made while the page after a folder-renaming save loads. Its helper clickPageWhileAnotherLoads holds back the first page's load report with the suite's existing holdNextRequest, so the second click always lands during the load, and checks Bloom remembered it.

What changed this run

  • The walkaround's /simplify pass found that the C# test hook (e2e/holdPageLoads) did what the suite's holdNextRequest already does from the test side: a page reports its load with exactly one request. The hook is gone from Bloom; the hold now happens in the test, which is also closer to a slow page (the report goes unanswered, so the page does not start sending its content early).
  • failedRequestsUnder moved to helpers/failedRequests.ts, shared by the two rename specs; the new spec's copy had lost the "asked for by which frame" detail.
  • Devin: a missing load report would have stalled a test for its whole five-minute timeout; the helper now fails after 60 seconds naming the page.
  • Smaller: waitForEditTabSettled uses getEditTabState; the new spec's header no longer claims the quick-click tests always reach a remembered click.
