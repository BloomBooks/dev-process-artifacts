What this PR is about

Problem

Depositors find out that their metadata breaks an archive's requirements only after exporting, from the archive's own validator. ELAR, the first archive to ask for this, wants lameta to catch those problems while the depositor works, and to refuse an IMDI or OPEX export that still has them.

What the PR does

  • Field rules in each archive configuration's fields.json5 (required, required when another field has a value, pattern, length, minimum items, English and translation requirements), checked after each edit.
  • ELAR's own checks run on the IMDI that lameta would export, in a sandboxed hidden window with a time limit. Comments in the generated IMDI lead each finding back to its lameta field.
  • Checks for every archive: contributors with no Person record, and file names that export would rename.
  • A Problems sidebar lists the findings by folder; clicking one opens the field and highlights it until it is fixed. While the sidebar is open, fields show their own problems.
  • Export runs every check when the dialog opens, and an archive configuration can refuse chosen formats while problems remain (ELAR: IMDI and OPEX).
  • Also: distinct qaa..qtz codes for unlisted languages across the project, a log file a user can send with a problem report, and a session form that tabs down its left half, then its right.
