What this PR is about

Problem

In the Image Chooser, a user who searches Openverse or Pixabay, loses their internet connection, and then clicks Use this image got only "Sorry, there was a problem adding the image." Nothing told them that the real trouble was being offline. Bloom also treated the failed download as a bug in itself and reported it as a problem (a toast, or a dialog on alpha builds).

Cause

Bloom downloads the chosen picture in C#. When the download couldn't connect, the exception escaped the request handler and reached Bloom's catch-all for API errors. That catch-all reports any exception as a problem and sends back a generic error, which the dialog shows as the generic message.

What the PR does

  • Bloom now decides whether a download failed because no connection could be made, it timed out, or the connection dropped partway (IsConnectionFailure). A server that answered with an error status, such as a 404, doesn't count.
  • For a connection failure, Bloom logs it and replies "502 Bad Gateway" instead of reporting a Bloom problem (ImageGalleryApi.cs:208). Every other failure takes the same path as before.
  • The chooser turns a 502 into a new localizable message that asks the user to check their internet connection, and it stays open so they can try again (ImageGalleryDialog.tsx:169).

Searching while offline still shows nothing, because that happens inside the bloom-image-gallery package. It's filed separately as BL-17037.

Worth knowing

  • The "Use this image" case was checked in a running Bloom with a faked unreachable picture. The developer has also checked it by hand, disconnecting from the internet just before clicking. It worked as expected with both Openverse and Pixabay.
  • The first click after the connection drops can take a while, because Windows keeps retrying before it gives up, and the chooser shows nothing while it waits. We decided to leave that as it is. The card's round-2 test ideas mention it, so testers don't report it.
  • On a network that is connected but slow, Bloom's download can wait up to its 100-second timeout before the message appears.
