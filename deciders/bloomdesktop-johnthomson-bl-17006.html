What this PR is about

Problem

After typing in one canvas text element (speech bubble, caption, text block), a single click on a different one selects it, but the typing cursor stays in the old one. Typed text lands in the bubble that is no longer selected, and the arrows, Delete and the Layer shortcuts (Ctrl+] and friends) do nothing to the selected one. The same happens after Add child bubble: clicking the parent leaves the cursor in the child.

Cause

A first click on an unselected element deliberately does not move the focus, so that it selects without starting text editing. setActiveElement dropped the focus only when the newly selected element had no visible text, so going from one text element to another left the focus in the old one.

What the PR does

  • When the selection moves to a different element and the focus is inside some other canvas element, Bloom now drops the focus. A second click on the selected bubble still starts typing in it.
  • A new unit test fails without the fix. canvas-layer-order.spec.ts drops its workaround for the bug: its child-bubble test now clicks the parent directly and presses a Layer shortcut, and fails without the fix.
  • An e2e helper fix: closeCanvasElementMenu moves the pointer off the menus before closing them. The submenu library remembers a submenu as open until the pointer leaves its row, even across the menu closing, so the next menu came up with the Layer submenu already covering the Layer row. At the nightly window size this made the layer spec time out.
