Decision · Devin bug, thread open

After a partly‑failed commit, the AI editor panel can become impossible to close

When you commit changes from the AI Image Editor, some pictures may be on the page you have open and others on different pages. If that commit only partly succeeds — one picture on another page couldn't be replaced, say, while one on the current page was — the code deliberately leaves the editor panel on screen so you can read the error, and also asks Bloom to save and re‑think the current page so the change that did land isn't lost.

Those two actions don't survive each other. The panel is attached to Bloom's main window, but everything that operates it — its × button, and the listener that hears from the editor — belongs to the page frame underneath. Re‑thinking the page reloads that frame and throws the operating code away, while the panel itself stays on screen. You are then behind a full‑screen panel whose close button does nothing, and the only way out is to restart Bloom.

This is new on this branch: the save was added so that swaps which landed before a failure are persisted (without it, storage goes stale and a later commit stops matching the page). So simply removing the save is not an option — it would bring back the bug it fixed.

Decision · Devin bug, thread open

A picture's license notes are lost when it is edited with AI

Bloom lets a picture carry both a license type (CC‑BY, say) and free‑text license notes — wording someone typed about how that illustration may be used. When we hand a picture's credits to the AI editor we flatten the license into a single string, and for any license that has a web address we send only the address. The notes never make the trip, and when the edited picture comes back we rebuild a bare license from that address, so the new file is written without them.

What a user would see: they typed notes about how an illustration may be used, ran an AI edit on it, and the notes are simply gone.

There is a second version of the same problem. A picture marked “contact the copyright holder” has no web address, so its notes text becomes the whole license string; coming back, that text isn't recognised as a Creative Commons address and is rebuilt as a custom license — quietly changing the license type.

This is not new today — it came in with the credits round‑trip earlier on this branch, and the branch still strictly improves on what came before it (previously AI‑edited pictures lost all their credits). Fixing it properly means changing the shape Bloom and the editor agree on, which is a change in two repositories.

For your information

A .webp result still loses its credits

The AI editor is allowed to return .webp, and we write credits into a result file using TagLib, which has no WebP support. The write fails, we log it and carry on, and that picture ends up with no embedded credits — the very symptom this card is about, for that one format. Devin has raised this on each of the last three runs; it was assessed and documented as non‑blocking twice before, on the grounds that it is a pre‑existing TagLib limitation rather than anything this branch introduced, and that the failure is logged rather than silent or corrupting.

Whether it matters depends on something I can't determine from this side: whether the editor ever actually produces .webp in practice. If it does, this is a live hole; if it doesn't, it is theoretical.
