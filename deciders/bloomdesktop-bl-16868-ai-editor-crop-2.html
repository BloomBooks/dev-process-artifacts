What this PR is about

Problem

After Edit with AI... puts a new picture on the page, Undo cannot reliably put back what was there. Ctrl+Z does nothing, and the Undo button can bring the old picture back uncropped: a cropped picture returns showing the whole photo, at the wrong shape.

Cause

Ctrl+Z outside a text box reached no undo at all. Text has CKEditor's undo and layout mode has origami's, but a picture change had neither, so only the Undo button could undo it.

A crop is two boxes: the picture, which grows past its frame and slides under it, and the frame, which has the shape of the part that shows. The undo record kept only the picture's box. The frame had meanwhile been reshaped for the new picture, so the sizing code refit the restored picture to the whole image, erasing the crop.

What the PR does

  • Undo puts back the picture's own box (master's rotate-and-flip work already puts back the frame's box and rotation) and tells the sizing code this is not a new image, so the crop survives.
  • Ctrl+Z outside text now does exactly what the Undo button does: it runs the page's one undo stack (#8387). This works in the page frame and in the top window, where the keystroke lands right after the AI Image Editor closes. Text boxes, form fields, dialogs and the AI editor keep their own undo; in layout mode the key stays with origami.
  • The key is matched by the character typed, so Ctrl+Y on a German keyboard and Ctrl+W on a French one are not taken as undo.

Targets master (6.6), not 6.5. Out of scope: a Fill background picture can come back at the wrong scale (BL-16880).
