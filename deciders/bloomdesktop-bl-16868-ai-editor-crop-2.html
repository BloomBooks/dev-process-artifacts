What this PR is about

Problem

After Edit with AI... puts a new picture on the page, Undo cannot reliably put back what was there. Ctrl+Z does nothing, and the Undo button can bring the old picture back uncropped: a cropped picture returns showing the whole photo, at the wrong shape.

Cause

Nothing listened for Ctrl+Z over a picture: text has CKEditor's undo and layout mode has origami's, but an image change had neither.

A crop is two boxes: the picture, which grows past its frame and slides under it, and the frame, which has the shape of the part that shows. The undo record kept only the picture's box. The frame had meanwhile been reshaped for the new picture, so the sizing code refit the restored picture to the whole image, erasing the crop.

What the PR does

  • Undo puts back the picture's own box (master's rotate-and-flip work already puts back the frame's) and tells the sizing code this is not a new image, so the crop survives instead of the frame being refit to the whole picture.
  • Ctrl+Z reaches the image undo in the page frame and the top window, in the Undo button's order: text fields, dialogs and the AI editor first, then layout mode, then a toolbox tool with its own undo, then the picture. Only the page frame listens, not the toolbox frame.
  • Unit tests cover capture and restore on the background and ordinary-picture paths.

Targets master (6.6), not 6.5. Out of scope: a Fill background picture can come back at the wrong scale (BL-16880).
