What this PR is about

Problem

The Fonts tab of the Book Settings dialog didn't list a font the user had set for the ISBN field on the credits page. Other language-independent xmatter fields were missed the same way, so a book could be published with a font the table never mentioned.

Cause

The ISBN field belongs to no language (lang="*"), so a font set for it is saved as a .Credits-Page-style[lang="*"] rule. The regex that reads user-modified font rules accepted only letters and hyphens in the language code. It skipped those rules, and also skipped tags containing digits, such as es-419. The regex that reads each language's default font had the same gap with digits.

What the PR does

  • Both regexes now accept digits, and the user-modified one also accepts *. So the used-fonts scan for publishing counts these fonts too. The default-font regex still never matches "*", which CollectionSettings relies on.
  • The Fonts table gives a font for a language-independent field its own row, labeled (no language), under the current languages. The row links to the first page where such a field has text. An empty field, such as an ISBN field with no ISBN, gets no row.
  • That row doesn't replace the style's font for the book's languages, and it can't be confused with an (all) row for a font every language shares.
  • New string BookSettings.Fonts.NoLanguage, translate="no", in BloomMediumPriority.xlf.
  • The row-building is split out as GetDataRows so it can be unit-tested. Five new tests cover the change.
