What this PR is about

Purpose

When a table's row or column was resized, the overflow marks on its text changed about a second after the mouse was released, and could be wrong in between. Text that didn't fit a row dragged short hung over the row below, and text that fit its cell was marked once a row was dragged taller than the table's own box. This PR makes the marks follow a table as it changes, and makes overflow in a table cell behave like overflow in a split-pane text box.

What the PR does

  • Marks update on every frame of a row or column drag, and right after every table operation (Grow, Hug, adding or removing rows and columns, undo).
  • Text in a table only has to fit its own cell; the table's box and its canvas element are skipped, the boxes above them still count, up to the margin box.
  • Text too big for its cell is cut off at the cell's content edge (in Edit and in published books) and the cell is marked.
  • Moving a canvas element checks its text again when the move ends.
  • The check is fast enough for every frame (about 40 ms for a 34-box table on a fast computer, 150 ms slowed four times): one page-wide pass, one layout for all heights, measure before marking, cached descent measurements.
  • The page's scroll bars are rebuilt only when a box starts or stops fitting, once a drag pauses.
