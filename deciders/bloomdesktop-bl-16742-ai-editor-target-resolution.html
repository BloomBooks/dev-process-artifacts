What this PR is about

Problem

The Bloom AI image editor generated at whatever resolution the picture already had, so an image that arrived small came back small however much of the page it fills. A user who wants a print-quality picture in a full-page slot had no way to say so, and nothing in Bloom told the editor what “big enough” meant for that slot.

What the PR does

Bloom now tells the AI image editor the pixel size each image slot in the book wants. The editor offers it as the Upscale tool’s “Auto” size and uses it for every generation.

  • One place does the arithmetic. A new module answers “how big should an image be for this space”. A paper page wants whatever fills the container at 300 DPI, the sum the image tooltip already did; the tooltip now calls this instead of repeating it.
  • A screen-sized page is measured against the screen this book is published for. A device layout wants the slot’s share of the book’s own BloomPUB image limit, the Resolution setting in Book Settings, since asking for more only makes pixels the publish step discards and asking for less wastes a limit the user raised on purpose. Where that setting cannot be read, the BloomPUB default of 1280 by 720 stands in. The page is fitted inside the screen on both edges, so the two ebook layouts that are not 16 by 9 do not overshoot the short edge.
  • Slots on pages nobody has open. Only the page laid out in the browser can be measured, so the front end writes each container’s share of its page into the HTML whenever a page is saved. That covers Edit-tab saves, every “Edit with AI” launch, and “Update Book”, which visits every page.
  • A background image is measured against its canvas, not its container. A canvas background is the picture of the whole canvas, and a replacement is re-fitted to fill it, while the container covers only as much as the current picture reaches. Measuring the container asked for the size of the old image’s letterbox.
  • The cover’s value survives bringing a book up to date. That rebuilds all xmatter from the template, which used to throw the cover’s share away. It now travels through the data-div and is restored onto the rebuilt container.
  • Books that predate this get no guess. A page not saved since this change carries no fraction, and its slots offer no “Auto” size rather than a made-up one.
  • The tooltip stops giving print advice about screens. On a device layout it drops the print-DPI lines and names the book’s own screen numbers instead. It fetches the setting only on such a page, so a paper page pays for no extra request.

Worth knowing

  • A “contain” background is an upper bound. Only a cover-fit background is re-fitted to fill the canvas; one set to contain is letterboxed inside it. So for those the new canvas measurement asks for slightly more than the picture will finally occupy. That is the right direction, since the replacement’s shape is not known until it exists, and it is stated in the code comment.
  • The raised setting has never been seen reaching an actual screen-size page. In the running Bloom, the test book’s BloomPUB limit was set to 1920 by 1080 and “Edit with AI” was launched; the launch payload carried the new numbers, and the setting was put back afterwards. But that book is A5, so its cover’s 300 DPI target was correctly unaffected, and the larger screen numbers never turned into a larger suggested size on screen. That step needs a device-layout book.
  • Only part of the rest has been seen working by hand. The A5 cover path was exercised in a running Bloom, including surviving a restart. The screen-size layouts, the ebook page sizes, and the background-versus-overlay pairing have not been, and the test ideas on the card say so.
  • This PR is stacked. Its base is #8356, not a version branch. Once that merges, this one needs re-basing onto Version6.5 before it can go anywhere.

A very old cover still loses its measurement

The fix that carries the cover’s measurement through an xmatter rebuild works by saving it alongside the other things Bloom already saves about a cover’s background picture. Those are only saved when the cover’s picture sits in the modern structure. In a book old enough that the cover picture is a plain image with none of that structure around it, nothing is saved, so bringing the book up to date still drops the measurement. The user sees the cover offer no automatic size in the AI image editor until they open and leave the cover page once, after which it comes back and stays. Nothing is lost and nothing is wrong on screen; the cover simply has no suggested size for a while.
