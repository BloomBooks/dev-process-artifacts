What this PR is about

A pseudo-localization sweep found three toolbox tools whose layout breaks when a translation is much longer than the English. Each had a different cause, so each is fixed separately; a new ShrinkTextToFit component serves the first two.

1. The Decodable Reader's "next stage" arrow was pushed off the toolbox

Problem: the "Stage 3 of 15" line and its two arrows could not wrap, so a long translation pushed the right arrow past the edge, worst when the panel shows a vertical scrollbar.

Fix: "of 15" moves below "Stage 3" when needed, each part wraps at spaces, and only a single too-wide word makes the label shrink (to at least 10px). The arrows never shrink. The Leveled Reader's "Level N of M" line is the same component.

2. The Leveled Reader's column headers ran together and were cut off

Problem: Measure / Max / Actual sat in fixed-width columns, so a longer translation overlapped the next header and was clipped at the toolbox edge.

Fix: all sections share one grid (CSS subgrid) so the columns line up; Max and Actual get their headers' width first; when there still isn't room a header wraps, shrinks to 8px, then breaks mid-word. Translator notes on Max and Actual ask for short text. English, Swahili, Hausa and Arabic stay at full size; Russian shrinks and breaks.

3. A long URL in the Image Description tool made the panel scroll sideways

Problem: "poet.diagramcenter.org" is one long word. Fix: it breaks mid-word only when it can't fit on a line of its own. The URL was already its own localizable string, so no translations are affected.
