What this PR is about

Problem

When a user enters a code for a different subscription in Collection Settings, the collection keeps its old Bloom Library bookshelf. Books uploaded afterwards still go to a bookshelf of the previous subscription, which the new subscription may not offer at all.

Cause

The save logic was meant to clear the bookshelf on a subscription change, but it compared the new subscription with itself. The check ran right after the collection's subscription had been replaced, so it was always false.

What the PR does

  • Compares the new code with the original subscription, in both the new Collection Settings dialog (CollectionSettingsUpdater.cs:147) and the legacy WinForms dialog that the Old Settings button still opens (CollectionSettingsDialog.cs:465).
  • Two valid codes count as the same subscription only when their names match exactly. A renewed code keeps the bookshelf; a different subscription clears it, even when its name extends the old one (Fake → Fake-LC). The looser prefix match only applies when one code isn't well-formed, so a mistyped code doesn't lose the bookshelf (the shared rule, also used by the BL-15056 expired-bookshelf recovery).
  • A bookshelf picked in the same session as the new code is cleared too, since the dialog lists the saved (old) subscription's bookshelves.
  • Unit tests cover a different subscription, a valid prefix-related pair, a renewal and a mistyped code. Each one checks the bookshelf both in memory and in the saved file (CollectionSettingsUpdaterTests.cs:447).
