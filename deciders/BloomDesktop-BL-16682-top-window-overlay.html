Which of the two designs do you want to keep?

The branch carries both. This is the decision the comparison was for.

Both designs fix the reported bug the same way — Bloom saves the page before opening the AI Image Tools, so a picture you have just added is actually there to edit. They differ in where the code that carries on after that save lives.

The first commit keeps the tools window inside the page area and adds a small general-purpose hook to Bloom's editing model so that something remembers, across the page reload, to open the window afterwards. The second moves the tools window out to Bloom's outer window, which is where the picture chooser and the copyright dialog already live for exactly this reason — and then the hook is unnecessary and gets removed. The second one also fixes a further bug on the way: replacing a picture twice without closing the tools used to fail the second time. Against that, it is a much larger change, and it is the one you have not yet seen running.

One step in this design has no automated coverage at all: Bloom's C# side reaching into the browser to open the tools window at the moment a page save has just finished and the page is about to reload. If that call were wrong, the symptom would be obvious and harmless — you choose “Edit with AI…”, the page redraws, and no window appears.

What should happen when someone retries a picture replacement that only partly worked?

Open thread — raised by Devin

When the user tells the AI tools to put results into the book, Bloom does the pictures on other pages itself and saves them straight away, and hands the ones on the page currently being edited back to the browser to apply. If that second part fails, the user is told the operation didn't fully succeed — but the other pages have already been changed and saved. If they then simply try again, Bloom redoes those other pages, this time against pictures that have already been replaced, so it fails again and leaves behind unused image files in the book folder.

This is not new to this branch and it isn't a defect in the diff — it is a gap in the agreement between Bloom and the separate AI tools app about what a retry means. I've already made the message honest about which pages were saved, which is what stops someone retrying blindly, and that is why leaving the rest alone is the recommendation: a proper fix means changing the exchange between the two apps, which is a different piece of work with its own card.

Not about this branch — it affects how much any preflight's “CI green” means

The only check reporting to a BloomDesktop pull request is pr-automation, whose actual job is to kick off the Devin review. On this branch that gap is covered, because both full local suites were run — but it will quietly mislead anyone reading a green tick on any PR here.
