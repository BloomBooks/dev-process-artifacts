What changed

Pressing Ctrl+Shift+Space (show hidden characters) in a text box made the cursor jump to the start of the box, because showing and hiding the symbols each rewrite the whole box’s HTML, which destroys the browser selection. The fix saves the caret as a character offset before each rewrite and restores it afterwards, reusing the same EditableDivUtils helpers the reader tools already use around their own HTML rewrites.

  • 81cc16a — the fix: save/restore around the show rewrite (showInvisibles.ts:102, :123) and the hide rewrite (:179, :192)
  • 20ad15c — merge of origin/master (clean)

Verified live in a running Bloom over CDP before preflight: with the fix the caret stays put through show/hide, with and without hidden characters present; temporarily reverting the file reproduced the reported jump-to-start exactly, confirming the test is sensitive to the bug.

Devin’s informational observations

Low-signal by Devin’s own classification — not mirrored to the PR. All three describe properties the fix has on purpose; listed here so you can disagree if you see it differently.

  • A highlighted selection becomes a plain cursor. Restoring by a single offset collapses a non-empty selection to its end point. Before the fix the selection was destroyed outright and the cursor sent to the start, so this is a strict improvement; the helper used is documented as insertion-point-only.
  • The offset math assumes one symbol per hidden character. Correct — and the replacement table guarantees it: every entry swaps exactly one character (or one HTML entity, which is one text character) for one symbol character, in both directions.
  • The blur path relies on the selection having already left the box. Also deliberate: on blur the selection index reads −1, so the code correctly does not yank the selection back into the box the user just left.
