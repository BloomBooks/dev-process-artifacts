What this PR is about

Problem

MeasureText reuses one hidden div to measure a font's descent. After it measured text that started with a newline, every measurement over the next ~2 s came out about a line too big. OverflowChecker subtracts that amount, so up to about a line of real overflow could go unreported.

Cause

The div was seeded by setting innerText to the text's first character. For a newline that inserts a <br>, so the later reuse updated nothing and measured from the wrong element.

What the PR does

  • The div always holds a text node containing the first visible character, so each reuse has a text node to update.
  • Its 2-second cleanup uses remove(), which doesn't throw if the div is already gone.
  • utils/measureText.browser.spec.ts checks measurements after text that starts with a newline or is only whitespace. Those cases fail without the fix.

There's no known user-visible symptom: Bloom's Edit tab strips that whitespace before overflow is checked. Stacked on #8408.
