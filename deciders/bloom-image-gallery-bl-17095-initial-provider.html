What this PR is about

Purpose

The image gallery always opened on Openverse, so someone who normally takes pictures from Art of Reading or Pixabay had to switch sources every time. Bloom now wants to open the gallery on the source the user last accepted a picture from (BL-17095), and the gallery needs a way to be told which source that is.

What the PR does

  • Adds an optional initialProviderId prop. When the gallery opens, it selects that source.
  • Sources arrive one at a time: local collections, and Pixabay after them, come after the host lists its collections. So the gallery waits for the named source, and falls back to the first source, as before, if it never arrives or can't be used yet (Pixabay with no API key).
  • The wait is bounded. After 10 seconds without the host's collection list, the gallery stops waiting and falls back. Collections that arrive later are still listed, and closing the gallery aborts the request.
  • The opening choice is made only once. A file picked from disk while the gallery is still waiting is not replaced when a late source arrives.
  • The rule lives in a small pure function, chooseInitialProvider, with unit tests.

This PR must merge before BloomDesktop's BL-17095 PR, which pins this repo and passes the prop.

Pixabay waits behind the collections request

Pixabay joins the source list only after the host answers the request for its local collections. That's the order on master, and this PR keeps it. If the host never answers, Pixabay never appears, and a gallery told to open on Pixabay falls back to Openverse after 10 seconds. Devin flagged this.

Adding Pixabay before the request fixes that, but brings back another finding from Devin. A local collection that happens to be named "Pixabay" gets the same id as the online source, and the gallery would then hide it. Today the local one wins and the online source is the one hidden. In Bloom, the host answers in milliseconds, and no installed collection is named Pixabay.
