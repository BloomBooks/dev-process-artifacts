What this PR is about

Problem

Bloom's Edit tab has several separate undo histories: CKEditor keeps one per text box, pictures have their own, the reader tools have theirs, and Change Layout mode has origami's. Ctrl+Z in a box undoes only that box, and many edits (moving, resizing or deleting a canvas element, most toolbox changes) cannot be undone at all. PR 8484 replaces them with one undo history for the whole page, built from recorded DOM mutations, but at 221 files it is too big for a person to review.

What the PR does

This is PR 1 of 3 in the re-cut that docs/undo/REVIEW-PLAN.md lays out. All three add the page history as code that nothing in Bloom calls yet, so master's behaviour does not change, and they merge in order: 8520 (engine), 8525 (markup filter), 8526 (input, keys and page readiness).

  • Changes to the page are recorded with a MutationObserver inside transactions. When the outermost transaction ends, its net change becomes one named undo step.
  • Undo and redo put those values back and restore the selection. An undo whose step no longer matches the page is refused and the history is dropped: it loses history but never damages the page. That includes a change made through doOutsideHistory while a transaction was open.
  • A filter interface lets the history leave out markup that exists only while a page is being edited (the filter is PR 8525), and a recorder keeps the history's events for a developer's window.
  • docs/undo/ holds the design notes.
