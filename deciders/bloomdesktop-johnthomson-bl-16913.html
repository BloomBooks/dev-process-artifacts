What this PR is about

Problem

On new Windows 11 machines, where Smart App Control is on by default, installing Bloom can end with "the application install hook failed", and Bloom may not start. Smart App Control refused to load unsigned DLLs such as L10NSharp.dll and DesktopAnalytics.dll, so Bloom crashed during the install hook.

Cause

Smart App Control allows a file only if it is signed by a trusted certificate or Microsoft considers it reputable, and reputation can't be relied on even for long-established files. The build signed only Bloom.exe, BloomPdfMaker.exe and the installer; 102 of 138 installed exes and dlls were unsigned, including Bloom.dll, the third-party tools and Velopack's Update.exe.

What the PR does

  • Velopack now does the signing during vpk pack. It signs every exe and dll that isn't already validly signed, plus the Update.exe, launcher and Setup.exe it adds. Vendor signatures (Microsoft, .NET and others) are kept. connections.dll, a text file of keys, is excluded.
  • The build first checks whether this machine can sign, by signing a throwaway file. The existing rule still applies: a failure is fatal on TeamCity unless OkIfSigningFails=true.
  • The build verifies the result. A new script fails the build if any exe or dll in the installed package, or the installer itself, lacks a valid signature.
  • The old per-exe signing calls are gone. Upload builds refuse to continue if signing didn't happen.
