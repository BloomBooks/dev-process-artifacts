What this PR is about

Problem

Inline (Word-style) images, the feature this stack of PRs builds, need the same right-click menu a canvas element image has. But CanvasElementContextControls both decides which controls to show and draws the menu, and it only works for canvas elements. An inline image is not one, and the canvas element manager knows nothing about it.

What the PR does

  • Moves the drawing of the context menu into its own module, canvasControlMenuRendering.tsx, which the canvas component now calls. The canvas menu looks and behaves exactly as before, including master's fix that closes an open submenu when the menu closes.
  • Lets a caller that is not a canvas element supply its own controls, menu items and an after-command hook. Nothing in this PR uses that yet. The inline image PRs later in the stack do.
  • Treats an element whose picture is a direct child as its own image container, so the menu's commands find the picture in a legacy image or an inline image.
  • Lets a Delete command hand removal to the object itself. If the caller doesn't do that, Delete removes the active canvas element as before.
  • Makes the front-end .prettierignore entries that contain a slash match in the pre-commit hook, which reads them relative to the repo root. Without that, committing the master merge reformatted the generated overflow test fixtures.
