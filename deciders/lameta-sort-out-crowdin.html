What this PR is about

Problem

lameta 3's translations were not reaching translators, and translators' work was not reaching lameta 3. The V3 branch of the Crowdin project had not been synced since March 2024. Most of the 2023–24 move from multilingual CSVs to .po catalogs had never been finished there: new v3 strings were missing, three obsolete CSVs were still listed, and Crowdin downloads landed in locale/pt and locale/zh while the app read locale/pt-BR and locale/zh-cn.

Cause

Crowdin's default two-letter folder naming gives pt and zh, which never matched .linguirc. A runtime folder remap hid the mismatch. There is one Crowdin project, not one per version: v2 still syncs to its root and v3 syncs to the V3 branch. That made it unclear what was safe to touch.

What the PR does

  • On Crowdin, done live on 2026-07-09: current sources uploaded to V3, v2 translations recovered into it, a perfect-match TM pre-translate run, and the three empty leftover CSVs deleted from V3. Nothing at the root (v2) was changed. 280 of 286 UI strings share their v2 translations automatically, 79 field translations came across from the old v2 CSVs, and the 3 CSVs gained 371 cells of translator edits.
  • A full backup of the Crowdin project in crowdin-backup/2026-07-09/, taken before any change on Crowdin.
  • crowdin.yml sends pt-BR and zh-CN downloads to those exact folder names. locale/zh-cn is renamed to zh-CN, and the stale pt and zh folders are gone.
  • scripts/crowdin/ holds reusable tools: backup, a report of true per-language counts, and catalog stats. It also keeps the one-time migration scripts. README-l10n.md documents the workflow.

How should the merge with master be committed?

The PR conflicts with master. I merged master locally and resolved every conflict: master's switch from yarn to pnpm, its new catalog loader in localization.ts, its re-extracted string catalogs, and the README. Typecheck passed, the localization tests passed, and lint found nothing in the branch's own files.

The repo's pre-commit hook (vp staged, which runs vp check) then refused the merge commit. A merge stages every file that master changed, and 20 of master's own e2e files carry 9 type errors, such as properties that are never initialized and a wrong argument count. Those files are byte-identical to master, so this branch did not cause the errors. Any branch that merges master will hit this hook failure.

The resolved merge is saved as git tree 279c2f3, tagged preflight-resolved-merge-tree in this worktree, so it can be committed without redoing the resolution.

Send master's new strings to translators?

Master's code has gained new translatable text since the July sync, and the merged catalogs now hold it. messages.po has 283 strings (about 39 of them new) and fields.po has 162, up from 118. Crowdin's V3 branch does not have these yet, so translators cannot see them and the app shows them in English.

Running vp run strings:sync after the merge uploads them to V3 and downloads the translations back. It writes to the live Crowdin project (the V3 branch only, never the v2 root), so it waits for your go-ahead.
