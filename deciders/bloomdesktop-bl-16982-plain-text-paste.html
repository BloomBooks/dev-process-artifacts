What this PR is about

Problem

Pasting plain text that has more than one line (from Notepad, say) treats anything in it that looks like an HTML tag as a tag. "if a <b and c> d" loses the "<b and c>" and the rest of the line turns bold. A line holding an image tag with an error handler would run script inside Bloom's page. Reproduced in Bloom 6.3.2, so it goes back at least that far.

Cause

For a multi-line plain-text paste, BloomField.reconstituteParagraphsOnPlainTextPaste (BL-9961) rebuilds the paragraphs itself: it reads the raw plain text from the clipboard and wraps each line in <p>, without escaping it. It runs in Bloom's CKEditor paste handler after CKEditor's paste filter, so nothing cleans what it returns.

What the PR does

Each line is HTML-escaped (&, <, >) before it is wrapped, which is what CKEditor itself does for a single-line plain-text paste. The later paste transforms are unaffected. Unit tests cover tag-like text, an ampersand, a would-be live image, and the single-line and HTML pastes the transform leaves alone; the escaping tests fail without the fix.
