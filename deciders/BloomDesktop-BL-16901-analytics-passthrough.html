What this PR is about

Problem

Bloom kept its own copy of the AI Image Editor's analytics vocabulary. It dropped any event name it didn't know, renamed the ones it did, and built its own "AI Image Editor Closed" event out of counts from the commit replies. So every new event in the AI Image Editor needed a matching change in Bloom, and the events it had already added (Open, Accept, Batch Run) never reached Segment.

What the PR does

  • Bloom forwards every event exactly as sent. No name list, no renaming, no added properties, and no session event of Bloom's own. The one Bloom event left is Change Picture (source ai-editor), one per picture that reached the book.
  • The AI Image Editor supplies the rest (bloom-ai-image-tools 0.2.13, now pinned): its events are named AI Image Editor …; every event carries aiImageEditorSessionId and sessionSeconds; Open carries historyItemCount; it sends AI Image Editor Close on cancel (with picturesCommitted) and AI Image Editor Commit Failed when Bloom reports a failed commit.
  • Bloom's close box now asks the AI Image Editor to close (request-close) instead of removing it at once, so its Close event gets sent. If it doesn't answer within two seconds, the overlay closes anyway.
  • bookEdit/aiImageEditor/AGENTS.md says Bloom must not know the AI Image Editor's event vocabulary.

Worth knowing

  • Not exercised in a running Bloom: the ✕ now waits for the AI Image Editor to answer request-close. It's covered by unit tests on both sides, but the real round trip hasn't been clicked through.
  • A relaunch that replaces an open session (opening "Edit with AI…" again while the overlay is up) still tears the old one down without a Close event. That path is rare.

A partly failed commit is counted as keeping nothing

When the user commits several pictures and only some land (C# saved the ones on other pages, but the swap on the open page failed), Bloom answers the commit with a plain "failed". The AI Image Editor can't tell how many landed, so it adds none of them to picturesCommitted. If the user then cancels, its Close event says picturesCommitted: 0, which reads as "kept nothing", although pictures did reach the book (and Bloom's Change Picture events counted them). This only happens when a swap on the open page fails, which is rare.
