What this PR is about

Problem

With the Image Description tool open, adding a page (or switching pages quickly) could raise a "Bloom had a problem" report: Cannot read properties of null (reading 'makeElement').

Cause

When a picture has no image description yet, setupImageDescriptions() asks the server for the new description's content and builds it when the reply arrives. If the Edit tab moved to another page in the meantime, the page frame is loading that page, which has no editing script yet, so the reply crashed. The picture it was for belongs to the page being left.

What the PR does

  • The reply now returns without doing anything when the picture is no longer in the document the page frame shows (imageDescription.tsx:255). The new page still gets its descriptions from its own newPageReady().
  • A new unit test, imageDescription.spec.ts, covers a normal reply and one that arrives after the page changed. Without the fix the second test fails with the reported makeElement error.
  • The hunk matches, byte for byte, the uncommitted change on the BL-16929 side-by-side-editing branch, so the two merge cleanly.
