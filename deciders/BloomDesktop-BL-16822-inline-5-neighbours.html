What this PR is about

Problem

With the PRs below this one, a picture can sit inside a text block, and every language's box in the block holds its own copy of it. Several older parts of Bloom walk the children of a text box, or decide a box is empty by looking only at its text, and each could mishandle a box that holds a picture. A box with a picture and no typing in it has no text at all.

What the PR does

  • Repairing duplicate language boxes no longer throws away a box that holds only a picture, unless another box for the language holds the same picture; then the copy is removed rather than merged in with its empty paragraph. Merging two boxes keeps a shared picture once.
  • The keyboard guard, which uses a browser undo to put back a picture a keystroke deleted, leaves Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z alone. Undoing a picture's insertion removes it on purpose, and a browser undo on top of that would take back the person's last typing. Only the undo key's own keyup is exempt, so a Delete pressed meanwhile, or a Z that repeats after Ctrl is let go, is still caught.
  • Talking Book no longer writes audio markup into the picture.
  • Tests pin three things the feature relies on: source bubbles leave the picture out, the bloom-canvas migration leaves it alone, and publishing one language keeps its image file.
