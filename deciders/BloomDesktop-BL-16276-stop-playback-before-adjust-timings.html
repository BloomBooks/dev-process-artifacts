A limit on the new guard, on legacy pages

Devin noted this as informational on its last pass, and it's accurate, so you should know the guard isn't airtight. The check asks the text box which recording mode it is, and that shared lookup has a long-standing fallback: if the box carries no recording-mode attribute of its own, it takes the answer from the first box on the page that does.

So on a page in a half-migrated state — the current box recorded by sentence but with no attribute, while some other box declares whole-text-box — the guard would answer "yes, adjustable" and the dialog would still open with nothing to show. That's inherited behavior of the existing lookup rather than anything this change introduced, and it needs an older or partially-upgraded book to happen at all.

Recommending it be left alone because the fallback is shared by the whole tool: changing it to be stricter would alter how every part of the Talking Book tool decides a box's mode, which is far too broad a change to ride along with a bug fix.

Should a blocked click say something?

When the guard blocks the click, nothing visibly happens for an instant — then the button greys itself out, which is the explanation. Devin argued for a message instead of silence. I decided against adding one on my own authority, because any new wording is a user-facing string that needs a localization entry, and that is more than a bug fix should carry without you deciding it.

Recommending it be left alone: the button going grey is honest feedback, and the situation only arises on a page that mixes recording modes.
