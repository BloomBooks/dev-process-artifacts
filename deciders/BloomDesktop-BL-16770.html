What this PR is about

Problem

The AI image editor hides its developer/tester tools unless Bloom (the host) asks for them. The only one today is the "Local Dummy (No AI)" model, which lets someone exercise the editor end to end without spending real AI credits. Bloom asked for those tools only on developer and alpha/unstable builds, so a tester running an installed beta — exactly the person we most want exercising this — had no way to try the editor for free.

What the PR does

  • Replaces the bare IsDevOrAlpha launch flag with a new ShouldShowDeveloperTools(). Dev/alpha/unstable builds still get the tools with nothing set.
  • On any other channel a tester opts in by setting BLOOM_AI_IMAGE_EDITOR_TESTER_TOOLS to true, t, y, yes or 1 — case-insensitive and trimmed, because the people setting it are testers typing into the Windows environment-variable box.
  • An ordinary beta or release install, with the variable unset, still shows end users nothing.
  • Adds unit tests for the accepted and rejected spellings, plus one that walks the accepted-values list itself so a value can't be documented without actually working.

An environment variable rather than a UI toggle: nothing here to localize, and no way for a real user to stumble into it.

Worth knowing

  • Nothing here was exercised by hand. The opt-in was verified only by unit tests — no one has actually launched a beta-channel Bloom with the variable set and confirmed the "Local Dummy (No AI)" model appears in the editor's model list. The QA notes on the card ask a tester to do exactly that.
  • Bloom reads the variable from its own process environment, so a tester who sets it in the Windows dialog while Bloom is running must fully close and reopen Bloom before it takes effect. That is stated in the QA notes so it doesn't get filed as a bug.

Decisions — settled

Both questions this report raised were answered on 2026-08-27: keep the variable named BLOOM_AI_IMAGE_EDITOR_TESTER_TOOLS, and leave its discoverability to the QA notes on the card rather than adding it to a document. Neither required a code change, so the branch is unchanged since the report was first published.
