What this PR is about

Problem

The production Parse server logs a steady stream of 500 errors, about 750 a day: $or argument must be a non-empty array. They come from the website. Some collection pages ask Parse for a book count, or for stats, with a query MongoDB rejects. Their count is then blank, or their stats fail.

Cause

A collection with no filter of its own gets one built from its child collections' filters (BL-10187, 2021). When none of those children has a filter either, the website still built an "any of these" filter with nothing in it, and Parse got an empty $or. Two earlier fixes, BL-9742 (book count) and BL-10126 (stats), had made the website skip the query for a collection with no filter. They relied on getting no filter at all, which this code had stopped returning.

What the PR does

  • getFilterForCollectionAndChildren now returns no filter when neither the collection nor any of its children has one. The book count, stats and moderator info widget already treat that as "don't query", so BL-9742's and BL-10126's handling works again.
  • The one caller that combines the result with more conditions, the :language: subset page, uses a filter that matches no books instead. Otherwise it would list every book in the library in that language.
  • As a backstop, constructParseBookQuery turns an empty "any of these" into a condition that matches no books (objectId $in []), rather than an empty $or.
