What this PR is about

Problem

On a monitor scaled above 100%, the screenshot that Bloom 6.5 takes for Report a Problem is much too big. At 200% it is about twice the window's size in each direction: the Bloom window fills only one corner, and the rest is blank or shows other parts of the screen. Bloom 6.4 does not do this.

Cause

6.5 made Bloom PerMonitorV2 DPI aware, so window sizes now come back in real screen pixels. The screenshot code still multiplied them by the monitor's scale factor. That correction was needed only when Bloom was DPI unaware, and it now scales everything twice.

What the PR does

  • The screenshot gets the window's rectangle straight from Windows, in real screen pixels (WindowsMonitorScaling.cs:71). While it measures and copies, the thread is switched to PerMonitorV2 (ProblemReportApi.cs:1184), which keeps the result right even while a dialog opened in the old DPI mode is up.
  • Both ways of taking the screenshot use that rectangle: the screen copy used when Bloom is in front, and PrintWindow, used when another app is in front (ProblemReportApi.cs:1126).
  • The old scale-factor helper is replaced. A separate branch for capturing a child control computed the wrong position and is gone. The screenshot bitmap is now disposed after saving.

Worth knowing

  • Two paths haven't been tried by hand: a screenshot taken while one of the dialogs that use the old DPI mode is open (they are all modal, so it is hard to set up), and a screenshot taken while another app is in front of Bloom.
