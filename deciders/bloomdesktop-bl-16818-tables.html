What this PR is about

Problem

Bloom has no way to lay content out in a grid. Authors who want a vocabulary list with pictures or a simple timetable fake it with positioned text boxes, which drift out of alignment and do not translate as one unit. Tables are a Pro-tier feature, and the people who reuse Pro books, above all to translate them, often have no subscription, so a table has to stay translatable and publishable for them while they are kept from building new ones.

What the PR does

  • The table itself comes from the bloom-table library (grid, menus, resizing, its own undo). Bloom attaches it to each table on the page, supplies the cell contents (a text box, a picture, a video, a nested table) and strips editing markup before save.
  • Two ways in: a Table item in the Canvas tool, and a Table section type in Change Layout.
  • Gating: Pro and the "tables" experimental setting. Below Pro, a table can be filled in and translated but not restructured, and an original book with a table cannot be published.
  • Shared editing code that now knows about tables: Undo picks the table's history or the text's by which changed last, a press on a row or column boundary starts a resize, copy and paste work in a cell, and pictures refit when a cell changes size.
  • After a zoom change, the selected canvas element's toolbar follows the new scale, at most once per 100 ms however many zoom changes arrive.
  • E2E support: a step caption in --e2e runs and an app/runningE2eTests endpoint. Making a go.sh Bloom's dialogs visible to tools moved out to BL-16976.
