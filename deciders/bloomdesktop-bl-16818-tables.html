What this PR is about

Problem

Bloom has no way to lay content out in a grid. Authors who want an alphabet chart, a vocabulary list with pictures, or a simple timetable have had to fake it with positioned text boxes, which do not stay aligned and cannot be translated as one unit. Tables are a Pro-tier feature, and the people who reuse Pro books, above all to translate them, often have no subscription, so a table must stay translatable and publishable in their hands while they are kept from building new ones.

What the PR does

  • Tables as content. A Table item in the Canvas tool palette, a Table section type in Change Layout, and a ready-made Alphabet Book page in Basic Book. Cells hold text (an ordinary Bloom text box with language tags and format gear), a picture, a video, or a nested table. Rows and columns are added, moved, resized and deleted through the editing chrome the bloom-table library supplies; whole tables are canvas elements and duplicate, move and delete as such.
  • Gating. Tables need Pro and the tables experimental setting. Below Pro, or with the setting off, an existing table is frozen: its text and pictures stay editable and its cells get the ordinary text and picture menus, but nothing can restructure it, the palette icon and Add Page entries are absent, and Change Layout's Table link shows the subscription dialog. An original book with a table cannot be published below Pro; a derivative publishes untouched, the same rule canvas elements follow.
  • Spreadsheet round trip. Export writes one [table] row and one [table cell] row per cell with the table's attributes verbatim in the hidden [details] column; import rebuilds the table from them, with C# unit tests.
  • E2E coverage. Three Playwright specs (tables-core, tables-extended, tables-gating; 29 tests, 8 of them fixme for suspected product bugs), a step caption at the bottom of the Bloom window during --e2e runs showing each step and its timing, a slow-step reporter, and helpers for canvas elements, keyboard, video import and relaunching Bloom under a different tier.

Not yet: bloom-table is a local pnpm link, not an npm dependency, so CI cannot build this branch until it is published. Spreadsheet round trip as an E2E test waits on BL-16813.

Decisions

1. Nested tables two levels deep and the spreadsheet

A cell can hold a table, and a cell of that inner table can hold another one. Spreadsheet export follows that to any depth, but import keeps track of only one level: it reads the inner-inner table's row and column and looks them up in the top-level table, so on import that table lands in the wrong cell, without a warning. Devin raised this (thread; the lookup). Nobody has asked for tables nested that deep, but silently misplacing content is worse than refusing it.

2. Undo prefers the table once a row or column has been added

Undo asks the table library first and CKEditor second. The table's history stays non-empty for the rest of the page session after any structural change, so two things go wrong. Add a row, type in a cell, press Undo: the row goes, not the typing, and the typing can no longer be undone at all (the local review's finding). Type, add a row, press Undo twice: the first removes the row, the second does nothing, because rebuilding the cells discarded their typing history (Devin's thread; the tables-extended spec has a fixme test). The first symptom is the worse one: Undo does something other than what the user just did. The code is at handleUndo.

3. A table's height cannot be changed by hand

A new table falls under the selection rules Bloom uses for text elements, which hide the corner handles. A person can drag a table wider or narrower, but not taller or shorter. Devin flagged it (thread; where the table is created), and the tables-extended spec has a fixme test for corner resizing. Rows do grow with their text in a Change Layout table, so height matters most for tables on picture pages.

4. A duplicated table's picture is missing from the BloomPUB

Duplicate a table that has a picture cell and publish. The original's picture shows in the reader; the copy's cell is empty. The copy's cell says it holds a picture but its image box has nothing in it, and the publishing step that turns a cell's picture into a background image never fires for it. Wiring the copy up properly (this run's fix) did not cure it, so the cause is elsewhere. It stays a fixme test in tables-core.

5. Two ways for a test to hand Bloom a file to choose

This branch added an E2E-only route that tells the Sign Language tool which video file to pick instead of opening a file dialog. Master has since added a general route that does the same for any file dialog, and Bloom's file-chooser code on master uses it. The two live side by side after the merge. The Sign Language tool on master still opens its dialog directly, so it cannot use the general route without a small change of its own.

6. Right-clicking a video cell shows nothing

At every tier, right-clicking a video cell opens no menu at all: not the Cell menu, not a video menu. Text cells get the Cell menu (or, below Pro, Bloom's text menu) and picture cells get the picture menu. The gating spec notes it and leaves it alone.

7. A spoiled spreadsheet table row can still insert a page

Import now leaves a book's table alone when a table row's hidden details cell is blank or malformed, keeps later tables aligned, and does not copy a page for such a row. One case is left: if that spoiled row also names a page type different from the page it should land on, import can still insert a template page of that type before skipping the row. Devin's thread. Closing it means separating "move to the next existing table" from "add a page" inside the importer's page-advancing code, which every row type shares.

FYI: bloom-table must be on npm before this can merge

The branch depends on the bloom-table library through a local pnpm link. CI cannot install it, so the TeamCity build cannot pass and the production bundle check was not run. Publishing the library and pinning its version in package.json is the last step before merge; nothing in this repo can do it.
