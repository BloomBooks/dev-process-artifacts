What this PR is about

Problem

lameta had no project that holds the cases that break it in the field: names that Windows, macOS or git handle badly, unlisted and private-use languages, people that sessions can't match, files that SayMore or old lameta wrote, and broken or huge media. Bugs in those cases turned up one user report at a time, and a developer had no way to reproduce them on demand.

What the PR does

  • pnpm run make-torture-project <folder> writes, deterministically, a large invented project of interviews with abstract artists (about 3,700 files). Every session, person and file in it carries one named hard case, and OtherDocuments/torture-cases.md lists each case, why it is hard, and the code it aims at.
  • Flags add what must not be committed or would hide everything else: names that are hostile on Windows, files that stop the project from loading or saving, and about 1.85 GB of large and broken media made on demand.
  • A manual spec loads a generated project and runs every exporter over it, validating IMDI against the real schema. It is skipped unless LAMETA_TORTURE_DIR is set.
  • The generated project is committed in the stacked #94, which .gitattributes keeps byte-exact. Devin refuses a diff that size, so the code needed its own PR.

The PR fixes no product bug. Working through the project turned up 27 bugs, which are written up separately; each will get its own branch with a failing test first.
