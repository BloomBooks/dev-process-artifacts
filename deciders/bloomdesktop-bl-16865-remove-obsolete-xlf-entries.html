What this PR is about

Problem

Over the years the English XLF files accumulated well over a hundred trans-units that nothing looks up any more — strings for UI removed as far back as Bloom 4, dead login flows, renamed page labels, and entries that were born orphaned. Every one is noise for translators (who translate strings no user will ever see) and for future audits.

What the PR does

Deletes 147 unused entries from the three en/ XLF files, per the aging policy in DistFiles/localization/README.md ("Why we can't just delete a string") and the developer's explicit authorization on BL-16865:

  • 117 ids unused since before Bloom 6.3 — no still-serviced release will ever pick their translations from an l10n_master merge again.
  • 30 ids obsolete as of 6.4 — now that 6.4 is the shipped release, strings 6.4 doesn't use will never need translations. 20 carried the mark from earlier upstream audits; 10 were identified by this audit.
  • Every id verified unused: literal repo-wide search, enumeration of every dynamic-lookup route (runtime-composed TemplateBooks.* caption keys, tooltip derivation, prefix+variable sites), caption-text search of shipped content, per-release-branch history checks (5.0–6.4), and two independent adversarial verification passes — which caught and restored two genuinely live entries (TemplateBooks.BookName.Sign Language Pages, ReaderSetup.PageHeader) whose old obsolete notes were wrong.
  • Only en/ files are touched, so re-adding an id later recovers its translations. A stale test-mock entry for one deleted id is also removed.
  • Base is master deliberately: Crowdin syncs source strings from master only.
