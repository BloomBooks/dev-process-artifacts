What this PR is about

Problem

Bloom references Microsoft-WindowsAPICodePack-Shell (and its -Core dependency), a WinForms/WPF package, only for the folder picker in MiscUI/BloomFolderChooser.cs. It is one of the dependencies the WinForms dependency plan sets out to remove.

Cause

The package came in (BL-9997, 2021) because on .NET Framework FolderBrowserDialog was the old tree-view picker. Since .NET Core 3.0 it shows the same modern Windows folder picker itself.

What the PR does

  • BloomFolderChooser shows a FolderBrowserDialog: same start folder, owned by Bloom's main window, with the description as its title as before, or "Select Folder" when there is none.
  • The package reference is gone, with a dead __MonoCS__ guard in that file, and the plan now lists Keyboarding as the last one-call dependency.

Worth knowing

  • Titles were checked against the real old dialog (the CodePack shown the same way from PowerShell): "Select Folder" with no description, the description otherwise. Clicked through Bloom: Rescue Missing Images, Export to Word (exported into the chosen folder), Export to Spreadsheet.

Test of the change

No automated test exercises the real folder picker: a native dialog can't be shown in a unit test, and e2e tests arm the chosen folder instead of opening it. The existing BloomOpenFileDialogTests cover that armed shortcut. The swap itself was checked live, title by title, against the old dialog.
