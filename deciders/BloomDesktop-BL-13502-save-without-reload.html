Decisions

1. Dropping the 100ms delay leaves a small race

You asked me to drop the tenth-of-a-second pause before a thumbnail right-click command runs, because it was a window in which typing could miss the snapshot Bloom is about to save. Done — but Devin points out something neither of us had written down: that pause was also what made the ordering safe.

The command is queued to run after Bloom answers the browser. Bloom releases its “one request at a time” lock a fraction of a moment later, on a different thread. Two of these commands — Duplicate Many Times and Choose Different Layout — open a window whose contents Bloom itself has to serve, so in principle that window could ask for its contents while the lock is still held, and hang.

My read: the race is between a few microseconds and a whole network round trip, so it should never lose in practice. But “should never” is doing real work in that sentence, and the symptom would be Bloom hanging, which is about the worst thing to be wrong about.

2. Copy Page no longer moves you to the page it copied

Copy Page used to finish by taking you to the page it had just copied. It no longer moves you anywhere — that is the change that stops it reloading the page, which is one of the visible wins of this work.

Those are the same thing when you copy the page you are already on. But a right-click doesn’t select a page, so you can right-click a different thumbnail and choose Copy Page. Previously that moved you to it; now it leaves you where you are.

My read: the new behaviour is the better one — being teleported to another page because you copied it is the more surprising of the two, and nothing about copying needs you to be there. But it is a change to what the user sees, so it should be a decision rather than a side effect of a refactor.
