You asked for the branch to be cheap to merge later. Two things came of that. New behaviour went into new files — the delay gate, the niceScroll cleanup, the content collector — and existing code was not reshaped just to add to it: SaveThen takes one more argument instead of five call sites hoisting their lambdas. Decisions

1. The toolbox tool is still not shut down when you leave the Edit tab

When you have a toolbox tool open — Talking Book, a reader tool, Motion — and you move to a different page, Bloom now correctly tells that tool the page is going away, so it can let go of it and close anything it had popped up. That was broken earlier in this branch and is fixed.

But leaving the Edit tab altogether is a different path, and it is still not covered. The page frame isn’t unloaded when you switch tabs, so nothing tells the tool to let go. In practice: a small window the tool had opened can stay on screen after you’ve switched away, and the tool keeps its hooks on a page you are no longer looking at. Do that repeatedly in a session and it accumulates.

This used to be handled for free, because leaving the tab performs a save, and every save used to detach the tool. That is exactly the coupling this branch removed.

2. Typing while audio plays, then saving, can lose the typing

To work out what to save, Bloom now copies the page and tidies the copy. Two of those tidying steps disagree about which should go first, and no single order is right for both.

CKEditor’s version of the text has to be written into the copy first, because that is the only place the reader tools’ word-marking can then be unwrapped out of it. But the Talking Book tool’s cleanup restores each element from a snapshot it took when audio playback started — and running that after the CKEditor copy means the snapshot wins. So if someone types in a text box while its audio is playing, and a save happens before playback finishes, the typing is not in the saved book.

The window is narrow: the snapshots are cleared when playback ends. But it is silent loss of a user’s typing, which is the worst kind of bug to ship.

3. The page is snapshotted when you click, not when Bloom saves

The old design asked the browser for the page’s content at the moment C# was ready to save it. The new one takes the snapshot when you click, and sends it along with the request. For the thumbnail context-menu commands, C# then waits a further tenth of a second before acting — a delay that exists purely so the menu can close.

Anything typed inside that gap is not in the snapshot. It is a small window, and the cross-page case is safe (a snapshot that arrives late is written back to the page it came from, not to the new one), but it is a real difference from what it replaced, and “a keystroke went missing” is very hard to diagnose later.

4. For information — how much is left to convert

This branch converts everything the page list initiates, plus the three “save and rebuild this page” callers. Still on the old round trip, with reasons: Add Page and Duplicate Many Times (driven from separate dialog windows that cannot reach the page), the copyright dialog (same reason), and the saves C# starts for itself when a tab changes or a collection closes. Those last ones are why the SavePending state and the request-the-content machinery cannot be deleted yet.
