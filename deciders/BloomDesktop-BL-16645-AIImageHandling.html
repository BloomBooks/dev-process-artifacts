Decision 1

Reusing a picture could drop its credits

In the AI Image Editor you can pick a picture that already exists elsewhere in the book instead of generating a new one. That path now goes through the same import processing as everything else. Almost always this amounts to a plain file copy, and the picture’s copyright, creator and licence come across untouched.

The exception is a reused picture large enough to need shrinking. Shrinking writes a brand-new file through GraphicsMagick, and the credits embedded in the original may not survive that. Bloom deliberately does not re-write credits on this path — a reused picture is supposed to keep its own — so there is nothing to put them back. The result would be a picture that silently loses its attribution.

In practice a picture already in the book was normally shrunk on its own way in, so it would not be resized again. The exposure is pictures that arrived some other way: spreadsheet import, BloomBridge, or copied into the folder by hand.

Decision 2 · for information

Oversized WebP results still are not shrunk

The point of this ticket was to stop enormous AI pictures landing in the book folder. That now happens for PNG and JPEG. WebP is the exception: Bloom opens pictures through GDI+, which has no WebP decoder, so there is no way to measure or shrink one. A WebP result is copied in exactly as it was before this change.

The AI Image Editor does allow WebP results, so this is a real hole, just a narrow one — WebP is already a compact format, so an oversized WebP costs far less than an oversized PNG would. Leaving it is reasonable: closing it means adding a decoding path Bloom does not otherwise have, for the least costly case.

Decision 3 · for information

A failed conversion can leave one stray file behind

If the shrink-or-convert step fails partway — after it has created its output file but before it has finished writing it — that half-written file stays in the book folder. The picture itself is safe: we fall back to a plain copy, so the right image still lands in the book under the right name. What is left over is only a stray file.

It is also not permanent: Bloom’s own periodic sweep for unreferenced images will remove it for .png and .jpg. It escapes the AI editor’s own prompt cleanup because that cleanup recognises files by their ai-image name, and the stray one is named after the source. Reaching this at all needs a genuine mid-write failure, so it should be very rare. Leaving it is reasonable: the tidy-up costs more than the mess.
