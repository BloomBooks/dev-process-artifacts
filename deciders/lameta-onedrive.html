What this PR is about

Problem

When a lameta project lives in a OneDrive, Dropbox, iCloud or similar synced folder that keeps files online until needed, many of the project's files are cloud-only placeholders. lameta treated them as local files. Opening a project downloaded or waited on every file, a provider that was down produced an error for every file, showing media details forced a download of the whole recording, and the file list never said what was actually on this computer.

Projects shared between people through a sync service had a second set of problems. A rename could leave a folder half-renamed while the sync engine held a file open, a folder deleted on another computer produced an error on every save, and saving could silently overwrite a colleague's edit that had just synced down.

What the PR does

  • Detects each file's cloud state (Windows file attributes; macOS file providers and iCloud) and shows it in the file list, with a panel to download a file or show it in its folder, and a setting that fetches selected files automatically.
  • Never probes or waits on a cloud-only file. Media details are kept in the file's .meta sidecar, previews wait until the file is downloaded, and project load requests its metadata files in parallel with a progress display.
  • When the provider cannot deliver during load, lameta stops asking after the first failure, shows one banner with a Retry button, and refuses to save over a file whose real metadata it never read. On macOS at most four downloads wait at once, and a metadata file that iCloud evicted is downloaded rather than replaced with an empty one.
  • Renames retry while another process holds a file, undo the per-file renames if the folder rename fails, and the repair of a misnamed metadata file now works.
  • A folder that vanished from disk warns once instead of on every save. A metadata file that changed on disk since lameta read it is moved aside before lameta writes its own version, under a name ending in .txt (ETR009.session (changed on another computer 2026-07-12).txt) so lameta never mistakes the copy for metadata.
  • The branch now builds with master's pnpm and vite-plus tooling.
