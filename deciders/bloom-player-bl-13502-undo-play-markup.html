What this PR is about

Problem

Bloom Desktop saves a copy of a game page while an author plays it in the Play tab, and calls undoPrepareActivity() on that copy so the book records the page as the author made it. undoPrepareActivity() left some of what playing adds behind, so it got saved into books: the mark on an item being dragged, the touch-action: none on draggables, narration highlight classes, the "video wouldn't autoplay" mark and video error messages. And narration's fixHighlighting splits sentences with long runs of spaces into extra spans, stripping the book's own highlighting, with nothing to put it back.

What the PR does

  • undoPrepareActivity() removes all of that markup from whatever element it is given, the live page or a detached copy.
  • prepareActivity() asks narration to record each sentence's markup, by id, before fixHighlighting first changes it; undoPrepareActivity() puts those sentences back. Sentences with a shared or empty id are left alone rather than risk swapping text.
  • Bloom Player's own reader gets the same cleanup when it leaves a game page.
