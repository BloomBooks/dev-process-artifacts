What this PR is about

Problem

A .webp picture can be added through the image chooser, but not pasted. If you copy a .webp file in Windows Explorer, or copy its path, and click Paste on an image container, Bloom says it "failed to interpret the clipboard contents as an image". The toolbar Paste button also stays disabled for a WebP file that is copied in Explorer.

Cause

Bloom reads the clipboard through libpalaso's PortableClipboard, which loads image files with System.Drawing (GDI+). GDI+ has no WebP codec, and libpalaso's list of image extensions that enable the Paste button doesn't include .webp either.

What the PR does

  • Adds BloomClipboard, a thin Bloom-side wrapper around PortableClipboard. When the copied file or path is WebP by content (so a WebP file saved under a .jpg name also works), the wrapper converts it the way the image chooser does: opaque photos become JPEGs, and lossless, transparent or animated images become PNGs, which keeps transparency. Everything else, including a file that can't be read, goes to PortableClipboard unchanged.
  • Pasting into an image container uses the wrapper and deletes the temporary converted file once the image is in the book.
  • The toolbar Paste button is enabled when a WebP file is on the clipboard, without converting anything. Because the button is updated about every 110 ms, that check remembers its answer for a file until the file's path or modification time changes. An actual paste always reads the file afresh.
