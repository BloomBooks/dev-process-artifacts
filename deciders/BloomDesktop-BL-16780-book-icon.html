What this PR is about

Problem

A branded book whose cover picture is still the placeholder gets the wrong icon in the collection, or no icon at all. Bloom picks the branding logo as the book's cover image. With the ABC brandings that logo is an SVG, which PalasoImage cannot load, so the thumbnail fails outright. The reported book is ABC-BARMM-007297-2656.

Cause

When the designated cover image is a placeholder, GetCoverImagePathAndElt looks for a fallback. That search accepted any image anywhere on the front cover. A cover also carries images that belong to the branding and to the license, and those are not pictures of the book.

What the PR does

The search is now one ordered list of candidates:

  • Whatever the book marks as its cover.
  • Otherwise, an image container or an image inside one.
  • The placeholder only if nothing real turns up.

Restricting the second step to image containers is what fixes the bug. The branding logo, the license image, and the QR code of the "Made with Bloom" badge never sit in a container.

The mark in the first step is read from the img, from the image container, or from an image inside a marked container. Only the img carries it on this branch; marking the container came in on Version6.5, which is downstream, so accepting all three shapes lets this survive the merge forward. A marked container has no image address of its own, so without the third shape the search would fall through to an earlier container and take the wrong picture.

Four tests cover the rules: the reported branding case, a loose real image on the cover, the container-level mark, and the existing behaviour that a marked placeholder yields to a real picture.

Worth knowing

  • The image container carries the whole fix, and every branding pack cooperates. All 73 packs under src/content/branding supply their cover logo as a loose img. ABC-BARMM's is literally <img class='branding' src='ABC-BARMM.svg'/>. None wraps one in an image container, so nothing today can defeat the rule. A future pack that did wrap its logo would be picked as the cover again, and the answer then is to reject the branding class in the loop.
  • The fix deliberately gives something up. A bare image sitting directly on the cover, in no container and with no cover mark, is no longer a candidate. That is the point: such an image is branding, a license badge, or decoration. A genuine cover picture in an old book carries the mark, and that path is untouched. Devin reached the same conclusion.
  • Nobody has opened the real book yet. The tests model the ABC-BARMM cover from the card, but ABC-BARMM-007297-2656 itself has not been loaded in a running Bloom to watch the icon appear.
