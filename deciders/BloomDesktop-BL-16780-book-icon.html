What this PR is about

Problem

A branded book whose cover picture is still the placeholder gets the wrong book icon, or none at all. Bloom picks the branding logo as the book’s cover image; with the ABC brandings that logo is an SVG, which PalasoImage cannot load, so the thumbnail fails completely. Example book: ABC-BARMM-007297-2656.

Cause

When the designated cover image is a placeholder, GetCoverImagePathAndElt looks for a fallback, and that search accepted any image on the front cover. A cover also carries images belonging to the branding and the licence, which are not pictures of the book.

What the PR does

  • The fallback considers only the book’s own pictures: an image anywhere inside a bloom-imageContainer, or a direct child of a bloom-canvas — the old shape of a background image not yet converted to a canvas element.
  • The marked image (data-book='coverImage') is still preferred whenever it holds a real picture, taken from the img or from the container.
  • Branding, licence and QR images are refused outright, through a shared IsBrandingOrLicenseImage that HasImages() already applied.
  • Class names are matched whole, so bloom-canvas no longer also matches bloom-canvas-element.
  • Twelve tests cover the search, including the two shapes that motivated the rules and the legacy shape the narrowing must not drop.

Worth knowing

  • The class guard survives for one concrete reason, not caution. With the structural rule fixed, removing it leaves only the hypothetical “branding wrapped in a container” test failing. It stays because the marked path is searched before any container rule, so a book already saved with data-book='coverImage' on its branding logo — every book bitten by BL-16776 — still yields the logo whatever the structure says. That case is now its own test.
  • Reproduced live, before and after. On a Little Zebra book with a custom-layout cover and a placeholder picture, one image change hands data-book="coverImage" to the logo; after the fix the cover-image endpoint returns the thumbnail fallback rather than Little-Zebra.png.
  • The guard only matches img elements. A branding supplying its logo as a background-image div would slip past it. All 73 branding.json files use a plain <img class='branding'> and none uses a background image, so there is nothing to fix today.
  • Hatton asked for this guard to be removed (“nah, don’t be pessimistic”) while reviewing his own first commit, which is why his second dropped it. His objection was right about the case he was shown; the custom-layout case and the mis-marked case are new information.
