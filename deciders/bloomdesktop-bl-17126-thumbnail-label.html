What this PR is about

Purpose

Bloom was slow to show the books of a collection at startup, and the time grew with the number of books, because every book's HTML was parsed for a label that is used only for books without a meta.json title. On the customer build, loading the book list took 2.9 s for a 64-book collection and 9.8 s for a 300-book one.

What the PR does

  • BookCollection.AddBookInfo now works out the thumbnail label only for a book whose meta.json has no title, the only case its one reader uses it.
  • A unit test checks that a titled book gets no label and an untitled one gets its label from allTitles.

One visible change: a book with a meta.json title whose HTML fails to parse is now listed normally, and the problem shows when it is opened, as before BL-16027; today it is listed as an error book. One such book was found among 1,766 real books. Still slow: a book with no meta.json title still costs a whole-file parse while the list loads.
