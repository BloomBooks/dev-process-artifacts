What this PR is about

Problem

After pasting a photo and setting its copyright and license, users sometimes get "Bloom had a problem with IMG_….jpg. The file may be corrupted…". The file is fine, and the information they entered is not saved. One reporter hit it five times in 20 minutes. Sentry shows two other users with the same error.

Cause

Writing the metadata needs the file to itself. Right after a paste, something else (most likely antivirus scanning the fresh photo) may still have the file open for a few seconds. libpalaso's own retries give up after about 2 seconds, and Bloom reported the "being used by another process" error as possible corruption.

What the PR does

  • Every place Bloom writes metadata into a picture file it has just written now waits up to about 5 seconds and tries once more if the file is in use. That covers the Copyright and License dialog, pasting, the image gallery, cropping and rotating, trimming during publishing, resizing on import, and the AI image editor. The wait and retry is RobustFileIO.RetryOnceIfFileInUse. A normal save does no extra work.
  • Before, crop, trim, resize and the AI editor logged the failure, and the picture quietly lost its copyright and license. Now the only cost is a short wait in that case.
  • If the file is still busy, the Copyright and License dialog says Bloom could not save the information, "possibly because another program is using that file". The paste path keeps its old message, as you decided.
  • RobustFileIO.IsFileInUseError recognizes sharing and lock violations, and the spreadsheet exporter uses it too. Crop/trim and the AI editor now share one "clear the tags, then write only the credits" helper.
