What this PR is about

Problem

After pasting a photo and setting its copyright and license, users sometimes get "Bloom had a problem with IMG_….jpg. The file may be corrupted…". The file is fine, and the information they entered is not saved. One reporter hit it five times in 20 minutes. Sentry shows two other users with the same error.

Cause

Writing the metadata needs the file to itself. Right after a paste, something else may still have the new file open for a few seconds; antivirus scanning a fresh photo is the likely suspect. libpalaso's own retries give up after about 2 seconds, and Bloom then reported the resulting "being used by another process" error as possible corruption.

What the PR does

  • Before writing, saving an image's copyright and license now waits up to about 5 seconds for the file to come free, using libpalaso's existing RobustIO.IsFileLocked.
  • If the file is still in use, the Copyright and License dialog now says Bloom could not save the information, "possibly because another program is using that file", and suggests waiting and trying again or restarting the computer. Other failures keep the "may be corrupted" message.
  • The paste path keeps its existing message, as you decided: a message about copyright and license would puzzle someone who only pasted.
  • A new RobustFileIO.IsFileInUseError recognizes sharing and lock violations. The spreadsheet exporter now uses it in place of its own inline check.

Worth knowing

  • Not exercised by hand in Bloom. The busy-file case depends on timing and is covered by unit tests that hold the file open on purpose.
  • When the file stays busy, the dialog's save runs on the UI thread, so Bloom looks frozen for about 7 seconds (5 s of waiting plus libpalaso's 2 s of retries) before the message appears. That only happens in the rare case where the save would otherwise have failed.
  • Placing a picture from the image gallery uses the same save, so it gets the same wait.
