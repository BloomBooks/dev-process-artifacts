What this PR is about

Purpose

In Edit mode, the only place to grab a horizontal origami splitter is its 3px dashed line. When a text box sits just below the splitter, the text box's empty top padding (16px at the default 1em) looks like part of the gap, but pressing there only puts the cursor in the text box. This PR makes that padding grab the splitter too.

What the PR does

  • A transparent ::before on the divider of a top-level horizontal split covers the top padding of the text box in the lower pane. Hovering it shows the resize cursor and percentage label, and pressing there starts the drag, because a pseudo-element's mouse events go to the divider. The divider's offsetHeight, which split-pane.ts uses to place the panes, does not change.
  • It applies only where basePage.less gives that text box its top padding: a text box directly in the bottom pane of a top-level horizontal split. Its height is that same --topLevel-text-padding-top, resolved at the text box's 12pt, and it starts below the divider's 3px border so that it ends where the text starts. Vertical splitters, nested splits and a picture below the splitter keep the 3px line, and the band does not extend upward, where it would cover the crop control of a picture above.
  • The band does not wait for data-splitter-label, which split-pane.ts adds only when the mouse enters the divider, so it works on a page whose splitter line nobody has hovered yet.
  • basePage.less now points to the rule that copies its selector and padding.
