What this PR is about

Problem

Bloom has several separate undo mechanisms, none sharing a record of what happened in which order: Change Layout mode's, the reader tools', the picture undo, CKEditor's per-box undo, and, since Bloom Tables, the table library's history. The Undo button chose between them with a hand-written chain of checks, and tables needed their own counter (undoOrdering.ts) to order their operations against typing. This is Stage 1 of retiring CKEditor; it changes no user-visible behaviour.

What the PR does

  • Adds one undo stack in the page frame (bookEdit/undo/). It dies with the page, as every existing undo already does. runUndoable makes one entry per gesture, and a failed undo or redo discards the stack rather than leaving it to undo a state no entry recorded.
  • Wraps the four older mechanisms as providers, in the order the old chain used. The reader tools' and CKEditor's undo now decline a text box that is no longer on the page.
  • Makes table undo native to the stack. Each table operation becomes an entry that asks the library to undo it. Typing (including reader-tool typing) and table operations undo newest-first, through one shared counter that replaces undoOrdering.ts. Table entries are unavailable in Change Layout mode and, as on master, cannot be redone.
  • Adds a last-resort Ctrl+Y in the page frame for entries that can redo, standing aside for the existing Ctrl+Y handlers.
  • Pins the routing with e2e tests and records the design in PLAN.md (§10 decisions 6–8).
