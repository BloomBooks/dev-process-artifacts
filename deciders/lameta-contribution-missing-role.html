What this PR is about

Problem

A session with a contributor whose <contributor> element has no <role> makes RO-Crate export fail with no crate, and PARADISEC CSV export fail the same way. lameta always writes a role, so such a file comes from hand edits or other tools (torture project finding 4). A contributor with no <name> stopped the whole project from loading.

Cause

File.loadOneContribution passed a missing <role>, <name> or <comments> through as undefined, though Contribution types them as strings.

What the PR does

  • The loader reads each missing element as an empty string, so every reader of contributions gets the type it expects.
  • A File.spec.ts test loads contributors with no role and no name; an export test checks that the RO-Crate and the PARADISEC session CSV are made.

File.ts belongs to fix-loading; this PR changes only loadOneContribution, which none of their PRs touch.
