What this PR is about

Problem

A picture that arrives on its side stays on its side. Bloom could crop a picture and move it, but it could not rotate it, mirror it, or set an item on a page at an angle. An author whose camera saved a photograph sideways had to leave Bloom, rotate the file in another program, and put it back.

What the PR does

  • Rotate right on the picture menu rotates the picture 90 degrees clockwise. An ordinary picture rotates as a box. A background picture rotates inside its area, which is reshaped to match, keeping the crop. Neither acts on an empty placeholder.
  • Flip horizontal and Flip vertical mirror the picture about the axes the user sees, however it is rotated. A cropped picture mirrors its visible part in place.
  • A rotation handle rotates a selected item to any angle, snapping to 45-degree steps, with CTRL to turn snapping off. Speech bubbles and similar shapes, and videos, get no handle.
  • Dragging, resizing, cropping and typing work on a rotated item. Clicks reach the right item and the right text, handles show the right cursors, and a rotated background keeps its framing when the page changes size or its picture is replaced.
  • Undo puts back each Rotate right, Flip and handle drag. Reset Image clears crop, rotation, mirror and a hand-chosen transparency, but does not straighten a rotated box. The picture menu is regrouped, and Escape closes it.

Every angle and mirror is saved in the book HTML. Known gap: BloomPUB publishing does not yet carry a picture's own rotation or mirror (first decision on the right).

Worth knowing

  • Not tried in a running Bloom: clicking into a rotated text box, flipping a rotated and cropped background, and rotating a fill-the-page background and then changing the page shape. All three are covered by unit tests only (third decision).
  • Dragging to select text inside a rotated text box still moves the box instead.

BloomPUB loses a picture's rotation and mirror

When a book is published as a BloomPUB, Bloom first crops each picture's file to the part the page shows. That step works out the region from the picture's unrotated box and then removes the picture's style, rotation included. A later step replaces each picture with a background element and would drop the rotation anyway. So a picture rotated with Rotate right, or flipped, appears in its original orientation in Bloom Reader, and a rotated and cropped picture can be cut to the wrong region. Nobody has checked yet whether an item rotated with the handle survives a BloomPUB.

Copying the rotation onto the replacement element would rotate the whole picture area and any text on it. The sound fix is to bake the rotation and mirror into the published image's pixels while cropping, and crop the region the page really shows. The published picture is then upright and needs no rotation, so Bloom Player needs no change. PDF and ePUB need the same check. See the review thread.

Which localization file for the new strings

The branch adds five strings: the menu commands Rotate right, Flip, Flip horizontal and Flip vertical, and the tooltip "Rotate" on the rotation handle. They are in BloomMediumPriority.xlf, marked not yet ready for translators, as new strings always are. The repository's rule is that the developer chooses the priority file, and nobody asked you. Medium is for secondary options and feature-specific commands; Bloom.xlf is for the most important things users must understand. See the review thread.

Try the unverified cases in a running Bloom

Four behaviours are covered by unit tests but have not been tried with a pointer in a running Bloom:

  • clicking into a rotated text box, which should start editing with the caret where you clicked;
  • flipping a rotated, cropped background picture;
  • rotating a background set to fill the page, then changing the page shape with Origami;
  • resizing and cropping a rotated item at a zoom other than 100%. Devin asked about zoom and nobody has checked it (thread).

An agent can drive a running Bloom from this worktree and try each one, or the tester can, from the notes on the card.
