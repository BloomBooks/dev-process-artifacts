What this PR is about

Problem

BL-16822 lets a picture sit inside a text block, with the block's text flowing around it, the way a picture behaves in a word processor. Until now the only way to put a picture beside a paragraph was a separate image box or a custom template. The page needs rules that wrap the text around such a picture, in the editor and in every published form, before any of the editing code can do anything visible.

What the PR does

  • Adds one stylesheet, inlineImages.less, imported by both the current themes and the frozen legacy theme, so editing, PDF, Bloom Player and ePUB all render an inline picture the same way.
  • Describes a picture's place and size entirely by a dock class (left, right, middle, bottom) plus custom properties: width as a percentage of the text block, vertical offset in pixels, and the picture's aspect ratio. Copying the class list and style from one language's copy to another reproduces the picture exactly.
  • Lets text run above the picture by making the vertical offset transparent padding that the wrap shape leaves out.
  • Shows the picture once per text block, in the visible language that comes first, and keeps the picture from hanging out below its block.
  • Leaves ready-made hooks for wrapping text around a picture's silhouette later, and explains the measurements behind them.
  • Adds a layout suite (pnpm e2e inline-images) that builds pages from the real stylesheet and measures where each line of text lands, with no running Bloom.
