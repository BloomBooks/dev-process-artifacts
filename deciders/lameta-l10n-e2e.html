What this PR is about

Problem

Installers built from master before #81 showed every field label (Title, Date, Genre, Full Name…) in English whatever UI language the user chose, and 3.0.21-beta, the build testers have, had no field translations at all. No test looked at the translated UI. Writing those tests turned up more: choosing a language from View > Interface Language left the menu bar in English; a session's Access label and other repeated labels stayed in English in every language; and several strings never went through the catalogs.

Cause

The CI build ran lingui extract --clean, which emptied fields.po and vocabularies.po before packaging (fixed by #81). Separately, fields.po holds some English texts once per context, but lameta looks field labels up by English alone, so an untranslated entry later in the file, or in vocabularies.po, hid a translated one.

What the PR does

  • Tests: lameta is started in each of the seven UI languages; the tabs, menu bar, and session and person field labels must be translated, and no sub-tab of Project, Sessions or People may show English that its catalog translates. Switching language from the View menu, and a pseudo-locale scan for text that skips the catalogs, are tested too. Expected text comes from the .po files. Two unit specs fail when a catalog loses its translations or a translated label shows in English.
  • Menu bar is rebuilt when the UI language changes.
  • Field catalogs: the app's loader uses any translation of an English text and drops untranslated entries.
  • Unwrapped strings on the Archive Configuration tab, the language pickers, the date hint and the Person and Consent columns now go through the catalogs.

Worth knowing

  • Not exercised by any test: the start screen's menu after a language switch with no project open, and dialogs (Export, Registration, rename) in other languages.
  • The localization suite can be run against an installer with pnpm e2e:installed, but only builds that contain this PR understand E2E_UI_LANGUAGE.

Translator work on Crowdin

The tests found no code errors left, but they did show translator gaps that users will see as English text:

  • vocabularies.po has no translations in any language.
  • "Languages", "Archive", "Grant", "Location", "Name" and "Other" are untranslated in messages.po, though some are translated in fields.po; those tabs read messages.po.
  • This PR adds 9 new strings that need translating.
  • Spanish "Mother's Language" is translated "Otros idiomas" ("Other languages").
