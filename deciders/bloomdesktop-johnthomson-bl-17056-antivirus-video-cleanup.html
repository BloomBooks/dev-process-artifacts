What this PR is about

(1/3) A refused delete made a book impossible to select

Problem. A user's antivirus (Avast plus Defender) refused Bloom's file changes in Documents\Bloom, and one sign-language book gave "Error selecting book" on every click.

Cause. A failed video conversion had left a temporary video in the book. The antivirus refused its deletion, and the unused-video cleanup didn't catch the exception Windows threw, so selecting the book failed every time.

Fix. Unused audio and video cleanup now logs a refused delete and goes on. Video conversion writes its output in the system temp folder, and a refused delete after a failed import no longer ends the import thread.

(2/3) Warn when Windows won't let Bloom change files in a collection

Purpose. Users don't connect antivirus folder protection with Bloom's errors. So after a collection opens, a background check (Windows only) creates, changes, renames and deletes files in a short-lived .bloom-access-check-… folder there. If Windows refuses, a quiet toast leads to an explanation and a help link. The settings of Defender's Controlled Folder Access only name the likely cause; they never trigger the warning on their own. Team Collection sync skips the check's folder.

(3/3) Problem reports name the antivirus

Purpose. Problem reports and Sentry events now list the antivirus products Windows knows about and whether each is protecting. Windows is asked once per run, in the background.
