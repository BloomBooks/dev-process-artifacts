What this PR is about

Problem

When Windows stops Bloom from writing a PNG in a book folder (antivirus, OneDrive, file permissions), Bloom shows a "Could not update PNG image" notice. In its Details dialog the link to our help article can't be clicked, and the message, the link and the diagnostics all run together in one block (reported by a tester on BL-16915).

Cause

The details are built as plain text, but the dialog renders its message as HTML. So the URL is never a link, and the newlines collapse into spaces.

What the PR does

The help line in MiscUtils.GetExtendedFileCopyErrorInformation is now written as HTML, the way other messages sent to this dialog already are:

  • the URL is a real link; clicking it opens the article in the user's browser, and the dialog stays open;
  • line breaks before and after it put the message, the help link and the diagnostics on separate lines.

The same text also goes to the log and Sentry, which now contain the markup. The helper's only other caller just writes to the log.
