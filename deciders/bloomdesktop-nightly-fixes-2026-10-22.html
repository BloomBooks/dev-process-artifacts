What this PR is about

Problem

The 2026-10-22 nightly reported the TypeScript unit tests as failed although all 1564 tests passed: vitest counted 9 "EnvironmentTeardownError: Closing rpc while 'onUserConsoleLog' was pending" errors from bookEdit/js/tableEditing.test.ts and failed the run. It can happen on any run, so the suite is flaky.

Cause

Unit tests were making real network requests. Under jsdom there is no server, so each request fails a moment later and logs; when that log arrives after vitest has torn the test file down, vitest fails the run. In tableEditing.test.ts the requests came from long-press setup (activateLongPressFor), which calls axios directly. Six other files did the same: 129 requests in all, mostly the Talking Book specs asking for the audio devices.

What the PR does

  • vitest.setup.ts refuses every XMLHttpRequest and fetch at once and fails the test that made it, naming the request (from afterEach, since the code under test usually catches the error itself). No request can fail late any more, and a new test that reaches the network fails immediately.
  • The seven files mock what they call, with vi.mock of utils/bloomApi (or bloomEditing's activateLongPressFor). The two Talking Book specs share a small helper that answers the audio-devices and recording-mode requests.
  • src/BloomBrowserUI/AGENTS.md states the rule and says to mock with vi.mock, not bloomApi's global mockReplies.
  • docs/nightly-failures/README.md records the 2026-10-22 nightly: this failure, and the e2e suite's failure to load (a stale canUndo import, already fixed by #8494).
