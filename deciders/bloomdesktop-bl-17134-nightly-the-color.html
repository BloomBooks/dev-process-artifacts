What this PR is about

Problem

Since 2026-11-17 the nightly fails all 8 color-picker component tests (colorPicker.uitest.ts, colorDisplayButton.uitest.ts). Their harnesses never load: MUI's createSvgIcon throws "Cannot read properties of undefined (reading 'muiName')". It fails every time, locally too, from a cold Vite cache.

Cause

The component tester pre-bundles every dependency it finds under react_components in one esbuild pass. Since the Collection Settings Languages page (BL-16739), that graph reaches @ethnolib/language-chooser-react-mui, whose exports points only at its CommonJS index.js. That file requires @mui/material, so esbuild wraps all of MUI in lazy initializers. The ESM icons (which the tester already aliases to, for an earlier version of the same problem) call createSvgIcon at import time without running those initializers, so the color picker's Colorize icon reads SvgIcon before it exists.

What the PR does

The tester's vite.config.ts now aliases the language chooser to the index.mjs ESM build that the package also ships. Nothing in the pre-bundle requires MUI any more, so MUI is no longer wrapped lazily at all.
