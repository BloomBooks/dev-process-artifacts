What this PR is about

Purpose. A user running Bloom in another UI language met English all over a table: the pills and + buttons, the Row, Column, Table and Cell menus with their Format, Size and border controls, and the Paint format badge. All of it comes from the bloom-table library, which had no way for Bloom to translate it. The Publish tab's subscription notice also named the Table feature in English, because Feature.Table had no XLF entry.

What the PR does.

  • Pins bloom-table dist-v0.1.4, which sends every string in its own UI through a localizer that the host installs.
  • tableUiLocalization.ts preloads all 89 ids as EditTab.Table.<id> when a page's tables are set up, then installs a localizer that answers from that dictionary and relabels the pills and + buttons that already exist.
  • Once Bloom learns whether the user may restructure tables, it asks the library to decide again whether to show the + buttons and pills, so they no longer stay hidden when that answer comes after the pointer has reached a table.
  • The XLF entries went to master on their own in cbf5b1603b; Crowdin has them, with French, Spanish, Portuguese and Indonesian suggestions and 31 tagged screenshots.
  • Tests: every library string has its English XLF entry; the preload and localizer are wired up; the chrome is re-decided after the answer arrives.
