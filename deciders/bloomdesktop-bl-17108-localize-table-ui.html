What this PR is about

Problem

A user running Bloom in another UI language met English all over a table: the pills and + buttons, the Row, Column, Table and Cell menus with their Format, Size and border controls, and the Paint format badge. All of it comes from the bloom-table library, which had no way for Bloom to translate it. The Publish tab's subscription notice also named the Table feature in English.

What the PR does

  • Pins bloom-table dist-v0.1.5, which lists every string it shows by its XLF id with its English, asks Bloom for all of them once, and shows none of its chrome or menus until the answer arrives, so a user never sees English turn into their language.
  • When the first table on a page is attached, Bloom hands the library its getLocalizations, the same function the image gallery uses, now shared in lib/localizationManager. A page without tables asks for nothing.
  • Once Bloom learns whether the user may restructure tables, it asks the library to re-decide its + buttons and pills, so a pointer already on a table sees them without leaving and coming back.
  • The XLF entries went to master earlier so translation could start; a test fails if a library string has no matching English XLF entry.
