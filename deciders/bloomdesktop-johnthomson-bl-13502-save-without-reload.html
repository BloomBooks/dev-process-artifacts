What this PR is about

A follow-up to #8209 (saving a page without reloading it), from testing of the game pages' Play tab.

Problem

On a game page, a save made while the tester had items dragged around in Play could write the tester's positions into the book over the author's. Clicking the Play tab while it was already selected did it reliably, and leaving the page then left the items where they had been dragged. A save made mid-drag, or while Play was in use with another tool (Talking Book, say) open, could also store play-only markup in the book.

Cause

Bloom Player's prepareActivity() records where each draggable is as the author's position. Nothing stopped Bloom calling it again while the page was already in Play: a second Play click, the page load, and the toolbox's repeated newPageReady() all did. The save only cleaned Play mode off its copy of the page when the Game tool was the open tool, though the Play tab works with any tool. And undoPrepareActivity() leaves some play markup behind.

What the PR does

  • A page is prepared for Play only once per time it enters Play. That also stops duplicate order-sentence words, a replay of the opening audio, and doubled image-link handlers.
  • Play mode belongs to the game page's tabs, not the Game tool. Every save cleans it off its copy whatever tool is open, and leaving the page ends it.
  • The save also strips what undoPrepareActivity() misses, including the touch-action: none on draggables.
  • Comic-editing suspension tracks Play separately, so another tool resuming editing can't make canvas text editable mid-Play.
