What this PR is about

Purpose

Follow-ups to #8570 (table overflow marks follow row and column resizing), which merged before they were done. On a page over Bloom's 30-box limit, where overflow checking is deliberately off, the new table checks still left marks that nothing cleared; each table was checked twice on page load and after operations that add cells; the e2e helpers repeated themselves; and the move re-check had no e2e test. Since BL-17105 merged, the table overflow spec also failed at set-up on master.

What the PR does

  • A page over the limit gets no marks from any check, while typing still sizes its boxes; a page that grows past it while open loses its marks, and one that comes back under it (however it got over) is checked in full once.
  • A cell's first size report, and reports of an unchanged size, no longer trigger a check.
  • The table e2e helpers read shapes, find cells and measure text fit in one place each, with the marks check back to one atomic read; a new e2e test moves a table past the picture's bottom and back.
  • tables-cell-overflow.spec.ts works with per-cell languages again (it ticks French in the table's Languages menu).
