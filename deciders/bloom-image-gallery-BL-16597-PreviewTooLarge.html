What changed this run

Decision 1 · Greptile P1 · Devin informational

A preview that fails once is never retried while the chooser stays open

When the chooser can't fetch a picture, it now shows a message saying so, and remembers that failure against that particular picture's address. Clicking away and coming back shows the message again immediately rather than trying a second time. That is right for a picture too big for the display engine to draw — it fails identically every time — but the same applies to a picture that failed only because the network blipped, and the user can't ask for a retry short of reopening the chooser.

Decision Leave as is — accept no retry.

This is not a regression: the pane went blank in exactly these situations before and also never retried, so the change makes existing behaviour visible rather than introducing it. The dominant real case is deterministic, so a retry would only cost another wait; and keying the failure to the URL is what makes switching between pictures paint correctly on the first render, which was a separate defect fixed in this PR. Recorded on the thread, now resolved.

Decision 2 · Greptile P2 · Devin informational

The “too large” wording leans on dimensions that may describe a different file

The reassuring wording is used only when the source reported dimensions past what the display engine can draw. The snag, confirmed in the code, is that for Pixabay those dimensions describe the original photograph (PixabayProvider.tsx:86) while the preview shows a much smaller web-sized rendition (line 80) — so in principle we could measure one file and blame the failure of another.

Decision Leave as is — keep both wordings.

For the wording to actually be wrong a source would have to report an original above ~537 megapixels; no provider currently wired up produces anything close, so the mislabeling isn't reachable in practice. The dimension test already removes the misleading reassurance in every case that does occur — the substantive half of the concern, fixed earlier in this PR. The browser cannot report why a load failed, so no cheap change makes it exact. Recorded on the thread, now resolved.

FYI 1

The wording is nearly unreachable in the shipping product

With the BloomDesktop fix in place, a big local picture gets a small stand-in that previews fine, so no message appears at all. In the gallery's own standalone mode no dimensions are supplied, so the neutral wording is what shows. That leaves the size-specific wording reachable only if an online source ever reports a >537-megapixel original, or if Bloom fails to build a stand-in and serves the original instead. It is a genuine backstop, not a routine path.

Decision Leave as is — noted, no action.
FYI 2

Two test-ideas comments now share one marker, and future runs may update the wrong one

Test-ideas comments are found again by a hidden marker in the text, and a preflight run rewrites the most recent one it finds. Because BL-16597 is being fixed in two repositories, the card now has two: one for BloomDesktop, and the round-2 one added here for the gallery. The new one was given a distinct marker, but the search is a substring match, so bloom-test-ideas-gallery still matches a plain bloom-test-ideas search. The practical risk is that the next preflight on either branch picks the gallery comment as “most recent” and overwrites it with notes for the other repo.

Decision Leave as is — watch it on the next run.

Nothing is lost today; the thing to notice is a future run rewriting the wrong comment.
