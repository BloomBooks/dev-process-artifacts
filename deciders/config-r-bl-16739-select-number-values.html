What this PR is about

Purpose

Bloom's new Collection Settings dialog (BL-16739, BloomDesktop #8502) has two dropdowns whose settings are numbers with one named choice: Line spacing (0 means "Auto", otherwise 1.0 … 3.0) and Font size in tools (0 means "Auto", otherwise 9 … 26). A ConfigrSelect could not express that. An option with a label had to have a string value, and a picked bare number came back as a string. So a client had to translate "0"/"1.5" back and forth, and a stored 0 never showed as selected.

What the PR does

  • A ConfigrSelect option may be { value: <number>, label?, description? }. Picking it stores the number itself, and a stored number shows its option and label as selected. 0 is an ordinary value. The option type is exported as ConfigrSelectOption.
  • How: formik-mui's Select re-sets the field from the clicked item's data-value, which is always a string. ConfigrSelect now supplies its own close handler that does the same, but maps the string back to the number of a { value: <number> } option.
  • Unchanged: string options, unlabeled options and bare number options (12) behave as before.
  • The Bloom story uses the new form for Line Spacing and Font Size ("Auto" = 0), and the README documents it.
