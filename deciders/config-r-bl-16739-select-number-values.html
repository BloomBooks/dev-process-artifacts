What this PR is about

Purpose

Bloom's new Collection Settings dialog (BL-16739, BloomDesktop #8502) has two dropdowns whose settings are numbers with one named choice: Line spacing (0 means "Auto", otherwise 1.0 … 3.0) and Font size in tools (0 means "Auto", otherwise 9 … 26). A ConfigrSelect could not express that. An option with a label had to have a string value, and a picked bare number came back as a string. So a client had to translate "0"/"1.5" back and forth, and a stored 0 never showed as selected.

What the PR does

  • Choosing an option stores its value exactly as written. An option may be { value: <number>, label?, description? }, and picking it (or a bare number such as 12) stores the number, not its string form. A stored number shows its option and label as selected, and 0 is an ordinary value. The option type is exported as ConfigrSelectOption.
  • How: MUI's Select already hands Formik the chosen item's own value. The string came from formik-mui's default close handler, which set the field again from the item's data-value attribute. ConfigrSelect's close handler now only marks the field touched.
  • A select's validation is typed string | number, since that is what it now receives.
  • The Bloom story uses the new form for Line Spacing and Font Size ("Auto" = 0), and the README documents the rule.
