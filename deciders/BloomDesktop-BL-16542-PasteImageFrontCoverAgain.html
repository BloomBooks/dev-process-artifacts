Decision · user-visible behavior

Should Bloom say anything when a paste replaces a Standard Layout cover picture?

On the card, a tester pointed out an inconsistency worth settling. When someone with no subscription pastes onto a page that already has a picture, Bloom now shows a “this needs a subscription” notice, which they liked — it makes replacing a picture feel like something you have to ask for. But on a Standard Layout cover, pasting quietly replaces the cover picture, because that page cannot hold a second picture at all. Their suggestion was a message along the lines of “Standard Layout covers can’t hold an extra picture, so change the page to Custom Layout if that is what you wanted.”

As shipped in this branch there is no message: the paste simply replaces the cover picture, which is what Bloom 6.4 did and what the card originally asked for. The picture visibly changes, so the result is its own feedback — and a modal on a routine action gets tiresome fast. The counter-argument is that someone who meant to add a second picture gets no hint about why they did not.

Notes
FYI · edge case

If such a page somehow has no picture area at all, the paste now does nothing

The new rule replaces the page’s picture. If a Standard Layout front- or back-matter page ever turned up with a picture frame that contains no picture area, there is nothing to replace, and the paste ends silently rather than adding a floating picture the page cannot hold. In practice Bloom builds that picture area for every picture frame as the page loads, so this should not be reachable; the code takes the quiet route deliberately, on the grounds that adding something the page cannot hold is worse than doing nothing.
