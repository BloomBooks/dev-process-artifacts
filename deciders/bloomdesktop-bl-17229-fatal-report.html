What this PR is about

Problem

In the nightly, the Test Case 52 test "books with the fake fatal titles show the fatal report dialog, and Bloom quits" timed out. Bloom showed its fatal report dialog, but the message stayed empty and the diagnostic section said "Loading..." for good. The test failed the same way on this machine three times out of three.

Cause

The test raised the dialog with switchTab, which then polls Bloom from inside its page to see whether the Edit tab is active. The tab switch holds Bloom's main API lock while the dialog shows, so that poll waits behind it, joining five requests from Bloom's own pages. Six waiting requests fill the browser's connections to Bloom, so the dialog's own requests never leave the browser. The same heading request sent from Node got its answer at once.

What the PR does

  • Splits the click out of switchTab as clickTab; switchTab behaves as before.
  • The fake-error test raises each dialog with clickTab and waits for the Edit tab after the dialog closes.
  • The doc comment of doThroughOneProblemDialog says when a page call after the dialog starves it.
