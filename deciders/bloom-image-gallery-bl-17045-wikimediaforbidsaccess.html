What this PR is about

Problem

When an Openverse search in the Image Chooser finds pictures hosted on Wikimedia Commons, their tiles in the results grid never show a preview. Choosing such a picture then fails with a 403 error.

Cause

  • No preview: for Wikimedia images, Openverse's thumbnail service takes about 30 seconds and then returns a 500 error.
  • The 403: Bloom downloads the chosen picture without a User-Agent header, and Wikimedia refuses requests that lack one. That half is fixed in BloomDesktop #8505.

What the PR does

  • For Openverse results stored on upload.wikimedia.org, the grid gets its thumbnail straight from Wikimedia at 330 px wide (one of Wikimedia's standard widths). The address is built from the URL's path alone, because Wikimedia now adds tracking parameters to many of these URLs.
  • Images no wider than 330 px use the original file, SVGs use Wikimedia's PNG rendering, and everything else (other hosts, TIFF, PDF, DjVu) still uses Openverse's thumbnail.
  • The version goes to 0.0.6 so BloomDesktop can pin it.

Worth knowing

  • Not tried by hand in the Image Chooser. The URL logic is unit-tested and the URLs it builds were checked against Wikimedia, but nobody has watched the grid fill in with real results.
  • Very long Commons file names (over 160 bytes) weren't verified, because I couldn't find one to test. Wikimedia names their thumbnails differently, so those few may still show no preview.
