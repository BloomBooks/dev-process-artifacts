What this PR is about

Problem

Bloom runs on machines set to many cultures, and culture bugs have only ever been found by accident, when a developer's machine happened not to be English. BL-15064 is the case in point: publishing to BloomPUB in a comma-decimal locale produced uncropped images, and it shipped in 6.1 and 6.2. Nothing in CI runs the tests under a non-English culture, and hand sweeps rot within months. Running the suite under Turkish for this card exposed a real user-facing bug: on a Turkish machine, exporting a book to a spreadsheet writes the cover row as [cover ımage] (dotless ı), and importing a correct spreadsheet leaves the cover image unchanged while adding a bogus coverİmage entry to the book. A hyperlink pasted as MAILTO: is rejected on the same machine. In French, the Reading App Builder download log reads "1,5 MB".

Cause

Culture-sensitive casing (ToUpper/ToLower in C#, toLocaleLowerCase in TypeScript) and culture-sensitive number formatting were used for ASCII identifiers and log text, which must come out the same on every machine.

What the PR does

  • Uses invariant casing in the spreadsheet label mapping and the hyperlink prefix check, and invariant number formatting in the RAB download log. New tests pin the Turkish cases so they are caught on every PR build.
  • Adds a test fixture that runs the whole C# suite under the culture named by BLOOM_TEST_CULTURE, inert when unset, plus a self-test that fails if a requested culture does not actually reach the tests.
  • Adds a weekly GitHub Actions workflow that runs the C# suite under fr-FR and tr-TR as a matrix, with a manual input for trialling other cultures.
  • Adds culture guidance to AGENTS.md: parse and format machine data invariantly, and how to write and run culture-agnostic tests.
