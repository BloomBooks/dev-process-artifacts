What this PR is about

Problem

The OverflowChecker layout tests (self, margin, and fixed-ancestor overflow) have been skipped since the move from Karma to Vitest, because jsdom has no layout. So nothing has been checking the code that turns a text box red when its text doesn't fit.

Cause

An earlier attempt at browser mode reused vitest.setup.ts. Its jsdom mocks (a fake canvas, a fake innerText) break real measurement in a browser. What looked like a "jQuery won't resolve" error was really old plugins expecting a global jQuery.

What the PR does

  • pnpm test now has two Vitest projects: unit (jsdom, unchanged) and browser, which runs *.browser.spec.ts in headless Edge, the engine behind WebView2. The browser project has its own small setup file and doesn't extend the app config.
  • The layout tests moved to OverflowChecker.browser.spec.ts, with one named test per fixture case. There's also a test that checks every case in turn in one document, the way Bloom checks a page.
  • It fixes a latent MeasureText bug the tests exposed. Measuring text that starts with a newline left a line break in the measuring div it reuses, so every measurement for the next ~2 s came out about a line too big and could hide real overflow. The div now always holds a text node with the first visible character (measureText.ts:51).
  • It deletes the unused vitest-notused.browser.config.ts and git-ignores what browser-mode failures leave behind.
