What this PR is about

Problem

The OverflowChecker layout tests (self, margin, and fixed-ancestor overflow) had been skipped since the move to Vitest, because jsdom has no layout. Nothing was checking the code that turns a text box red when its text doesn't fit.

Cause

An earlier browser-mode attempt reused vitest.setup.ts. Its jsdom mocks (a fake canvas, a fake innerText) break real measurement. The "jQuery won't resolve" error was really old plugins expecting a global jQuery. The checked-in fixture .html files had also been hand-formatted, which put whitespace inside the test boxes.

What the PR does

  • pnpm test now has two Vitest projects: unit (jsdom, unchanged) and browser, which runs *.browser.spec.ts in headless Edge, the engine behind WebView2.
  • The layout tests moved to OverflowChecker.browser.spec.ts one named test per fixture case, plus a test that checks every case in turn in one document, the way Bloom checks a page.
  • The fixture .html files are generated from their .pug with pnpm exec pug --pretty bookEdit/OverflowChecker, and each says at the top not to edit it by hand. Prettier leaves them alone.
  • The second commit adds a pair of cases for the descent adjustment (BL-6338), which the old tests never covered. It also fixes the old "fixed height" case: its style said height=50px, so it never had a fixed height. A comment at the horizontal check says why nothing tests it.
  • The MeasureText fix these tests turned up is in #8410, stacked on this PR.
