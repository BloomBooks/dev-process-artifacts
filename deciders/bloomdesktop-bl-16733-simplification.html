BL-16733: simplifying the Front & Back Matter page

An adversarial review of PR #8493 looked for complexity, especially any that exists only because the old WinForms dialog is still around. The fixes on the left have a single obvious form and need no decision. Three findings need your call.

Fixes with one obvious form

  1. The pack list comes from the dialog's own GET. Legacy-driven. Today the page makes a second fetch to settings/xmatter, an endpoint built for the old dialog, whose POST feeds DialogBeingEdited. Instead, GET collection/settings would carry the packs (value, label, description), and a small helper would share the label code with the old handler until cutover. The page then needs no effect, no state and no dialogOpen. The tests' URL switch and the e2e poll get simpler, and cutover no longer has to split the old handler.
  2. The badge data rides in the same GET. That's the QR image, the language name, the address and the default caption. collection/qrCodeBadge goes away, so there's one response and one fetch per open.
  3. The value is the pack Bloom will really use. The GET would report the valid pack (GetValidXmatter) plus an explicit "branding chose this" flag. The page then drops two rules: adding an uninstalled pack to the list as a raw name, and guessing "branding chose it" from the list length. C# already replaces an uninstalled pack on save, so the first rule protected nothing.
  4. The preview stops mirroring the dialog's trim rule. The dialog already works out the values as they'll be saved, for its restart check; it would pass those to the page. That drops the captionWhenOpened prop and its test.
  5. One place for the QR link rule. ?utm_source=qr and the lang-qr-code.png name are each written twice in BookStorage. GenerateQrCodeImage would call MakeLanguageQrCodeBitmap and use one file-name constant.
  6. Cleanup.
    • Delete two tests that only test a mock or a refactor.
    • Stop exporting QrCodeBadgePreview, which nothing outside the file uses.
    • Fix the comment that says every branding has the same badge picture. Five brandings use a dark badge and one a white-on-red one; the preview is a generic badge.

Checked and not carried over: the review's "latent bug" in the pack rule can't happen. When a branding chooses a pack, XMatterPackName already returns that pack, so the saved pack can't differ from the forced one.

Checked and kept

  • The old string ids (AdvancedTab.*, ProjectInformationTab.*, the pack names) stay. Renaming an id loses its translations, and the plan says to reuse ids.
  • The QR image comes from C#, so it matches the books' styled code and link.
  • The five-line bold-language split in the preview stays, because a live preview has to be built in the browser.
  • Restart for QR changes stays: every book's badge has to be rebuilt.

How should the QR caption box work?

The caption box opens filled with the default caption ("More books in {0} language:") as if the user had typed it. C# then remembers what it sent out and saves the caption only if it changed. Otherwise the default would be frozen in today's interface language. This trick was copied from the WinForms dialog into the new save model (BL-16902). It's also why the default caption has to reach the page a second way, for when the user clears the box.

Without the old dialog, we would send the stored caption as it is (usually empty) and save whatever comes back. The preview already shows the default when the caption is empty. What the user sees changes: the box opens empty instead of showing the default.

Should Page Numbering Style leave the Front & Back Matter group of the save model now?

The save model groups values by the page that shows them. pageNumberStyle still sits in frontBackMatter, but we decided it belongs on the Languages page (BL-16739), so that card would have to move it. Nothing on the client reads it yet, so it could move now.

How should the Places explanation be shown?

Config-R draws a group's heading but ignores its description. So the page draws the Places heading and its explanation itself, copying Config-R's heading style, and that copy will drift if Config-R's styling changes. This isn't caused by the old dialog, but every later page will want group descriptions too.
