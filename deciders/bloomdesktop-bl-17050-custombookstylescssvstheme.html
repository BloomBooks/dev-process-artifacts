What this PR is about

Problem

Books migrated from Little Zebra keep their page margins when the user switches to the Edge to Edge theme. On A4/A5/A6 pages, pictures and "Size to fit image" never reach the page edge, and Bloom gives no warning. Deleting the book's customBookStyles2.css makes it work.

Cause

Little Zebra's migrated customBookStyles2.css sets the per-side margin variables directly on .A4Portrait, .A5Portrait and so on. Edge to Edge only set the general --page-margin: 0mm, which the per-side variables normally fall back to, so the custom 12mm values won. This appeared in 6.6 because BL-15958 widened Edge to Edge from the Ebook/Device sizes, which Little Zebra's CSS never targets, to every page size.

What the PR does

  • Edge to Edge's numbered-page rule now also sets the four per-side margins to var(--page-margin) (0). That rule is more specific than the custom CSS's page-size rules, so the theme wins whatever order the CSS loads in.
  • customBookStyles2.css stays linked, so its other styles still apply, and the EFL migrations that pair that file with a non-default theme are unaffected.
  • A unit test checks that the four declarations sit inside that numbered-page rule.

Checked in a running Bloom on a copy of a Little Zebra book at A5 with Edge to Edge and Full Bleed: numbered pages went from 12mm per-side margins to 0mm, with customBookStyles2.css still linked.

1. Hand-set margins in a book's appearance settings

A book's appearance.json can carry per-side margins such as "page-margin-top": "15mm". Bloom writes them into a .bloom-page rule. Under Edge to Edge they no longer apply to numbered pages, because the theme's numbered-page rule is now more specific; those pages get 0mm. No settings dialog exposes these values, and no shipped migration, branding or xmatter settings file sets them, so only a hand-edited book would notice. Front matter, back matter and other themes are unaffected. The unit test CssOfSettingsObject_OverridesMargin uses exactly this setup but only checks the text, so it still passes. Leaving it as is seems right: someone who picks Edge to Edge wants zero margins on content pages.

2. Little Zebra margins on cover and front/back matter

The fix covers numbered pages only. On the cover and other front/back-matter pages, a Little Zebra book under Edge to Edge still shows Little Zebra's margins. Its cover rules (e.g. .A5Portrait.outsideFrontCover) set the per-side margins directly, which beats the theme's general margin on those pages, exactly as it did on numbered pages before this fix. Edge to Edge deliberately keeps a small 3mm margin on those pages (the standard margin with Full Bleed), so the difference is 3mm versus Little Zebra's 10–15mm. The card only reports numbered pages. Leaving it seems reasonable, but it is a visible inconsistency a tester might notice.
