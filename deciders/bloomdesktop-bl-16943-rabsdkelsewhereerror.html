What this PR is about

Problem

In Publish > Apps, Prepare can report "Prepare complete." while the "Install build tools" step stays unchecked. Choose Books, Build and the later steps then stay disabled, and nothing tells the user why. A forum user hit this on 6.4.1, and Colin hit it earlier (BL-16491).

Cause

Bloom runs rab.bat -install-sdks-if-needed and names its own JDK and Android SDK folders. When Reading App Builder (RAB) 14 starts, it looks for an existing Android SDK in C:\sdk, C:\sdk2, and so on. If it finds one, it prints Android SDK is already installed at: C:\sdk, installs nothing in Bloom's folder, and exits 0. RAB treats the JDK the same way. The forum user's Bloom also wasn't using its own RAB: it fell back to their standalone RAB 14.6. Separately, Bloom never sees RAB's exit code (rab.bat ends with GOTO :EOF), so a failed download looked like success too; PR #8435 fixes that.

What the PR does

  • Bloom uses only Reading App Builder for Bloom, with its own JDK and Android SDK, as BL-16148 intended. It never falls back to a standalone RAB. Open in RAB brings forward only a window of that edition.
  • Prepare and Build check the build tools themselves. If Bloom's JDK or SDK isn't there after -install-sdks-if-needed, they stop with a plain error ("Bloom could not set up the tools it needs to build Android apps. Please use Help > Report a Problem…"), followed by details for support: which tool is missing, which folder RAB used instead, and RAB's own error if its command failed.
  • Prepare updates an older Reading App Builder for Bloom when kRabInstallerVersion is newer. Nobody is forced back into Prepare. If the update can't be downloaded, or its installer never starts (it couldn't be staged or launched, or the admin prompt was refused), Prepare carries on with the installed version. If the installer runs and fails, Prepare stops with a plain "Bloom could not install/update Reading App Builder…" message, because the older version may no longer be intact; clicking Prepare again retries. Interrupted downloads leave nothing behind. This is how users will get the RAB fix (app-builders #2494) once it's released.
  • The user sees Bloom's own message. Prepare/Build failures used to show only the innermost error, which hid every plain-language wrapper (ReportFailure).
