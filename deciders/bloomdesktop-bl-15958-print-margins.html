What this PR is about

Problem

With Use full bleed page layout on, text ends up closer to where the printer cuts the paper than the theme intends. In the Default theme at A5, text sits about 9.5mm from the cut instead of 12mm. In Edge to Edge it is worse: text on the cover, title page and credits page sits right on the cut, and text on content pages is only 2 to 3mm inside it. Separately, a book in Edge to Edge on a paper size without full bleed can't get pictures to the edge of the printed page, and nothing tells the user why.

Cause

Full bleed doesn't add a band around the page. It scales the whole page up (about 1.04 at A5) and shifts it so part of it lies past the cut line. Theme margins are page padding in the page's own, unscaled coordinates, so a margin of M ends up M × scale − bleed − overhang from the cut.

What the PR does

  • Every page and cover margin goes through one Less mixin, .marginAsPadding, which turns a theme margin into the padding that leaves that margin measured from the cut. A margin of 0 stays 0, so pictures and full-page covers still run into the bleed. Without full bleed the padding is exactly what it was.
  • The Default theme's per-page-size margin (A5 12mm, A4 and Letter 15mm, A6 10mm) is now --standard-page-margin, and --page-margin is set from it. With full bleed, Edge to Edge uses that margin for its text, on front and back matter and as the inset of text boxes on content pages. Pictures on content pages still reach into the bleed.
  • Page numbers, whether placed from the bottom or the top of the page, get the same correction, so they line up with the text.
  • Book and Page Settings → Theme & Layout warns when the theme is Edge to Edge, the page size is a paper size, and full bleed is off, with a link to Print Publishing.
  • Two e2e specs cover the margins and the warning (Notion Test Case IDs 846 and 847).
