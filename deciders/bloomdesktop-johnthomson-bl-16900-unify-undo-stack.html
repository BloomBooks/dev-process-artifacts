What this PR is about

Problem

Testing of the one undo stack found that Ctrl+Z did nothing at all after a table operation, such as adding a row. The Undo button took the operation back.

Cause

  • In a text block, CKEditor handles Ctrl+Z and knows nothing of Bloom's undo stack. The page took the key first only when the next undo was an inline-image change, so for a table operation CKEditor got the key and did nothing.
  • When the toolbox loaded the reader settings (whichever tool is open), ReaderToolsModel.restoreState set the reader markup type to Decodable. From then on the reader tools claimed Ctrl+Z and Ctrl+Y on every page, and the page's handler stepped aside for reader tools that were not open.

What the PR does

  • The page's Ctrl+Z handler takes the key whenever the next undo is any entry on the stack, the same rule the Undo button follows. It moves into its own file, undo/undoKeys.ts, installed with the page's undo setup, and tests the key before doing anything else.
  • restoreState no longer sets the markup type; only a reader tool marking up the page does.
  • inlineImageCanUndo and inlineImageUndo lost their last caller and are removed.
