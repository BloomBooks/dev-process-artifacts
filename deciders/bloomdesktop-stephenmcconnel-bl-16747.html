What this PR is about

Problem

Some messages from Bloom's C# code always appear in English, whatever language the user picks. Examples are the Talking Book microphone problem, the "Windows too old" message, the PDF booklet print instructions, most Team Collection errors, and the spreadsheet import/export failures. The code asks for an id that is in no English XLF file, so Crowdin never got the string and no translation can exist. In 3 cases the id was a typo for an entry that already exists. In 31 cases the entry had never been added.

What the PR does

  • Corrected ids: the code now uses the existing entry for the microphone, Windows-version and spreadsheet-export messages, so it gets their existing translations.
  • New English entries (translate="no", because this is master) for the rest. Each priority file holds the entries that match its importance: Bloom.xlf, Medium and Low.
  • Two developer-only strings are no longer localized: a fake test report's Retry button and the missing-API-endpoint report.
  • Error details go into {0} instead of being added to the end, so translators can place them. This covers spreadsheet export/import and the Team Collection folder-access message. "Being editing" is now "being edited".
  • A new test fails when a literal GetString id in src/BloomExe is in no English XLF file. Ids parked in the commented-out Team Collection block count as present.
