What this PR is about

Problem

When you translate a book, each text box shows a source bubble with one tab per source language; languages that do not fit go into a small (n) pull-down at the end of the tab strip. On a page laid out with the picture beside the text — Image on Left or Image on Right — picking a language out of that pull-down made the whole bubble disappear. The chosen language was never shown, and the bubble only came back after clicking away from the text box and back into it. Reported on 6.5; present in 6.3 and 6.4 too.

Cause

Those are the layouts that split the page left/right, so the text block is about half the width of the margin box (measured live: 233px against 469px). Bloom treats any such narrow block as liable to have its bubble overlap a neighbour, and switches that bubble from “always visible” to “visible only while the text box has focus”. Picking a language rebuilds the bubble, and the rebuilt one was created in the not-yet-shown state — but the click leaves focus in the text box, so the focus event that would have shown it never arrives. qtip builds its element lazily, so the bubble was not merely hidden: it was absent from the page entirely.

What the PR does

  • The rebuild now asks for the new bubble to be shown at once, via a showImmediately flag threaded from the pull-down handler through to the bubble-creation code, where it only affects whether the bubble starts out shown.
  • The focus/blur show-and-hide events, the position and the styling are untouched, so the bubble still hides on blur exactly as before.
  • Other callers pass nothing and behave as they always did.

The underlying condition is geometric, not layout-specific: any page whose text block is narrower than the margin box was in the same mode and had the same bug.

Decision 1

A neighbouring bug the review turned up

The same function that rebuilds the bubble is also used by the prompt dialog on game pages, which asks for its bubble to be attached and positioned differently from an ordinary one (it sits outside the part of the page that gets scaled, so it needs its own handling).

When a language is picked from the pull-down, the rebuild does not carry that special handling over — it never did, before this PR either. So if a game prompt dialog ever shows a source bubble with three or more languages, picking one from the pull-down would likely leave the bubble the wrong size or in the wrong place. Nobody has confirmed that dialog can actually get a pull-down, so this may be unreachable in practice.

It is not a regression from this PR, and fixing it properly means the rebuild would have to remember how the bubble was originally created — a real design change, not a tweak.
