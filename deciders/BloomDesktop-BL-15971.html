Decisions

1 — FYI: importing TopBar into the Collections pane drags in a global side effect

The fix makes the "Edit this book" button watch the same navigation-lock signal as the main tabs, by importing a hook (useWorkspaceTabInfo) that lives in TopBar.tsx. That file also registers the TopBar component globally when it loads. Devin (informationally) noted this is harmless today — the Publish tab already imports it the same way, and each screen re-registers its own root component afterwards, so the right one always wins — but that a shared hook living in a file with a global side effect is fragile if the loading order ever changes. Leaving it as is matches the existing pattern in the codebase; a refactor is easy but belongs to a housekeeping change, not this bug fix.

Notes

2 — FYI: a C# test fails whenever the test session's temp folder contains "17"

NoErrorForEmptyAudio (spreadsheet audio import) asserts that no import message mentions "17", to prove page 17 imported cleanly. But import messages include full file paths, and this session's isolated temp folder happened to be named a7817563‑… — which contains "17" — so an unrelated "file not found" message tripped the check. It will fail this way for anyone whose temp-folder name contains "17", and has nothing to do with this branch. Leaving it as is is reasonable because a papercut is already logged in PAPERCUTS.md for the next housekeeping pass, and fixing it here would put an unrelated test change into this PR and restart the review cycle.
