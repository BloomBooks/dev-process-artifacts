What this PR is about

Problem

The new React Collection Settings dialog showed a placeholder on its Languages page. The collection's languages, their fonts and their script settings could only be changed in the old WinForms dialog, spread over its Languages tab, the Book Making tab and the Special Script Settings dialog. The reader tools' alphabet and sentence punctuation could only be changed in Reader Setup.

What the PR does

  • A Languages page in place of the placeholder, built on the dialog's shared page context like the other pages. It has a group each for Language 1, 2, 3 and the Sign Language. Each shows its language with Change…, which opens the existing language chooser as a nested dialog; Language 3 and the Sign Language also offer Set… and Remove. Each written language has its Default Font and a More sub-page with the tool font size, line spacing, Asian word breaking and right-to-left.
  • Reader tools, Language 1 only. Its More page edits the reader tools' alphabet and sentence-ending punctuation. On save, just those two values are written into the reader tools' own file in the collection folder, keeping the stages and levels; nothing is written if they didn't change. An edited alphabet is cleaned the way Reader Setup cleans it, through a new optional valuesToSave a page can give the dialog, which the dialog applies both to what it saves and to its Restart check. The fields are locked while Language 1 itself is being changed, and when the file is damaged, so the rest of the settings always save.
  • Page Numbering Style sits at the bottom of the page. Only its place in the dialog's data moved; the collection file is unchanged. Its choices come in the dialog's own settings GET, so the old dialog's endpoint can go with it.
  • Small supporting changes: the settings GET sends the default font for a new Language 3 and the page numbering styles; the language chooser can hand its pick to a callback and is sized properly without a WinForms frame; the reader tools' default settings and alphabet clean-up moved where both callers can use them, unchanged.
  • The More pages rely on Config-R 1.0.0-alpha.31 or later (sillsdev/config-r#31); master already has alpha.33. Before #31, any edit on a More page threw the user back to the Languages page.
  • An end-to-end journey test (collection-settings-languages.spec.ts): Language 1's font, then on its More page a line spacing and a new alphabet; Restart; then the saved collection, the reader tools' stages, and the reopened dialog.
