FYI 1 — The inset is approximate, not exact alignment

The page number is nudged in from the edge by 0.5em, but that em resolves against the page number's own 11pt font, while the text box's thin margin resolves against the text's font (often larger). At typical ebook sizes the two land within a millimetre of each other, and exact alignment is impossible anyway because book text sizes vary. Leaving it as is keeps the inset tied to the theme's padding token, so it follows any future change to that padding. Devin noted the same thing as informational.

Notes

FYI 2 — Padding set to 0 makes the number flush again

If a user sets the book's text padding to 0 in Book Settings, the forced page number returns to the page edge — because the text box it aligns with is then flush against the edge too. That is the alignment the card asked for, just at zero; it is arguably correct rather than a bug. Devin noted it as informational. Leaving it as is means "the number lines up with the text" holds at every padding value, with no special cases.
