What this PR is about

Purpose

Every request for a book file on api.bloomlibrary.org/v1/fs/... goes to the fs function (a Parse lookup) and then to S3, so every download and read-online page pulls the file from S3 again. Most book files never change once uploaded or harvested. If we know which version of a file a request gets, Cloudflare can keep that version and serve repeat requests without S3, for old clients too.

What the PR does

  • fs reports the file's version on its 302 (fileVersion): lastUploaded for upload buckets, harvestStartedAt for harvest buckets, and nothing while a harvest isn't Done. The upload and harvester code was checked for write order. The 302 is private, no-store.
  • The worker caches the S3 file under that version for a year, 2xx only (?v= on the S3 URL as the cache key), for every client. fs is still asked on every request, so new uploads, re-harvests and deleted books take effect at once. Cached responses get the worker's own Cache-Control and no Age.
  • Clients may put the version in the URL: ?v= for downloads, {bookId}@{version} for read online (stripped before fs). It only adds immutable when it matches fs's version, so a wrong one can't pin stale bytes. Downloads get the real file name.
