Decision 1 — Nine C# test failures in the sandboxed test run

The full C# suite was run through build/agent-dotnet.sh, which builds into a private output tree so it can run alongside your live Bloom. Nine tests fail there: four MakePdf_* tests (they need BloomPdfMaker.exe, an externally-downloaded component that isn't deployed into the private tree), four xmatter tests needing the Test-XMatter pack, and one page-insert styles test needing the same fixtures. This branch changes no C# at all, so these cannot be regressions from it — but the wrapper's test tree will keep reporting them on every preflight until the missing artifacts are provisioned, which adds noise to every future run.

Decision 2 — Residual one-frame text dropout at CKEditor attach

After all the fixes, one visual artifact can still occur: for a single frame (~16ms), some sentences' letters may not be painted while their layout and highlight are, right at the moment CKEditor attaches to the page (about a second after a page loads). Live instrumentation shows the page's content and styling are correct at every frame — this is the browser's rasterizer missing a frame deadline while CKEditor replaces a paragraph and the overflow checker measures text, and it was far easier to see while Bloom ran under the Visual Studio debugger. You were testing whether it still reproduces without the debugger when we started this preflight.
