What this PR is about

Problem

In a collection that uses an ABC branding, every book showed a grade circle on the cover, the title page and the back cover, and the circle often showed the wrong grade. A book that had never been given a level showed "Grade 1". A book whose "This book is leveled" switch the user had just turned off went on showing the grade it had before, and kept it after a restart. The back cover, which is meant to read "Kindergarten" for a book with no level, showed a number instead.

Cause

The stylesheet drew the grade from the level recorded on the page alone. The Leveled Reader Tool keeps its level after the switch goes off, so that record outlived the level the book actually had. The server did not clear the number either: a test for the word "leveled-reader" also matched "leveled-reader-off", and the routine that clears the number ran after the number had already gone out to the pages.

What the PR does

  • The ABC stylesheet shows a grade only when the book has one. The grade rules require the book to be marked as a leveled reader, and the number and its "Grade " label appear only when there is a value. A book with no level gets an invisible circle, which is how it behaved before 2022.
  • The back-cover "Kindergarten" rule now names the class the ABC xmatter really emits, so it applies at all. It never did.
  • Book records the level and the stage on the book only while the book is of that kind, and writes them as soon as the user flips either switch.
  • BookData tests the classes as whole words, and clears the number before the data goes out to the pages rather than after.
  • The Leveled Reader and Decodable Reader controls update the page as the user changes them, so the circle follows the switch with no page change. Where a book is both kinds, the decodable stage wins, which is the order the server applies.

Worth knowing

  • One case was not exercised by hand in a running Bloom: a book that is both a leveled reader and a decodable reader, when one switch goes off. Bloom kept shutting down during that check. Unit tests on both the server and the client cover it, and it is in the QA test ideas on the card. Every other case in the grade matrix was confirmed live.
  • Nothing in this branch touches the publishing code, so the grade in a published BloomPUB rests on Bloom Player copying the book's classes onto its page. The code says it does; a tester confirming it on a real device file would close the last gap.
  • A book that is only a decodable reader shows Grade 1 and a blue circle, whatever its stage. That is this stylesheet's documented default, not a side effect of this change.
  • The book-icon fix that was in this worktree has moved to branch BL-16780-book-icon, which targets Version6.4. It is not in this PR.

Decisions

Nothing is blocked. These two are about how much you want confirmed before this merges.

The both-readers case has only been seen working in tests

When a book is both a leveled reader and a decodable reader, and the user turns the leveled switch off, the number on the cover has to fall back to the decodable stage rather than keep the old level. The code does that on both the server and in the browser, and there are unit tests for each. Nobody has watched it happen in a running Bloom, because the Bloom instance kept shutting down during the attempt. Every other case in the grade matrix was confirmed live.

The published book was not opened

The grade rules changed shape, and this branch does not touch the publishing code. Bloom Player copies the book's classes onto the page it builds, which is what makes the new rules work there, and that is visible in its source. No BloomPUB was actually built and opened during this work.
