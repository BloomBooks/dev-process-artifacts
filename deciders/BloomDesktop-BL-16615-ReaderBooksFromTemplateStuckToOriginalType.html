Decision · from Devin (Investigate)

Generalize the fix to requiresToolId(), or keep the narrow reader-only guard?

The fix ignores two specific page tags by name: "leveledReader" and "decodableReader". Devin points out that Bloom already has a general rule for “this page belongs to a particular tool” — a tool method called requiresToolId() — and today only the Games tool returns true for it. So an alternative is to ignore the page tag unless some tool actually claims it via that method, instead of naming the two reader tools explicitly. The upside: it would also cover other legacy tags — Devin specifically names "signLanguage", which appears on pages in existing sign-language books and today would still get “stuck” the same way. The downside: it changes behavior for sign-language books too, which is beyond what BL-16615 and John Hatton asked for, and that path has no test coverage here. This is a design/scope call, not a bug — the current code works correctly for the reader case the card is about.
