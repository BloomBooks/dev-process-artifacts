What this PR is about

Problem

If api.bloomlibrary.org doesn't answer an upload, Bloom waits about 100 s and then tells the user to "restart Bloom or get technical help". Neither helps: the service is busy, and trying again a few minutes later works. This happened on 2026-10-27, 09:38–09:50 UTC, and the nightly's upload tests failed the same way.

There is also a latent bug. The server reports a cancelled operation as Canceled (one L), but Bloom only treated Cancelled as a failure. So a canceled operation returned nothing: upload-start then failed with a null-reference error, and upload-finish quietly counted it as a success.

What the PR does

  • A timeout, no response, or a 5xx on upload-start or a status poll now throws a WebException whose message is "BloomLibrary.org isn't responding right now. Please try again in a few minutes." The response is still logged as before.
  • BookUpload already shows a WebException as a network problem: the existing localized "There was a problem uploading your book." followed by that message, with no restart/technical-help line. So BookUpload is unchanged. The second line is unlocalized, like the other second lines here, so there are no new strings.
  • Failed, Canceled and Cancelled all count as failures.
  • There is still no automatic retry, and the timeout is unchanged.
