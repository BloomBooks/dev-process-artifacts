Decision 1

A C# test fails on this machine, and it isn't ours

The full C# suite came back 3047 passed and one failed: SafeXmlTests.Xml_DoesNotProvide_ThreadSafety. This branch changes no C# at all, so it cannot be the cause — and the test fails just as reliably when run on its own.

What that test does is deliberately abuse a plain .NET XML document from two threads at once and assert that it blows up — the point being to demonstrate why Bloom wraps XML access in its own safe classes. Whether it actually blows up depends on the two threads colliding in the right way, which on this machine they never do, so the assertion “it should have thrown” fails. The test already carries a marker excluding it from the build server, with a comment saying it is flaky there and someone should fix it up.

Why it is worth a moment of your attention rather than a shrug: the repo's own agent instructions state that the full C# suite is expected to be green when run this way, and that a failure means a real problem. As long as this one test fails every time, every future preflight has to re-investigate it and re-conclude it's noise. Whatever you choose here is separate work from this PR, which touches no C#.

For your information

What Devin noticed but did not flag

The clean re-review still left five informational observations. None were judged worth acting on, but two are worth you knowing about, because they describe deliberate choices rather than oversights:

The cleanup removes every floating tooltip inside the element being deleted, not only the “Choose topic” one — source bubbles and ordinary hint bubbles go too. That is intended: the whole element is about to leave the page, so every tooltip anchored inside it is about to be orphaned. It does mean the change quietly fixes a leak that was there for ordinary text boxes as well; you just never saw those, because unlike “Choose topic” they only appear while the box has the cursor in it.

The new test stands in for Comical — the drawing library that actually removes the element — with a plain browser removal. That matches what Comical really does today, and it matters that it does: a plain removal is precisely the thing that leaves the tooltips behind, so the test would not pass if the stub were more forgiving than reality. The limitation Devin names is real but mild: if Comical ever changed to a removal style that cleans up tooltips by itself, the test would keep passing rather than telling us the fix had become unnecessary.
