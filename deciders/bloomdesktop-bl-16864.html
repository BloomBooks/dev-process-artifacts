What this PR is about

Problem

A book made from the Playground template is a scratchpad: Bloom deliberately unlocks every feature inside it so people can try things out, and in exchange nothing made from it may be published. Every publish screen enforces that — except Publish > Audio or Video, which only disabled the final Save… button. Record and Play Recording stayed enabled, so you could record a Playground book, click Play Recording, and Bloom would hand the finished file to your video player, where it can be kept and used as a real publication. The block was on the wrong button.

What the PR does

Disables Record for a Playground book. gotRecording is only ever set by the websocket event a completed recording raises, so with Record off the rest of the stepper — Play Recording and Save… — is unreachable. The screen still previews the book normally, and no other kind of book is affected.

That follows the pattern the other publish screens use, and that BL-16855 wrote down on FeatureInfo.UnlockedInPlayground: “the other publish screens stay usable for a Playground book and just disable the button that actually publishes it.” On this screen the button that actually produces the publishable artifact is Record, not Save.

The whole change is one line, at PublishAudioVideo.tsx:531.

Over to you

Should the backend refuse to record a Playground book too?

The block added here is in the screen, not the server. publish/av/recordVideo will still happily record a Playground book if something asks it to — the button is simply never clickable. That is exactly how the other publish screens work: ePUB, PDF, BloomPUB and Library upload all enforce the Playground rule in the React code alone, and their API endpoints have no check either. The Apps screen (BL-16855) is the odd one out, because there the export genuinely can be started from more than one place.

Since Bloom controls both ends of the API and the only caller is our own button, a second check would be belt-and-braces. But it would also be the only enforcement a future refactor of this screen couldn't accidentally drop.
