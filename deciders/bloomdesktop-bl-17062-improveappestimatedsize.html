What this PR is about

Problem

Publish → Apps shows a size bar so users can tell whether their app fits under the roughly 100 MB Android limit. Before a book had been built its figure was far too high: a Little Zebra book with big pictures showed 116 MB for an app that was really 16 MB. The real sizes that appeared after a build were thrown away each time the user came back to Apps.

Cause

Until a book's BloomPUB existed, Bloom counted every file in the book folder: full-size original pictures, a PDF left from an earlier publish, backups. A BloomPUB leaves most of that out and shrinks the pictures. And entering Apps deleted every BloomPUB made earlier, which also raced with the size request and caused an occasional error.

What the PR does

  • Estimates what publishing will actually produce. Counts only the files the BloomPUB export takes, and applies publishing's own rules to the pictures on the book's pages: shrunk to the publish resolution, an opaque PNG or shrunk JPEG at a typical JPEG rate, a picture that is or will be made transparent kept as a PNG. Pictures publishing leaves alone count at full size. A PNG counts as opaque only when its header rules out transparency; otherwise it counts at the larger, transparent size, because checking the pixels takes about 0.1 s per picture.
  • Keeps built BloomPUBs between visits. Each gets a small record of what it was made from (Bloom version, publish settings, subscription, the book's content and metadata). The size bar and Build reuse a BloomPUB only while it still matches.
  • Shows estimated and measured sizes differently (striped vs. solid), and adds a Measure exact sizes button that makes the missing BloomPUBs without building the app.

On the card's collection (estimate → actual): Apwiya 14 → 3.9 MB (the old method counted about 104 MB; its PNGs are opaque paintings saved with an alpha channel), Atthu 7.1 → 6.8 MB, Epuri 9.0 → 7.3 MB, Epwittipwitthi 8.8 → 6.5 MB. The 4-book app shows about 50 MB before measuring and 35 MB after, the size of its built APK.

Worth knowing

  • No automated test runs the real export-and-reuse path; the unit tests and the opt-in Reading App Builder test both stand in for it. It was exercised by hand with Measure at the head commit, but a full Build has not been re-run by hand since the review fixes.
  • Kept BloomPUBs now stay in the collection's Bloom App Data folder, a few MB per measured book. In a OneDrive or Dropbox collection they get synced.
  • ImageUtils.IsIndexedColorPngFile, which image processing runs on every PNG, now uses the shared PNG constants. The change is mechanical and newly tested, but it is the one shared path outside the Apps screen this PR touches.
  • Fonts installed on the computer are not part of a kept BloomPUB's record, so a font update alone doesn't make Bloom rebuild a book.
