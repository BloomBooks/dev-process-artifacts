What this PR is about

Problem

With a new book, typing a title on the cover and then closing a picture's Copyright and License dialog makes the cover picture disappear ("missing or loading too slowly") until you change pages. On a Wall Calendar it shows "Page expired" instead. The reporter (6.5) got "Page expired" doing the same thing on a Big Book cover. Moving a page in the page list right after typing a title can do the same. Nothing is lost; changing pages recovers.

Cause

The first time the book is written after it gets a title, Bloom renames its folder from Book-xxxxxxxx to the title. The page being edited is served from a URL inside that folder, and its pictures and scripts are relative to it. Some saves reload the page before writing the book: closing the image Copyright and License dialog, its "copy to all images", and moving a page. When that save is the one that renames the folder, the page reloads under the old folder. The save's own navigation afterwards was skipped as "already going there", so the page, a picture or a script was not found.

What the PR does

  • EditingStateMachine holds back any navigation requested while a save's action runs and the book is written. Afterwards it goes once to the page the action named, from the book's current folder. A save whose action navigated elsewhere now loads only the final page, not both.
  • One _saveInProgress flag replaces the old flag for the action window.
  • Tests: two new unit tests, and a new e2e spec that fails on any request under the old folder and checks the cover picture still shows after the dialog closes.
