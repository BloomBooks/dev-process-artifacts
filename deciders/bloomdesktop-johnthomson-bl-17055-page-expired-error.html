What this PR is about

Problem

Typing a book's title (a new book, or retitling one) and then doing something that saves the book can leave the page on screen pointing at a folder that no longer exists. Until you change pages you get one of these:

  • "Page expired" (what the reporter saw in 6.5);
  • the cover picture shown as missing;
  • a missing configure.js on a Wall Calendar;
  • a "Cannot Find Image File" notice from the page list.

Nothing is lost.

Cause

The next write after a title change renames the book's folder to the title. The page being edited and the page list are both served from addresses inside that folder. Three things went wrong:

  • Some saves reloaded the page before writing (the image Copyright and License dialog, moving a page), so the reload used the old folder.
  • Saves that stay on the page (opening the AI image editor) left it on the old folder.
  • A thumbnail refresh could reach the old page list before Bloom replaced it.

What the PR does

  • EditingStateMachine prevents navigation while a save's action runs and the book is being written; a navigation asked for then is dropped, and once the book is written it goes to the page the action named.
  • EditingModel remembers which folder the page on screen came from. After any rename, once the save is done, if the page came from another folder, it saves and shows it again from the new one. This covers every reason to save, present or future. Opening the AI image editor waits for that reload, so it isn't closed by it.
  • A page-content request from a page list loaded from another folder (judged by its Referer) gets nothing to draw.
  • Tests: new unit tests for the state machine and the page-list check, and a new e2e spec with three cases. Each case failed before its part of the fix.
