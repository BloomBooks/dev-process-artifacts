What this PR is about

Problem

All eleven toolbox tools have been React for some time, but the Edit tab's toolbox frame still ran the legacy jQuery-UI accordion in parallel: toolbox.ts built every tool's panel into a hidden #toolbox div, and the visible React toolbox adopted those DOM nodes back out through a bridge (window.toolboxReactAdapter, CustomEvents, a MutationObserver, and a 250 ms poll). That double bookkeeping was dead weight and a steady source of subtle bugs — the Talking Book busy cursor pointed at the hidden copy and never showed, and an id-spelling mismatch silently broke image-description detection.

What the PR does

  • One React root renders the toolbox; a small state store (toolboxState.ts) is the single source of truth for which tools are offered, expanded, and running, and each tool is an ordinary child component whose lifecycle a React effect runs. The accordion, the hidden div, and the whole bridge are deleted — about 2,100 lines net; toolbox.ts goes from 1,948 to under 900 lines.
  • toolIds.ts owns the canonical tool ids plus the shims for the persisted spellings, so the on-disk book format is deliberately unchanged.
  • The per-keystroke markup engine (reader-tool highlighting, paste cleanup, CKEditor coordination) moved verbatim from toolbox.ts to pageEditingMarkup.ts.
  • Tools deliver their own stylesheets; the Playwright harness and uitests now drive the real tools.
  • Review-driven fixes now included: a Decodable Reader crash on a book with no saved toolbox settings; the toolbox continuing to drive a tool whose section was collapsed when its page stopped applying; and clicking an open tool's header now (deliberately) collapses it — see the decision at right.

1 · Clicking the open tool's header now collapses it

In 6.3, clicking the header of the tool that is already open did nothing (a deliberate workaround, BL-16533, because the legacy sync re-expanded it with a flash). On this branch the click really collapses the section: every panel is closed, and the tool quietly keeps working on the page until another header is clicked. The code documents this as deliberate, and the related bug (Bloom driving a collapsed tool that stopped applying) is fixed — but it is a visible behavior change this PR's description never mentions, so it needs your confirmation. Leaving it as is keeps the standard accordion affordance and matches the store's design. (the open Devin thread)
