What this PR is about

Problem

Since #8456 (BL-16806), a full build (the nightly's msbuild Bloom.proj /t:Build) produces a Bloom that dies while opening a collection, with a TypeLoadException for SIL.IO.UnixFilePermissions. 41 e2e tests failed in the 2026-10-09 nightly.

Cause

#8456 moved libpalaso to 18.0.0-beta0046 only in BloomExe and BloomTests. BloomPdfMaker (SIL.Core) and the Freeze Doctor (SIL.Core.Desktop) stayed on beta0028. All three build into one folder and the other two finish after Bloom, so Bloom ran beta0046 SIL.WritingSystems on top of a beta0028 SIL.Core that lacks the type. The dependency check that exists for exactly this compared only assembly versions, and every libpalaso 18.0.0 prerelease is 18.0.0.0.

What the PR does

  • Puts WebView2PdfMaker, BloomFreezeDoctor.Core and BloomFreezeDoctor.Protocol on libpalaso beta0046, like BloomExe.
  • Makes check-dependency-versions.ps1 also fail when co-located apps take a shared DLL from different package versions (e.g. SIL.Core/18.0.0-beta0028 vs -beta0046). On the pre-fix state the old script passes and the new one fails, naming SIL.Core.dll and SIL.Core.Desktop.dll; on this branch's build it passes.
