What this PR is about

Problem

The new React Collection Settings dialog still showed a placeholder on its Advanced page, so a user could not turn automatic updating on or off or rename the collection there, which the old WinForms dialog allows.

What the PR does

  • A real Advanced page with Program › Automatically Update Bloom and Collection › Collection Name. Saving and renaming go through the shell's existing settings properties; a name change turns OK into Restart.
  • Since the reworked save stores exactly what it is sent, the dialog trims an edited collection name before deciding on Restart and before saving: spaces typed around a name are not a rename, and no folder gets a name ending in a space. An untouched name goes back exactly as it was, so saving another setting never renames a collection.
  • The checkbox appears only where Bloom can update itself (Windows 10 and later): the dialog's settings reply now says whether that is the case.
  • In a Team Collection the name is greyed out with the old dialog's explanation underneath, kept readable rather than faded with the rest of the row.
  • Three new strings in BloomMediumPriority.xlf, marked translate="no"; the other labels reuse existing ids.
  • Unit tests, and an e2e journey test (Test Case ID 838) with new helpers for text settings and OK/Cancel.
