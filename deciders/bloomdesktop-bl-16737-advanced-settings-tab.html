What this PR is about

Problem

The new React Collection Settings dialog still showed a placeholder on its Advanced page, so a user could not turn automatic updating on or off or rename the collection there, which the old WinForms dialog allows.

What the PR does

  • A real Advanced page with Program › Automatically Update Bloom and Collection › Collection Name. Saving and renaming go through the existing save path; a name change turns OK into Restart.
  • The checkbox appears only where Bloom can update itself (Windows 10 and later): the dialog's settings reply now says whether that is the case.
  • In a Team Collection the name is greyed out with the old dialog's explanation underneath, kept readable rather than faded with the rest of the row.
  • Three new strings in BloomMediumPriority.xlf, marked translate="no"; the other labels reuse existing ids.
  • Unit tests, and an e2e journey test (Test Case ID 838) with new helpers for text settings and OK/Cancel.

1. Should the three new strings go to translators now?

This PR adds three English strings to BloomMediumPriority.xlf: the group heading "Collection", the auto-update description "When a new version of Bloom is available, Bloom will get it for you." (from the card's mockup), and the Team Collection explanation "The collection name cannot be changed because this is a Team Collection. Contact the Bloom team for more information." (copied from the old dialog, where it was never localized). All three are marked translate="no", which keeps them away from Crowdin. The page names added by BL-16902 for this same unreleased dialog are marked the same way, which is why I left these provisional. Leaving them as they are is the recommendation, since the dialog is still being built and its wording may change.

2. A rename relaunches Bloom without its launch options

When someone renames a collection, Bloom closes and starts a brand-new copy of itself whose command line is only --rename <old folder> <new folder> (Program.RestartBloom). Every option the original was started with is dropped. For the e2e suite that means the new Bloom would take your keyboard and foreground, use your own user settings and recent-collections list instead of the test's, and keep running after the test ends. So the new e2e test stops when OK turns into Restart and presses Cancel. I recorded this in AUTOMATION-DEBT.md. The same happens on other self-restarts with no arguments, e.g. after a UI language change.

3. Adding only a trailing space to the name still asks for Restart

If someone adds just a space to the end of the collection name, OK turns into Restart, and pressing it closes and reopens the collection with nothing renamed (the save step trims the name, so it sees no change). The old dialog trimmed before deciding, so it never asked. The cause is the dialog's general "does this change need a restart?" check (restartNeededFor, from BL-16902), which compares values exactly. It costs the user an unneeded reopen and nothing else.

4. A manual Notion card for what the e2e test leaves out

Notion test case 838 describes exactly what the e2e test does: auto-update is saved, and a rename asks for Restart. Two things are left only to manual testing: pressing Restart after a rename (the folder really gets renamed and the books survive), and the greyed-out name in a Team Collection. They are in the test-ideas comment on BL-16737, but the inventory rule is that untested steps live on a card of their own so a manual test run finds them.
