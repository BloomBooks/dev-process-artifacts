What this PR is about

Purpose

Authors want a table in the middle of running text, as in a word processor: a few lines of text, a small table, then more text, all in one text box that grows and flows like any other. Until now a table could only fill a page-layout section or sit in a canvas element. With this PR, right-clicking in a text box offers Insert Table, which puts a two-by-two table into that language's text at the caret, between two paragraphs.

What the PR does

  • Insert Table splits the paragraph at the caret and puts the table between the halves. A recorded sentence that the split cuts keeps its recording on one half only. The table is as wide as the box, its rows grow with their text, and half a line of the surrounding text separates it from the text.
  • The table belongs to that language's text: it is hidden with it (Talking Book does not play its cells then), and a new language's text does not get a copy (C#, TranslationGroupManager).
  • The cells have no CKEditor, so no formatting. Anything that rewrites the outer box keeps the live table; the outer box's commands are cancelled inside it; Ctrl+Z / Ctrl+Y in a cell are the browser's own.
  • Backspace, Delete, typing, Enter, and cutting or pasting (by key or the top bar's buttons) next to or across the table cannot delete it. Its buttons show only while the focus is in it.
  • Each table has a grip left of its first row, shown with the page's other editing marks (not in Change Layout), that drags it elsewhere in the same text.
  • Talking Book, the reader tools and source bubbles skip the table's text, and the overflow check leaves out the empty paragraph and margin below a table that ends the text.
