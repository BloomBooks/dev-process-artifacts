What this PR is about

Problem

The nightly e2e test "Rotate right rotates the page's background picture … and four rotations put it back" (Test Case 827) has failed every night since 2026-10-15 with "After four rotations the background's left is 0, not -1." The file runs serially, so the 7 tests after it were skipped too.

Cause

#8459 (BL-17009) makes a fitted background picture overhang each edge it fills by 1px, so no white line shows. Rotate right refitted the picture exactly to its area and never added that overhang. After any rotation the bleed was gone and the white line could come back, and after four rotations the left was 0. Confirmed locally: reverting #8459's commit alone makes the spec pass, and master fails the same way through the dev server.

What the PR does

  • Rotate right enlarges a background picture's new layout by the same bleed the fitting code uses. It scales the picture and any crop together and keeps it centred, and it measures the area exactly, so a fractional-width area gets the full overhang on both sides. Pictures that aren't backgrounds are unchanged.
  • The bleed constants and helper move unchanged into backgroundImageBleed.ts, so the rotation code can use them without importing the background image manager.
  • Unit tests for rotating a background now expect the bleed, and new ones check the overhang on every filled edge, including on a fractional-width area.
  • The nightly-failures doc entry records the confirmed cause and links this PR; it stays until a nightly passes with the fix.
