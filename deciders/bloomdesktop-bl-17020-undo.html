What this PR is about

Problem

Undo in the Edit tab was split among separate histories: CKEditor's for each text box, the Undo button's own stack, the picture undo, the reader tools' undo, and the undo of several tools and dialogs. Ctrl+Z and the Undo button could do different things, many actions could not be undone at all, and undoing in one history could overwrite a later change that another had recorded.

What the PR does

  • Replaces them all with one undo and redo history for the page, built from the changes that a MutationObserver records, with each user action grouped into one step.
  • Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z, the Undo button and a new Redo button reach it from the page, the toolbox and the top bar. The C# Undo command is gone.
  • Brings typing, pictures, tables, canvas elements and their commands, dialogs and the toolbox tools onto it. Talking Book and the reader tools no longer rewrite the text boxes behind its back.
  • Groups typing as Chromium's own undo does (a line with its Enter, deleting after typing, caret moves, IME commits), and adds one rule of Bloom's own: a pause of a second ends a step.
  • Refuses an undo, rather than damaging the page, when the page changed underneath the step. It logs every step, undo, redo and clear under short names such as did Move(SpeechBubble). A developer's Show Page History window shows the stack.
  • Tests: unit tests and a randomized test of the history engine, browser tests, undo e2e specs, and an undo round trip at the end of 16 feature specs. Also fixes a toolbox open/shut restore race and an e2e page-selection race found along the way.

Design and limits: docs/undo/ (OUTLINE, MINIMUM, OPEN-ISSUES, TYPING-STEPS).
