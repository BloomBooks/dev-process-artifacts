What this PR is about

Purpose

Every page of the React Collection Settings dialog has landed, so it can become the only Collection Settings dialog. This PR removes the old WinForms dialog and its "Old Settings" button, along with everything only it used: its own save path, its settings/* endpoints, and its copies of the language chooser and several panels. With one dialog, each settings rule lives in one save path instead of two.

What the PR does

  • The old dialog is gone: both WinForms dialogs, the Old Settings button and its launch path, the four React tab bundles, the settings/* endpoints only they used, the legacy Create Team Collection path, and a startup check that could never fire. Every rule of the old OK handler is in the new save path, except the dead "experimental book sources" option.
  • The language chooser only runs in the browser. The Publish tab's sign-language link, its last WinForms user, opens it itself and saves with one POST.
  • The new dialog is simpler: it loads its settings before it shows and is rebuilt on every open; a non-administrator gets a small dialog of its own, with a message C# now builds as plain text; the posted languages, with their fonts, go straight into the collection's list.
  • Cleanups along the way: one component draws a settings row with its subscription badge (the Bloom Library and Experimental pages and Book Settings' Full Bleed row each built it by hand); the e2e helpers drive the language chooser and the Languages page's Change…/Set…/Remove, taken from #8575.
  • Strings and docs: fifteen unused strings are marked obsolete (none deleted); the plan doc is removed.

Decisions

Split the cleanups into a PR of their own?

Some of this PR's improvements don't need the old dialog gone and could have gone in first:

  • the shared badge-row component;
  • the dialog loading its settings before it shows and starting fresh on every open;
  • small tidy-ups in CollectionSettingsUpdater;
  • the e2e helper work;
  • the plain-text admin message.

Others depend on the cutover: the save path no longer taking the WinForms dialog's inputs, the Publish chooser moving to the browser, and the removals. A first PR with the independent part would leave the cutover mostly deletions, easier to review. Splitting now means untangling the single squashed commit, a second PR with its own preflight and review, and rebasing this one onto it.
