What this PR is about

Purpose

Every page of the React Collection Settings dialog has landed, so it can become the only Collection Settings dialog. This PR removes the old WinForms dialog and its "Old Settings" button, along with everything only it used: its own save path, its settings/* endpoints, and its copies of the language chooser and several panels. With one dialog, each settings rule lives in one save path instead of two.

What the PR does

  • The old dialog is gone: both WinForms dialogs, the Old Settings button and its launch path, the four React tab bundles, the settings/* endpoints only they used, the legacy Create Team Collection path, and a startup check that could never fire. Every rule of the old OK handler is in the new save path, except the dead "experimental book sources" option.
  • The language chooser only runs in the browser. The Publish tab's sign-language link, its last WinForms user, opens it itself and saves with one POST.
  • The new dialog is simpler: it loads its settings before it shows and is rebuilt on every open; a non-administrator gets a small dialog of its own; the posted languages, with their fonts, go straight into the collection's list.
  • Strings, docs and e2e helpers: fifteen unused strings are marked obsolete (none deleted); the plan doc is removed; e2e helpers drive the language chooser (search, script, custom name) and the Languages page's Change…/Set…/Remove, taken from #8575.

Decisions

The e2e worker crash that this PR's front end sets off

On this machine, the Playwright worker process dies (exit code 3221226505, a Windows fail-fast) soon after the test fixture launches Bloom, so the tests after it never run. It hit xmatter-packs.spec.ts and font-chooser.spec.ts in all three runs today, and once on Oct 30. Runs split by which half came from where:

  • Master's Bloom with master's tests: 18 of 18 passed, twice.
  • Master's Bloom with this PR's tests: 18 of 18.
  • This PR's C# with master's front end: 18 of 18.
  • This PR's Bloom, front end included: crashed every time.

So something in this PR's front end sets it off, on Bloom's launch rather than in a test step. Master's nightly passes these specs, and this PR has never been through a nightly. Windows logged no crash event, so no module is named.

Share the subscription-badge row with Book Settings

This PR adds RowWithSubscriptionBadge, which draws a settings row with its subscription badge at the right, for the Collection Settings pages. Book Settings' Full Bleed row (BookSettingsConfigrPages.tsx) builds the same markup by hand. Moving the component next to the badge in react_components and using it there too would leave one copy of that layout.

Build the not-an-administrator message as plain text

The dialog a non-administrator sees gets its message from WorkspaceView.MustBeAdminMessage, which builds HTML for a message box; the GET reply then turns its <br> into line breaks with .Replace("<br>", "\n"). If anyone changes that markup, the dialog shows raw tags with no error. A small parameter (or two methods) could build each form from its parts.

Two lines in BL-16739's test notes

BL-17042's test ideas now send testers to BL-16739's notes for the Languages page. Two of its lines will mislead once this PR merges. "The old one is still there as Old Settings" stops being true. And "after changing languages around … each language should keep its own font" reads as if a font follows its language. A live check shows the opposite: when Change… replaces a language, the font and More settings stay with the position (swap English and French, and Written Language 1, now French, keeps English's font). That is how the code is written: the chooser changes only the name and tag.
