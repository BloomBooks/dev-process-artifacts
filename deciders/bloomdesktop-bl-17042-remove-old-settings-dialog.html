What this PR is about

Problem

Every page of the React Collection Settings dialog has landed, but the old WinForms dialog was still there behind an "Old Settings" button, with its own save path, its own settings/* endpoints and its own copies of the language chooser and several panels. Two save paths meant every rule had to be fixed twice, and the old one kept code alive that nothing else needed.

What the PR does

  • Removes the old dialog and everything only it used: the WinForms dialog and Script Settings dialog, the Old Settings button, the four React tab bundles, the old settings/* endpoints, the old Create Team Collection path, and a startup check that could never fire. Every rule of the old OK handler is in the new save path, except the dead "experimental book sources" option.
  • The language chooser now only runs in the browser. The Publish tab's sign-language link, its last WinForms user, opens it itself and saves with one POST.
  • Simplifies the new dialog: it mounts only while open, so every open starts fresh with no reset code; a non-administrator gets a reply holding just the reason; the Create Team Collection dialog gets its folder and name from the dialog (two endpoints fewer); fonts travel on the languages instead of a parallel array.
  • Strings and docs: ten strings nothing uses are marked obsolete (none deleted); the plan doc is removed; e2e docs, the run-bloom skill and the branding-report tool no longer describe or call the old dialog.

Two cleanup ideas from the review that I did not do

(a) The dialog lets a page change its own values just before saving (ISettingsPage.valuesToSave), which exists only so the Languages page can tidy the reader tools' alphabet (commas and line breaks into single spaces). Doing that tidy-up in C# instead would remove the mechanism, but breaks the plan's rule that clean-up belongs in the client and duplicates the tidying code. (b) The Subscription page asks Bloom twice per keystroke (the code editor and the status line each look up the code); fixing it means reshaping SubscriptionStatus, which the Collections tab shares, to save a local call that takes milliseconds. I recommend leaving both.

Do (a): clean the alphabet in C# (~60 lines removed, moderate; changes where a rule lives)
Do (b): one lookup per keystroke (moderate; touches a component the Collections tab shares)
