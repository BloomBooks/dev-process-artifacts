What this PR is about

Problem

Cloud Team Collections (BL-16531) was built in BloomDesktop PR #8052, with its Supabase backend sitting in the Bloom Editor repo by mistake. The backend belongs in bloom-core-supabase so it can be reviewed, merged and deployed separately from the Bloom client. The client, starting with the Share dialog (BloomDesktop #8394), is written against it. Reviewing the port also turned up real security and concurrency problems in that carried-over backend.

What the PR does

  • Port (first commit): the tc schema as declarative files plus its generated migration, the seven edge functions and their tests, the local dev stack and ops scripts under team-collections/, and an AGENTS.md.
  • Security: members can no longer call the "finish" functions directly. The edge function identifies the caller from their own token, then calls finish with the service role. Taking over someone else's checkout now needs a secret checkout token, stored only as a hash.
  • Concurrency and data safety: finish rechecks the lock and base version, so stale work can't overwrite newer work. Row locks are taken in one order, so retries are idempotent and there are no deadlocks. The stale-upload sweep waits a 48-hour grace period and rechecks each file before deleting it. Paths are Unicode-normalized, and rename conflicts and oversized sizes are refused, all at start.
  • Ops: the S3 endpoint is optional on hosted deployments, and the sweep's IAM permissions are complete.
  • CI: a new db-tests job runs the pgTAP suite on every PR.

The contract changes the Bloom client must follow are in team-collections/docs/CONTRACTS.md v1.8. Nothing is live until the migration is applied and the TC secrets are set on a hosted project.
