What this PR is about

Problem

Every toolbox tool has been React for some time, but the Edit tab's toolbox still ran the old jQuery accordion underneath it. toolbox.ts built each tool's panel into a hidden copy of the toolbox, and the visible React toolbox lifted those panels back out through events, a DOM observer and a quarter-second polling loop. Keeping two copies was dead weight, and it caused real bugs: the Talking Book busy cursor was aimed at the hidden copy so it never appeared, and a mismatch in how a tool id was spelled silently disabled image-description detection.

What the PR does

  • Deletes the legacy half: the accordion, the hidden toolbox, the lifting machinery and the accordion styling. The React toolbox builds each tool's panel directly, and each tool's panel is built once and reused.
  • Gives tool ids one home, with the conversions to the spellings books store, so what is written into a book is unchanged. Icons, always-on status and subscription markers now come from the tools themselves, and the "More..." list is derived from them instead of kept by hand.
  • Simplifies what a tool has to implement, and lets each tool supply its own stylesheet.
  • Fixes along the way: the busy cursor, image-description detection, an iconless header asking for an empty image, and a Decodable Reader crash in a book that has never saved toolbox settings.
  • Renames the accordion's vocabulary (second commit): "section" was the jQuery accordion's word for a tool's row, and the accordion is gone. ToolboxSection becomes OfferedTool, expandedSectionId becomes openToolId, and the spec file is renamed to match. "Offered" and "open" are the words the last PR in the stack already uses.

Nothing here is meant to look different to a user. This is the third of four PRs; #8402 and #8403 are merged, and the last one gives the toolbox's state and each tool's lifecycle to React.
