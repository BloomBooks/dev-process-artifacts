Explicit InvariantCulture searches are not covered by the rule

Devin pointed out that CA1310 only catches searches that pass no comparison. About 36 existing searches explicitly pass StringComparison.InvariantCulture (or its IgnoreCase form). One example is BloomServer.cs:903, which checks whether a path starts with localhost/. The rule doesn't flag these, and this branch leaves them alone.

They can't cause the Thai crash. The invariant culture is the same on every computer, so these searches never depend on the user's region setting. The card lists them as out of scope "unless someone decides otherwise". Ordinal would still be the more precise choice for paths and markup, and a little faster, but no bug is known. So the recommendation is to leave them for now.
