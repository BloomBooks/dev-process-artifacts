What this PR is about

Problem

The AI image editor is a separate app that Bloom opens inside the Edit tab, and it is English-only: whatever language a user has set Bloom's interface to, every button, label, message and art-style name inside the editor stays in English. Bloom already holds the editor's English strings — they went onto Version6.5 ahead of this PR so that Crowdin could start translating — but nothing yet hands them to the editor, and no translations of them had been committed.

What the PR does

  • As it starts, the editor sends Bloom its whole string table and Bloom answers with the ids it has a translation for. Anything Bloom does not know about runs in the editor's own English, so an editor build newer than Bloom's string files still works.
  • That exchange uses an endpoint of its own, aiImageEditor/localizations, rather than Bloom's general-purpose i18n/loadStrings, which reports every id it cannot find — on a Developer build that is a toast and a line written into the local xlf per string, hundreds of times per launch.
  • The launch reply also tells the editor which language Bloom's interface is in, so the editor can hide the text it deliberately never translates (the long art-style descriptions) instead of showing English inside a translated Bloom.
  • Spanish, French, Indonesian and Portuguese translations of the editor's strings are committed alongside the English.
  • The English strings are brought up to the editor release this PR pins, dist-v0.2.8: Improve Quality replaces Upscale, Extra Instructions moves to Change Style, the model chooser's rows gain tooltips, and the gallery gains a Reset zoom button and the lines saying where a picture came from. The pin moves from dist-v0.2.5 to dist-v0.2.8.
  • While the editor has a dialog of its own open, Bloom hides the close button it draws over the editor, so two close buttons a few pixels apart cannot shut the whole editor by mistake.

Worth knowing

  • The English strings for the editor already sit on Version6.5: you landed them separately so Crowdin could start, then improved their translator notes there. The PR's diff still shows all of them, because GitHub compares against the merge base, but the only English changes this branch now makes are the dist-v0.2.8 delta.
  • That earlier landing is also why the merge conflicted on 166 entries. It was resolved by rule, not by hand: the base's text won for every string both sides had, this branch's set of strings won, and the one changed English source was reapplied. Each of those was checked mechanically after the merge.
  • None of this has been exercised in a running Bloom during this run — no build was launched, and the editor's side of the exchange is only covered by the host-contract test.

The four language files are hand-edited

This branch writes Spanish, French, Indonesian and Portuguese translations of the editor's strings straight into DistFiles/localization/es|fr|id|pt. The project's standing rule is that only DistFiles/localization/en/ is ours to edit and the other language folders belong to Crowdin, so on the next sync whatever Crowdin holds for these ids wins and anything written here can be replaced or reverted without warning. In the meantime the text sits in the files looking exactly like translations a human translator reviewed. Devin has flagged it twice, and its thread is still open.

Notes

The editor's strings go to translators immediately

All of the editor's English entries are written without translate="no", so Crowdin picks them up on its next sync and translators can start on them straight away. The written rule is that a new entry carries translate="no" until we say it is ready, which keeps half-settled wording from reaching translators and being translated twice. Since getting this editor translated is the point of the card, this may well be what you want — but it is the opposite of the rule, and Devin flags it on every run until the thread is closed.

Notes

The newest editor text will show in English

The twenty-three strings added for editor release dist-v0.2.8 have no translations in the four languages: their entries carry the English text marked as still needing translation. So in a Spanish Bloom the editor will read in Spanish except for the Go buttons, the Improve Quality tool and its Image Kind menu, the gallery's Reset zoom button, the lines saying where a picture came from, and the tooltips on the list of AI models, which will read in English. Everything works; it just reads as a mix. The QA notes on the card now say this is expected, so a tester will not file it.
