The two edits

  • ToolboxRoot.tsx:826–827 — the tool headers get position: relative; z-index: 1005 back, so they sit above the Talking Book tool’s disabling sheet again.
  • audioRecording.less:502–513 — the sheet becomes width: 100% (was calc(100% - 20px)) with an explicit top: 0 in place of top: inherit.

Why it broke

The disabling sheet has always been a position: fixed element covering the whole toolbox viewport at z-index: 1001, headers included. What kept the headers looking and behaving normally was a rule in toolbox.less:271 targeting #toolbox h3. When the toolbox root became React/MUI in 6.4, the headers turned into AccordionSummary elements and that selector stopped matching them — the legacy #toolbox is now display: none, so the rule is dead code.

That is what made the long-standing calc(100% - 20px) suddenly visible: the 20 px it leaves uncovered started landing on the bright teal active header instead of on the panel-colored tool body. The gap itself was there in 6.3 too — measurable in the dark band above the headers — it just never fell on anything colorful.

The intended stack, restored

1002Show playback order switch, and the Help link
1001The translucent disabling sheet — 70% panel gray, swallows clicks
1000Microphone device list
autoEverything else in the tool — dimmed and inert while the mode is on

How Devin’s two flags were handled

  • Flag 1 — “the Help link’s z-index has no effect”: refuted and resolved. Devin reasoned that .help-link is a statically positioned <a>, so its z-index is ignored. But it is a flex item of .ui-audioBody, which is display: flex; flex-direction: column — and the Flexbox spec makes a non-auto z-index take effect on a flex item regardless of position. The margin-top: auto beside it (what pushes Help to the bottom) only works on a flex item, so it corroborates. Decisive evidence: in the reporter’s 6.4 screenshot, taken with the sheet showing, the word “Help” measures #FFFFFF, while white text that is under the sheet measures #6C6B6B in that same image.
  • Flag 2 — “headers stay clickable, including the Talking Book header”: mostly answered, one residual left open for you. The route Devin asked about is handled by design: removeRecordingSetup() checks the mode flag and tears the UI down when you switch tools or pages, deliberately leaving the switch checked so the mode resumes. And this fix does not newly enable the scenario — the un-dimmed 20 px strip is inside the header and clickable today, so it was already reachable. What is left is a genuine pre-existing gap; it is the first decision on the right.

Decision · from Devin flag 2

Collapsing the tool panel leaves the on-page number buttons behind

With Show playback order buttons switched on, the page shows a small numbered button on each text box, and the Talking Book tool panel is grayed out until you switch the mode back off. Because this fix makes the tool headers clickable again, you can now click the “Talking Book Tool” header itself to collapse the panel while that mode is still on.

If you then pick a different tool, everything cleans up properly. But if you simply collapse the panel and leave it collapsed, nobody tells the older toolbox code that the tool was put away — the React toolbox only notifies it when a different tool is opened, not when a section closes to nothing. So the numbered buttons stay sitting on the page with no tool open beside them. Re-opening the Talking Book tool, or choosing another tool, clears it up.

This is not new to your change. It arrived with the 6.4 React toolbox and applies to every tool in it — the old jQuery toolbox physically could not close a section to nothing, so 6.3 never had the situation. And the specific route was already reachable in 6.4, because the un-dimmed 20 px strip this PR removes is itself part of the clickable header. What your change does is make it obvious rather than accidental.

Decision · new consequence of this fix

The sheet now covers the panel’s scroll bar, so it can’t be dragged while dimmed

Widening the sheet from calc(100% - 20px) to the full panel width means it now also lies over the right-hand edge where the tool panel’s vertical scroll bar appears on a short window. While Show playback order buttons is on, that scroll bar can no longer be dragged with the mouse, because the sheet swallows the click.

Mouse-wheel scrolling still works — a wheel event over a covering element still scrolls the scrollable container underneath it — so the panel remains reachable, including the switch you need in order to leave the mode. That 20 px inset was almost certainly there to keep the scroll bar usable in the first place, and this is the trade for closing it. I recommend keeping the full width: it is what makes the reported stripe impossible to come back even if the header layering shifts again, and it leaves no strip of the panel that looks disabled but still accepts clicks.
