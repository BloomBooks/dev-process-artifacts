What this PR is about

Problem

Every so often the nightly's e2e suite fails with "1 error was not a part of any test", though every test passed: the fixture's teardown cannot delete the test's bloom-e2e-* temp folder ("EPERM, Permission denied"). It has happened three times (10-12, 10-13, 10-30), each right after a spec that restarts or relaunches Bloom.

Cause

Teardown kills Bloom, waits only until its HTTP port goes dark, then deletes the folder, counting on fs.rmSync's maxRetries to wait while the dying Bloom lets go of its files. On Node 24 (the repo's .node-version) rmSync does not retry on EPERM: it throws at once. Reproduced locally with a file held open by another process; on 10-30 it threw 0.15 s after the test ended.

What the PR does

  • After the port goes dark, the kill helper (now killAndWaitForBloomToExit) waits until the serving Bloom process has exited, within the same 15 s deadline. Windows closes a process's handles before it counts as exited, so the delete then succeeds. restart() and both stop()s use it.
  • Records the cause in docs/nightly-failures/README.md (nightly triage 2026-10-30).
