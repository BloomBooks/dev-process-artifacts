What this PR is about

Problem

BL-16271 is moving Bloom's collection Settings dialog off WinForms and onto React with Config-R, and nothing on master was ready for that work to start: the React side was an empty two-page skeleton that nothing launched, backed by a placeholder endpoint, and everything that saves collection settings lived inside the WinForms dialog's OK handler.

What the PR does

  • A React dialog shell. Seven Config-R pages in the new design's order, with localized labels and placeholder content, opened by a second Settings button on the collections toolbar. The WinForms button is relabelled "Old Settings" until the cutover.
  • Shared with Book Settings. Both dialogs keep the usual BloomDialog shape and share what Book and Page Settings already had: ConfigrDialogMiddle (only the form scrolls, with the select-padding fix) and the dialog size.
  • Opened from the browser, from any tab. showCollectionSettingsDialog(pageKey?) raises the dialog's launch event directly, and App renders the dialog, so later callers on any tab can open it on a named page.
  • A save path of its own, one place per setting. The GET returns the current values and which of them need a restart; OK posts { values, restartRequired } once, and C# reopens the collection if needed. CollectionSettingsValues is a live view of CollectionSettings: each simple setting is one property that reads and writes it, and [RequiresRestart] marks those needing a restart, so a new setting needs that property, its TS type and its Config-R control. CollectionSettingsUpdater holds what spans several values: the languages, the xmatter check, and the subscription, bookshelf and administrator rules ported from the WinForms OK handler. A save that fails is reported and leaves OK enabled.
  • Team Collection administrators only. A member who is not an administrator gets just the reason, in a small dialog with Close.
  • The WinForms dialog is untouched. It and its endpoints are exactly as on master; the two coexist only on alpha until the cutover.

The plan for the rest of BL-16271 is docs/collection-settings-react/PLAN.md (§3.0 records what was built).
