What this PR is about

Purpose

The site's book downloads (PDF, ePUB, BloomPUB/.bloomd, .bloomSource) now come through api.bloomlibrary.org/v1/fs instead of straight from S3. This is always on. Direct S3 downloads are billed AWS egress, and Cloudflare's rate limits and bot rules never see them. S3 URLs also show the book's S3 folder, which can include the uploader's email.

What the PR does

  • A new FsUrl.ts builds /v1/fs/{bucket}/{bookId}/{path}: upload for the PDF, harvest for the rest, with a dev- prefix for sandbox books. The URL carries no version.
  • Names are encoded for the fs function's double decode. A literal + or % is double-encoded; everything else is encoded once, so file names stay readable.
  • getArtifactUrl tries the fs URL first for those four downloads. When none can be built, it uses today's S3 URL. Reading online and everything else are unchanged.
  • Known quirk: titles with a literal + or % download under an encoded name until the API sends Content-Disposition.

Earlier work on versioned URLs and reading online through fs is kept on site-files-via-fs-versioned.
