What this PR is about

Purpose

The site's book downloads (PDF, ePUB, BloomPUB/.bloomd, .bloomSource) now come through api.bloomlibrary.org/v1/fs instead of straight from S3, with a version in the URL. This is always on, with no flags.

  • Direct S3 downloads are billed AWS egress, and Cloudflare's rate limits and bot rules never see them.
  • S3 URLs show the book's folder, which can include the uploader's email.
  • The version lets the worker cache each download for a year without serving a stale file.

What the PR does

  • FsUrl.ts builds /v1/fs/{upload|harvest}/{bookId}/{path}?v={epochMs}, with the dev- buckets for sandbox books.
  • The PDF is versioned by lastUploaded. Harvested files are versioned by harvestStartedAt, and are offered only once the harvest is Done.
  • Names are encoded for the fs function's double decode, with spaces as %20 as before, so Bloom Reader keeps the file names it already used.
  • There is no S3 fallback: with no fs URL, the download isn't offered.
  • All three download buttons get their link from getArtifactDownloadUrl, which adds download=1 so the server names the file; the links' download attribute is empty.
  • Reading online and shellbooks are unchanged.
