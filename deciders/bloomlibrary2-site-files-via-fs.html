What this PR is about

Purpose

bloomlibrary.org fetches book files straight from S3: the PDF, ePUB, BloomPUB and .bloomSource downloads, and every file of a book read online. Each of those fetches is billed AWS egress and is invisible to our Cloudflare rate limits and bot rules. This PR lets the site fetch them through api.bloomlibrary.org/v1/fs instead. Downloads can do so against today's production. Versioned URLs, which let Cloudflare cache files for a long time, wait for the API. All flags are off, so the site behaves exactly as today.

What the PR does

  • Builds /v1/fs/{bucket}/{bookId}[@{version}]/{path} (upload/harvest, or the dev- buckets for sandbox books).
  • kServeDownloadsThroughFs: downloads use fs URLs. This flag can be turned on now: with versions off, its URLs are unversioned, and production serves those today.
  • kFsUrlsIncludeVersion: adds @{epoch ms} (the last upload for the PDF, harvestStartedAt for harvested files). With it on, a file without a known version uses S3. It waits for the API.
  • kReadOnlineThroughFs: Bloom Player reads …/harvest/{id}[@v]/bloomdigital/index.htm, so the book's files come through fs too. It is meant to wait for versions.
  • Harvested files are only offered once the harvest is Done, as before. Names are encoded for the fs function's double decode.

Blocker for versioned URLs (not for downloads)

On 2026-11-13, api. and staging-api.bloomlibrary.org both returned 404 for {bookId}@{version}, and 200 without it. The bloom-core-supabase worker must strip and cache @version ("step 0") before kFsUrlsIncludeVersion or reading online goes on.

Real downloads checked

The code built each URL with downloads on and versions off. Every file of all four types that exists for three real books (spaces, El Niño, А+А) came through production fs byte-identical to S3. In Chrome, the .bloompub saved as ASB8 Nkhuku na dzongololo.bloompub, and the PDF opened as El Niño.pdf, as S3 PDFs do today. Only titles with a literal +/% get an encoded name (decision 1).
