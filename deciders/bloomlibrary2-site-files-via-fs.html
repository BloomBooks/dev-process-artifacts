What this PR is about

Purpose

bloomlibrary.org fetches book files straight from S3: the PDF, ePUB, BloomPUB and .bloomSource downloads, and every file of a book read online. Each of those fetches is billed AWS egress and is invisible to our Cloudflare rate limits and bot rules. This PR lets the site fetch them through api.bloomlibrary.org/v1/fs at versioned URLs, so Cloudflare can cache them without purging. Both parts are behind flags that are off, so the site behaves exactly as today.

What the PR does

  • Builds /v1/fs/{bucket}/{bookId}@{version}/{path} (upload/harvest, or the dev- buckets for sandbox books). The version is in the path so Bloom Player's relative links inherit it. With no version, the S3 URL is used, as before.
  • Downloads (kServeDownloadsThroughFs): the uploaded PDF is versioned by the last upload. Harvested files are versioned by harvestStartedAt, only when the harvest is Done. Each download's bucket and path are worked out once, and either URL is built from that.
  • Reading online (kReadOnlineThroughFs): Bloom Player gets …/harvest/{id}@{harvestStartedAt}/bloomdigital/index.htm, so all the book's files come through fs.
  • Names are encoded for the fs function's double decode: a literal + or % is double-encoded.

Blocker for turning the flags on

On 2026-11-13, both api.bloomlibrary.org and staging-api.bloomlibrary.org returned 404 for any {bookId}@{version} fs URL, while the same URL without @version returned 200. The bloom-core-supabase worker must strip and cache @version ("step 0") first.
