What this PR is about

Problem

On a computer whose regional format is Thai (probably Lao too), every Bloom operation that reads or writes the credits and license stored inside an image fails. That covers choosing a picture, editing its credits, and anything that saves images with metadata. It also breaks every book's cover thumbnail: selecting a book in the Collections tab replaces its thumbnail with a hazard sign (BL-16944). In a debug build it also trips an assert and Bloom exits.

Cause

When the TagLib# library isn't told a file's type, it works it out from the file name by searching for the last period. That search follows the current culture's sorting rules, and under Thai rules the period is ignored, so every file name looks like it has no extension and TagLib# refuses the file (the error ends in (taglib/)). libpalaso's credits code and Bloom's own code both reach TagLib# this way.

What the PR does

  • At startup Bloom registers a hook with TagLib#. When TagLib# can't identify a file but its real extension is a type TagLib# supports, the hook opens it as that type. Otherwise the hook does nothing, so unsupported or mislabeled files behave as before. One registration covers libpalaso's calls and Bloom's own (TagLibCultureFix.cs, registered at Program.cs:134). It can go once a TagLib# release searches ordinally (mono/taglib-sharp#381).
  • The test suite registers the same hook for every test. New Thai-culture tests (PNG and JPEG) cover saving and reading credits through libpalaso and Bloom's own direct call. They first confirm the runtime really ignores the period, so they can't pass for nothing.

Proof in a real 6.4 Bloom

I ran this branch's freshly built 6.4 Bloom with its culture forced to Thai, on a scratch copy of two books from "English Books", and clicked each book in the Collections tab. The same build ran twice. In run A a test hook switched the fix off; in run B the fix was on.

In run B both books' thumbnails were rewritten when clicked and matched the originals byte for byte, and clicking all 16 books on screen, templates included, raised no error.
