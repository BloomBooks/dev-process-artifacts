What this PR is about

Problem

On a computer whose regional format is Thai (probably Lao too), every Bloom operation that reads or writes the credits/license metadata inside an image fails with UnsupportedFormatException. That covers choosing a picture, editing its credits, and anything that saves images with metadata. The culture sweep's th-TH leg found it.

Cause

When TagLib# isn't given a mime type, it works one out from the file name with a culture-sensitive LastIndexOf("."). Under Thai ICU collation the period is ignorable, so the extension comes out empty and the mime type is taglib/. libpalaso's ClearShare code and Bloom's own code both call TagLib.File.Create(path).

What the PR does

  • Bloom registers a TagLib# FileTypeResolver (TagLib's own extension point) at the top of Program.Main. When TagLib's mime type is unknown but the extension found with Path.GetExtension is known, the resolver creates the file with the right mime type. Otherwise it stays out of the way, so mislabeled and unsupported files behave as before. One registration covers libpalaso's calls and Bloom's own direct calls. It can be removed once a TagLib# release searches ordinally (upstream fix: mono/taglib-sharp#381).
  • BloomTests registers it in a [SetUpFixture], as Program does. New th-TH regression tests (PNG and JPEG) cover the libpalaso save/read path and Bloom's RobustFileIO.CreateTaglibFile. They first check that the runtime really ignores the period, so they can't pass for nothing.
