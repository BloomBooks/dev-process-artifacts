What this PR is about

Problem

Checking what a change does to lameta's exports meant comparing with golden files of master's output, or with a generated project committed under sample data. Both have to be regenerated and re-reviewed whenever exports change on purpose. What John needs before publishing is different: what this build exports that the version testers or users have does not.

What the PR does

  • pnpm run compare-exports [<tag>] does the whole comparison. Unless it is given a tag, it compares with the newest beta or release (alphas are skipped; today v3.0.21-beta).
  • It makes a git worktree of that tag under tmp/compare-exports and installs it the first time; an install counts as done only once it finishes.
  • It generates the torture project with this checkout's generator for each version, checks that its paths fit Windows' limit, runs the export harness in both, and writes the differences to tmp/compare-exports/differences.txt.
  • The generator can be called in-process, and vitest no longer collects specs under tmp/.
  • #120, stacked on this PR, deletes the generated torture project from sample data and gitignores its folder; nothing reads it any more.
