What this PR is about

Problem

In a Match Sounds game, an audio button does nothing when its sound file has # in its name. This happens in the Game tool’s Play mode and in BloomPUB. A % in the name breaks the sound the same way, and the same goes for a game page’s correct-answer and wrong-answer sounds.

Cause

Bloom stores these sound names unencoded on purpose (BL-16669), so whatever builds a URL from one must encode it. The game runtime that plays them, in both Play mode and BloomPUB, is bloom-player’s, and it didn’t encode the name. So bird#1.mp3 was requested as audio/bird.

What the PR does

  • bloom-player now encodes the name (bloom-player#444, published as 2.22.0-alpha.2). This PR moves Bloom’s lockfile from 2.20.3-alpha.1 to that version. package.json already asks for alpha.
  • The UrlPathString.cs note that said Bloom Player doesn’t encode these names yet is updated, and the comment on the editor’s playSound now mentions # as well as %.
