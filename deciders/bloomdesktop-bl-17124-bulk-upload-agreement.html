What this PR is about

Problem

On Publish > Web, for a book whose upload agreements were already accepted, the three agreement boxes first showed unticked and then ticked themselves a moment later. A click in between was undone, and the screen and the saved value could disagree. The nightly bulk-upload test hit this after a Bloom restart: its click on the first box never stuck.

Cause

The screen fetched the saved value in a separate request from the book info, and each box started unticked and copied the value in later through an effect. Whichever request came back last decided what the boxes showed.

What the PR does

  • libraryPublish/getBookInfo now also returns agreementsAccepted (LibraryPublishApi.cs:151), so the boxes get their value in the same answer that enables them. The separate GET is gone; libraryPublish/agreementsAccepted is post-only (:503).
  • The parent holds the ticks as one array, and the boxes are controlled, with no state or effects of their own. They are rendered from one list of labels (LibraryPublishSteps.tsx:64, :813).
  • The save is posted from the change handler, only when "all ticked" changes (:220).
