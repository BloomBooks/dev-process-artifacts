What this PR is about

Problem

When a book whose original has a custom license (the user's own free text) is used to make a derivative, the Credits page reads:

This book is an adaptation of the original, Title, Copyright © 2007 Someone. Licensed under For permission to re-use this text, contact the copyright holder..

"Licensed under" makes no sense before free text, and the custom text's own full stop gets a second one. SIL PNG has more than 100 such books.

Cause

Bloom already had a rule that shows custom license text on its own. But whenever the original has a title and a copyright, and the UI language has the full sentence translated (English always does), Bloom uses the one-sentence template …, {0}, {1}. Licensed under {2}. instead, which skips that rule.

What the PR does

  • Custom licenses skip the full-sentence template, so the Credits page shows the copyright sentence followed by the user's text as typed. Creative Commons and "contact the copyright holder" originals are unchanged.
  • Existing derivatives pick up the new sentence the next time Bloom brings the book up to date (and so does the harvester), unless the user took over the sentence with the 6.6 override.
  • A new unit test covers the fixed sentence. Without the fix, it fails with the sentence from the bug report.
