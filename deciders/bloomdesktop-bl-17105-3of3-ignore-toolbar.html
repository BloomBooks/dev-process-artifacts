What this PR is about

Purpose

After #8598, a table cell set to L1 was stored as V, which shows whichever language the toolbar ticks first, so changing the toolbar changed the book's tables, and when the toolbar put another language first, the collection's first language could not be chosen for a cell at all. This PR adds a role, CL1, that names the collection's first language whatever the toolbar shows, and makes the table's menu use it.

What the PR does

  • CL1 works in any text box: Bloom shows its box, counts it when publishing, makes the box when the toolbar leaves that language out, runs it right to left when it should, and marks it bloom-contentCL1, which gives it the rich-text editor.
  • CL2/CL3 are other names for N1/N2, read in one place on each side. Nothing writes them yet.
  • Bloom before 6.6 refuses a book that uses these roles.
  • Boxes added or shown after page load look as they will after the next load, through a front-end copy of C#'s rules: table cells (including settings copied from older cells, now shown at once without waiting for the menus' names), new canvas text boxes, and the canvas Language submenu.
  • The canvas Language submenu still stores V/N1/N2, but names each entry for the language its setting shows and shows it at once; nothing changes when the toolbar's first language is the collection's first.
  • Bloom Player gets the matching change in bloom-player #450, and this PR moves Bloom to that release, 2.23.0-alpha.4.
