What this PR is about

Problem

A table dragged onto a canvas page puts one picture area inside another: each picture cell has its own. Several parts of the canvas code found a picture area's background picture by taking the first one anywhere inside it, and for the page's picture area that can be a cell's picture. Resizing the outer area, converting an old-style background, refitBackgroundImage, the hover buttons, Change Image, the tooltip, paste and the Motion tool could all act on the cell's picture. In the worst case the cell showed, and saved, the page's picture. Separately, a hidden picture area with a border reports a negative size, which slipped past the zero-size guard and produced nonsense geometry.

What the PR does

  • Every lookup of a picture area's own background picture goes through one function, getBackgroundCanvasElementFromBloomCanvas, which only accepts a picture whose nearest picture area is the one asked about. It still finds a picture that the Image Description tool has wrapped.
  • The fitting code skips a picture area whose width or height is zero or less, and waits for a later refit.
  • refitBackgroundImage returns a promise that settles once the picture is fitted.
  • Unit tests cover the nested cases, the size guard and the Image Description wrapper; the nested-canvas tests fail without the fix.
