What this PR is about

Problem

With the computer offline, searching Openverse or Pixabay in the Image Chooser did nothing visible: no error, no "No matches found", just an empty results area. The user had no way to tell that the search had failed, or why.

Cause

The results pane only showed an error when there were also images to show. Openverse reported its failure, but with no images, so it was never displayed. Pixabay didn't catch its failure at all, and the pane cleared itself as if nothing had happened.

What the PR does

  • Every failed search is now shown, even one that returned no images.
  • Offline failures get a translatable message: "Could not reach Openverse. Check that this computer is connected to the internet." A failure counts as offline when the server never answered. Other failures still show the existing untranslated technical message.
  • One shared helper reports failures for all online providers. Pixabay now catches its errors like Openverse does, and Wikimedia and Europeana (both disabled) use the helper too. A future provider that doesn't catch its errors still gets the same treatment from the search pane.
  • Losing the connection while scrolling keeps the images already loaded and shows the offline message below them. Scrolling again once back online retries the page that failed instead of skipping it.
  • An early warning appears under the search bar while an online source is selected and the browser reports being offline, and it updates as the connection comes and goes. It is a hint only, and it never shows for local collections such as Art of Reading.

Worth knowing

  • Checked by hand in the dev server with Chrome's offline emulation: the early warning, the offline errors for Openverse and Pixabay, the warning clearing when back online, a bad Pixabay key showing its own error, and no warning on Art of Reading. Retrying a failed later page could not be reproduced by hand, because the emulation left that request hanging instead of failing. That fix rests on reading the code and on the bots' re-reviews.
  • A failed Art of Reading search, for example with Bloom's local server down, now shows the untranslated technical error where it used to show a blank area.
  • To reach users, BloomDesktop still needs the two new strings added to its English .xlf files and an upgrade to the new package version. Neither is in this PR (see the questions).

Bump the package version in this PR?

BloomDesktop picks up this gallery as an npm package. The version in package.json is still 0.0.4. Earlier feature PRs bumped it so that BloomDesktop could upgrade unambiguously ("Bump version for unambiguous yarn upgrade in clients"). The last two merged PRs (#21 localization, #22 restyle) did not, so 0.0.4 no longer identifies one build.

Who does the BloomDesktop side, and when?

Two BloomDesktop changes are needed before users see this. First, trans-units for ImageLibrary.CannotReachSource and ImageLibrary.ComputerSeemsOffline in one of DistFiles/localization/en/*.xlf, so translators get the new messages. Second, upgrading BloomDesktop's bloom-image-gallery dependency to the new version. The upgrade can only happen after this PR merges and the version is published. The trans-units can be added any time.
