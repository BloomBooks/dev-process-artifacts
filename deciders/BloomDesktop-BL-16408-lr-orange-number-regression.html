What the French collection's settings told us

Mid-run you sent ReaderToolsSettings-fr.json from the French Decodable Leveled pack, which settles a question the two screenshots on the card had left open. In that pack the levels limit quite different things: levels 1–3 limit letters per word (6, 8, 10) and set no sentence limits at all, levels 4–6 limit words per sentence (5, 10, 15) and set no word-length limit, and level 7 limits only sentences per page.

I ran the real settings through the fixed component at every level. LR2's case is fixed: on levels 4, 5 or 6, the book's longest sentence of 16 words is now flagged orange, which is exactly what the tester expected. LR1's case depends on which level the book is at: on levels 1–3 its 11-letter word is now orange, but on levels 4–7 it stays green, and correctly so — those levels set no word-length limit, and 6.4 left it green too.

That matters because LR1's screenshot shows a blank Max cell on the "Word Lengths → this page" row, which only happens when the level has no word-length limit (4–7) — or when the tool has no level data at all. So either LR1 is on a level where green is the right answer, or something stopped the tool from seeing the level's limits. The first decision at right is about which.

Decision

Does LR1 in the French quick test need more work than this?

The tester reported two numbers that should have been orange and weren't. This PR definitely fixes LR2's (the 16-word sentence). LR1's — an 11-letter word under "Word Lengths → max in book" — is only supposed to be orange if that book is sitting on level 1, 2 or 3, because those are the only levels in that pack that limit word length. On levels 4–7 green is the correct answer and always was.

The reason to look twice is that LR1's screenshot shows nothing in the Max column on the row above it ("this page"), and on levels 1–3 that cell should show 6, 8 or 10. Two things could explain that: the book is simply on a level with no word-length limit (nothing more to do), or the tool drew its panel before it knew the level's limits, in which case every limit reads as unknown, every Max cell goes blank, and nothing can ever be flagged — a different bug, in the same panel, that this PR does not address. Devin independently noticed that unknown limits are silently treated as within-limit, which is what that failure would look like.

Decision

"Sentence Counts → total in book" can never turn orange

While checking Devin's claim that a third row had lost its colouring, I found something slightly different and pre-existing. That row is judged against a limit called "maximum sentences per book", and although the setting exists in the data, nothing in Bloom ever writes it — the Set Up Levels dialog has no field for it. So the limit is always zero, which means "no limit", which means the number can never be flagged, no matter how many sentences a book has. The code already carries a comment saying as much.

This is not a regression: 6.4 behaves identically, and it is outside what this PR set out to fix. But it does mean the row is decoration — it shows a count that is never judged against anything.

FYI

An average showing "9.0" can now be orange

The average rows are displayed rounded to one decimal place. Before this change the colour was decided from that rounded text, so an average of 9.04 against a limit of 9 counted as within the limit. It is now decided from the real value, so that row goes orange while still displaying "9.0" — which is what 6.4 did, and why I changed it back. The cost is that an author can see an orange number that looks equal to its limit with no way to tell why. The QA notes already warn the tester not to file that as a bug.
