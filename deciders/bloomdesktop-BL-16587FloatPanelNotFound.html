For your information

A Talking Book test fails intermittently in the full front-end suite

The first full run of the front-end tests this session had one failure, in the Talking Book tool's tests: it expected a sound file's address to begin with localhost:63315 but got localhost:3000. The second full run of the very same code was clean, so the suite is being reported as passing — but the failure is worth knowing about because it will surface again.

It is a timing race in the test, not a defect a user could hit. Those tests build their page inside a hidden frame that starts out blank, and the sound player's address is worked out relative to whatever address that frame currently has. If the assertion runs before the frame has settled, the address falls back to the test runner's default of localhost:3000 and the comparison fails. Nothing about the product's behavior changes either way — only whether the test looked a moment too early. Under load, when all 54 test files are competing for the machine, looking too early becomes more likely, which is why it appears in the full run and never when that file runs on its own.

This branch is not the cause. Running the Talking Book tests beside this branch's new test five separate times produced five clean runs, and swapping in unrelated stand-in test files changed nothing. The Talking Book tests arrived with the recent conversion of that tool to React, which is already on master. It also will not show up in the pull request's checks, because the front-end suite is not one of the checks GitHub runs on this repository.
