What this PR is about

Problem

On a derivative's credits page, the user can unlock the sentence about the original book's copyright and license and reword it. Deleting all the words is meant to hand the sentence back to Bloom, so that Bloom's own sentence returns, locked. Instead, testing found the sentence stayed blank after leaving the page, with the padlock still offering to unlock an empty field.

Cause

  • Bloom decides whether a save must update the book's data div by comparing the page's data before and after editing. The "before" comes from the book's own locked copy of the page, which has no data for the sentence, and an emptied field gives none either. So the save skipped the data div, and the user's old wording stayed.
  • The saved page took whatever the field held, an empty paragraph, and nothing put Bloom's sentence back.

What the PR does

  • A save from a page whose unlocked field is empty always updates the data div and removes the user's wording from it. This also covers a field that was centered or otherwise formatted before its words were deleted.
  • After a save that updates the data div, the saved page's sentence is rewritten from the data div. It shows the user's wording if there is any, otherwise Bloom's sentence, using the choice the full update already makes.
