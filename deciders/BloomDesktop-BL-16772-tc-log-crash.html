What this PR is about

Problem

A user whose Team Collection's local folder (under Documents\Bloom) contained read-only files could not open that collection at all. Bloom showed a raw "Access to the path …log.txt is denied" error report and gave up — even though Bloom has a disconnected-mode fallback (BL-16227) designed to open the collection anyway with Team Collection features switched off.

Cause

When Team Collection initialization failed (a sync write to the unwritable folder threw), the recovery path wrote an "initialization failed" message via TeamCollectionMessageLog.WriteMessage — which appends to log.txt in the same unwritable folder. That second exception escaped the constructor uncaught and killed the whole collection-opening process.

What the PR does

A failure to persist a Team Collection status message no longer stops anything: the file write is wrapped so the message survives in memory (the current session's status dialog still shows it) and in Bloom's own log, and the collection opens in disconnected mode as designed. A regression test makes the log file read-only and verifies the write doesn't throw and the message is retained. The PR targets Version6.4 directly — the affected user is on 6.4 Beta — and the change is deliberately minimal: one production method plus one test.
