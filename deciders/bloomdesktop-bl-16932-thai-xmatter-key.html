Decision 2 · from the local review

A shortcut in the xMatter folder can crash Bloom

Bloom finds an xMatter pack's name by looking for -XMatter in the folder name. XMatterPackFinder also follows any Windows shortcut in that folder and accepts whatever it points at without checking the name, so a shortcut to an ordinary folder makes XMatterInfo.Key throw. Long-standing; not introduced by this PR.

Chosen: Leave as is, and record the decision as a code comment
Committed as f354e18c5a: a comment beside the shortcut loop saying the missing name check is deliberate, what it causes, and why failing loudly is wanted when someone has hand-made a shortcut there.
