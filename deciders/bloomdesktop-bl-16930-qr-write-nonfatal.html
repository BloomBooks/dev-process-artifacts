What this PR is about

Problem

On 6.4.1, some users can't open a book at all. Selecting it fails with "A generic error occurred in GDI+" and every retry fails the same way. Both reports so far (BL-16915, BL-16930) had Avast running and the collection under Documents. In BL-16930 Bloom was also refused writes to license.png and a rename of a new book's folder, so something is blocking Bloom's writes across the whole collection folder.

Cause

When a book is selected, Bloom rewrites lang-qr-code.png for the "More books in this language" badge. Bitmap.Save throws when Windows denies the write, and the exception escapes the book's support-file update, so selection fails. The same failure on license.png was already caught and reported as a passive notice.

What the PR does

  • Saves the QR code image through ImageUtils.SaveOrDeletePngImageToPath, the helper license.png uses, so a refused write gives the usual passive "Could not update PNG image" notice and the book opens with its previous QR image.
  • Adds a unit test that holds the file open exclusively and checks that the badge HTML is still updated, a problem is reported, and the old image is left intact.
  • This is the part of #8398 (merged to Version6.5) that unblocks users. The extra diagnostics #8398 added to that notice are not backported.
