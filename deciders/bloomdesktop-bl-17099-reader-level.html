What this PR is about

Problem

In a book with no level saved yet (a new book), clicking the Leveled Reader's arrow within about a second of the tool appearing could be undone: the tool went back to the default level, and that default was saved in the book and as the starting level for new books. The Decodable Reader's stage had the same fault. A nightly hit it in reader-tool-stage-and-level.spec.ts ("each book remembers its own level"), where the first book reopened on level 1 instead of 2.

Cause

For a book with nothing saved, the tool asks Bloom for the default level or stage and applies and saves whatever comes back. The arrows work while it waits. In the nightly, Bloom took 1.2 seconds to answer; the test had moved to level 2 by then, and the late answer (1) was applied and saved over it.

What the PR does

  • The stage and level arrows are disabled while a reader tool restores the book's stage or level, so a click during the wait cannot happen (Andrew Polk's suggestion on the card).
  • The model counts the restores in progress, because a new page can start one while the last still waits; the arrows come back when the last one finishes, however it ends.
  • The e2e helper that waits for a restore also waits for the arrows to be enabled.
