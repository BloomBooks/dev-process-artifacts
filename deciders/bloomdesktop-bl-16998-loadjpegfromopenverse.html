What this PR is about

Problem

Some pictures chosen from Openverse in the Image Chooser could not be inserted. Bloom showed "Sorry, there was a problem adding the image" and logged Expected SOI marker at the start of the file. It happens with pictures from hosts such as images.rawpixel.com, a common Openverse source.

Cause

Those hosts serve WebP from addresses ending in .jpg. Bloom named the downloaded file after the address and loaded it with System.Drawing, which cannot read WebP.

What the PR does

  • Identifies a picture by its content, not its name. A new GetImageFileFormat recognizes JPEG, PNG, GIF, BMP, TIFF and WebP from the first bytes. A download is streamed to a temp file, named for what it really is, and deleted if the download fails.
  • Converts WebP before import with the GraphicsMagick Bloom already ships (ConvertToJpegOrPngIfNeeded). This covers downloads and WebP chosen from disk. Photos become JPEG; lossless, transparent or animated WebP becomes PNG, so line-art transparency keeps working.
  • IsJpegFile and IsPngFile share the new check. JPEG detection now also accepts valid JPEGs that don't start with an APP0/APP1 segment.
  • Unit tests with three small WebP samples, including malformed data that a download could contain.

Decisions

Let the Open File… dialog offer .webp pictures?

Bloom can now convert WebP pictures, including ones picked from the user's own computer. But the Image Chooser's Open File… dialog only lists JPG, PNG, BMP, GIF, TIF and SVG files, so a user with a .webp file saved from a web browser still can't pick it there. Browsers often save pictures as .webp nowadays. Devin flagged this (thread). Adding it is a new, user-visible capability rather than part of the bug fix, so it needs your call. The chooser's preview already treats .webp as something the browser can show.
