What this PR is about

Problem

Show in Folder (the Sign Language tool's, and Bloom's other "show this file in Explorer" commands) opens the right folder in File Explorer but leaves nothing selected, so the user has to look for the file. The nightly e2e test sign-language-advanced-import-delete.spec.ts (Test Case 584) fails on exactly this.

Cause

Bloom asks Windows through libpalaso's PathUtilities.SelectFileInExplorer, which calls SHOpenFolderAndSelectItems. On Windows 11 25H2, and on the GitHub Actions runners, that call selects the item only when the folder is already open in an Explorer window. When it has to open a new window, it shows the folder and selects nothing.

What the PR does

ProcessExtra.ShowFileInExplorerInFront, which every Show in Folder path goes through, now starts a short-lived background thread before it asks Explorer to show the item. The thread lists the Explorer windows that already show the item's folder (Show in Folder waits for that, at most 2 seconds), then for up to 10 seconds looks for a window showing the folder and selects the item there if it isn't selected. It never changes the selection in a window that already showed the folder. A new tab in an existing window counts as new, so this also works where Explorer opens folders in tabs.
