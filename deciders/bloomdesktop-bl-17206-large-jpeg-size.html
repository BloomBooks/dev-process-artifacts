What this PR is about

This PR changes only tests.

Problem. Both tests in file-meddler-large-image.spec.ts (Test Case ID 257) have failed every night since they were added. They stop at their own setup check that the photo they paste is over 1,000,000 bytes: on the runner it is 822,306 bytes. Bloom is never reached.

Cause. The fault is in the test. makeJpegFile draws the photo on a browser canvas, and Chromium dithers canvas gradients only when it draws on a GPU, so the photo compresses much better on a machine without one. With Bloom's WebView2 started with --disable-gpu, this machine wrote the 6000×3375 photo in exactly the runner's 822,306 bytes (1,362,156 with its GPU). Bloom shrinks a picture by its pixel size, so the byte count matters only to the test's own idea of "large".

Fix.

  • The spec's photo is now 8000×4500: 1,336,949 bytes without a GPU and 2,310,321 with one. It is still 16:9 and still far larger than anything Bloom keeps.
  • The setup check's message now says what it checks ("over a megabyte").
  • makeJpegFile's doc comment records that its file size depends on the GPU.
