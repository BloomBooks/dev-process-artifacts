What this PR is about

Problem

Debug builds of Bloom sometimes die during startup with Assertion Failed: If at all possible, you should provide an appropriate acceptFinalUrl param when looking up a url during startup. Release builds don't crash, but on a slow connection they make a blocking server request for each book while the collection loads.

Cause

Loading a collection built a Bloom Library page URL for every uploaded book, at two points. The background status fetch built one per book, and the badge on every book button asked for it as soon as the button appeared. Building the URL needs the Bloom Library address, which comes from a server lookup. When that lookup hasn't finished yet, which is usual on a cold start, each request either trips the assertion or blocks until the lookup is done.

What the PR does

  • The status Bloom keeps for each uploaded book holds the book's ids instead of a URL, and builds the URL only when asked (GetBloomLibraryBookUrl).
  • The badge-info API reports only whether the book is on Bloom Library and what state it is in there (CollectionApi.cs:951).
  • A new collections/openBookOnBloomLibrary endpoint builds the URL and opens the browser when the user clicks "View on BloomLibrary.org" (CollectionApi.cs:975). It runs off the UI thread. Clicking the link doesn't select the book.

Nothing on the collection-load path looks up a URL any more. Users see the same badges, and the link opens the same pages.

Worth knowing

  • Nobody has tried this in a running Bloom yet. The badge link now opens through a Bloom API call instead of an ordinary web link, so clicking it once is the check that matters.
  • The new unit tests check how the URL is built. No test checks that loading a collection makes no URL lookup.

Decisions

Check the badge link in a running Bloom?

The badge link used to be an ordinary web link. Now it calls a new Bloom endpoint that builds the address and opens your browser. Unit tests cover building the address, and nothing has exercised the click. An agent can check over the automation connection that the badges still appear with the right states. It can't click the link without opening a browser window in front of you.

John Hatton's request for a broader review

On the card, John Hatton asked for an AI review of "everything around this Bloom Library URL stuff plus the count of books", recalling inefficiencies that were noticed but never worked on. This PR fixes only the per-book URL lookup. It doesn't look at book counts or the other Bloom Library queries.
