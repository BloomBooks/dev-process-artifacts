What this PR is about

Problem

Debug builds of Bloom sometimes die during startup with Assertion Failed: If at all possible, you should provide an appropriate acceptFinalUrl param when looking up a url during startup. Release builds don't crash, but on a slow connection they make a blocking server request for each book while the collection loads. A review of the surrounding code (requested on the card) also found that the badges cost far more than they need: the status query ran two or three times per collection open, each badge then made its own request, and each of those rescanned every book folder.

Cause

Loading a collection built a Bloom Library page URL for every uploaded book. Building it needs the Bloom Library address, which comes from a server lookup that usually hasn't finished on a cold start, so each request either tripped the assertion or blocked.

What the PR does

  • A book's status holds its ids, not a URL. The URL is built only when the user clicks "View on BloomLibrary.org", through a new collections/openBookOnBloomLibrary endpoint (BloomLibraryStatus.cs).
  • The collection keeps its books' statuses, so list rebuilds don't lose them, and queries Bloom Library in the background only for books it has never asked about: normally once per collection open (BookCollection.cs).
  • Each query ends in one websocket message with the whole collection's badge state. The book list holds it and hands it to each button, so buttons rendered later get it too; it re-reads the state when it appears and whenever its websocket (re)opens (BooksOfCollection.tsx). Badges make no requests of their own.
  • No more example.com probe before the badge query or the language book count. A failed query leaves the badges alone and is retried at the next list rebuild. Offline, Open Collection cards show no "unpublished" count instead of counting every book.
  • Unrelated, included because we hit it: the dev-only LESS watcher retries renaming its state file briefly on Windows, where another process can hold the just-written file for a moment (watchLessManager.js).
