What this PR is about

Problem

Going from the Publish tab to the Collections tab sometimes showed "Bloom had a problem: Cannot empty page while editing" (14 Sentry reports from 5 people since August). It needed a page click in Edit immediately followed by a click on Publish, and then a Publish tool that ran the page layout update.

Cause

  • A thumbnail click that reached Bloom after the switch to Publish was still acted on: the hidden Edit tab started navigating to that page, though nothing was shown.
  • Publish's page layout update loads every page off-screen with the editing code, and each one reports "my DOM has loaded" to the Edit tab. The off-screen load of the awaited page made the hidden tab believe it was editing it, and leaving Publish then tried to empty an "editing" page.

What the PR does

  • No page is loaded while the Edit tab is hidden. A request that would show one still runs its action and saves; the page it names is shown when the user returns to Edit.
  • Only the Edit tab's own load counts. Each navigation gets a number, passed in the page URL and sent back with the page's "loaded" report; only the awaited navigation's report moves the tab to Editing.
  • An e2e test of the card's sequence (late-page-click-after-leaving-edit.spec.ts, Test Case 861), which fails with both fixes switched off. Its helpers find Publish destinations by their label, for every test that picks one.
