What this PR is about

Problem

Nothing automatically checked that changing Bloom's interface language actually changes what is on screen, although translated text reaches the UI by several separate routes, any of which can break silently. The "Show translations which have not been approved yet" option, and the language menu in the Choose Collection dialog, had no automated coverage at all. This is manual Test Case 69, "change UI language repeatedly".

What the PR does

  • A workspace test switches the real language menu through English, French, Spanish and Turkish, checking one visible string per translation route after each switch. It then checks the unapproved-translations gate both ways, using Turkish text that is translated but never approved.
  • A second test starts Bloom at the Choose Collection dialog, switches the dialog to French, then opens a collection and checks the whole workspace comes up in French.
  • The e2e fixture gains a Choose-Collection launch mode and a way to re-find Bloom's page after a language change rebuilds it. It shares master's per-launch settings folder, so no test touches the developer's own settings. The language helpers extend master's Pseudo-English ones.
  • Bloom itself changes only when started by the test tools. It skips its self-restart when the unapproved option is toggled (the test restarts it instead). Its Choose Collection dialog and React dialogs follow the same "don't take focus, use the monitor you are told" rule the main window already follows.

Dialogs don't take keyboard focus in ./go.sh sessions

To keep test runs from grabbing the keyboard while you work, this PR makes every React dialog open without activating, and stops the Choose Collection dialog from bringing itself to the front, whenever Bloom runs with --automation (ReactDialog.cs:27, Program.cs:2294). The main window and splash screen already follow that rule.

But ./go.sh also passes --automation to every dev Bloom. So when you test by hand through the dev launcher, a dialog such as Collection Settings may open without the keyboard: Enter, Escape and typing do nothing until you click in it, and the Choose Collection dialog can open behind other windows. An installed Bloom is unaffected.
