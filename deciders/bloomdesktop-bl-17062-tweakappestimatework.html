What this PR is about

Purpose

Two follow-ups to #8531, which made the Apps screen's size estimate use the actual size of BloomPUBs Bloom keeps between visits.

  • Estimates after a Bloom update. Each kept BloomPUB's record names the Bloom that made it, so after any update every one was thrown out and the size bar fell back to rough estimates until the user measured or built again. A BloomPUB the earlier Bloom made from the unchanged book with the same settings is still a much better guide to the book's size than the estimator.
  • Feedback on OK in Choose Books. Testers saw a pause after clicking OK with no sign that anything was happening.

What the PR does

  • The Apps size estimate now uses the size of a BloomPUB made by an earlier Bloom when the book and the publish settings haven't changed. It still counts as an estimate (striped, not "measured"), and Build and Measure still make it again, exactly as before.
  • When a book no longer matches its kept BloomPUB, Bloom remembers that verdict for the book's current state, so the repeated size requests on the Apps screen don't read the whole book again each time. The cheap meta.json check now runs before the whole-book content hash.
  • In Choose Books, clicking OK shows a spinner and disables OK and Cancel until the save finishes and the dialog closes. The X, Escape and clicks outside the dialog are ignored meanwhile, since the save can't be stopped once it has started.
