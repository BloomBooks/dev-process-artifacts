What this PR is about

Problem

Pasting a picture into a text block pasted the picture's file path as text instead of the picture. Ctrl+V in a text block is left to the browser and CKEditor, and most picture copies (Bloom's own Copy Image, a file copied in Explorer, a browser's "Copy image") put the path or URL on the clipboard as text beside the picture, so the text is what got pasted. The top-bar Paste button sent the picture to the page's canvas instead, or pasted the same text.

What the PR does

  • With the focus in a text block that can take inline images, pasting a picture (Ctrl+V or the Paste button) adds an inline image holding it to that block, docked right at the start of the block, where Insert Image puts one.
  • With an inline image selected, the pasted picture replaces its picture instead, through the image's own "Paste image" command. Bloom leaves an image it has just inserted or pasted selected, so Insert Image followed by a paste fills the new image, and a second paste right after a first replaces it, as on a canvas.
  • It reuses the canvas paste's round trip, so there is no C# change. The image appears only once the picture has arrived, so a failed or cancelled paste leaves nothing, one Undo takes back the paste, and a save made in the meantime waits for the picture.
  • A clipboard with formatted text as well as a picture (Word, Excel, part of a web page) still pastes as text. Blocks that can't take inline images, and a paste with a canvas picture selected, behave as before. The Paste button with the focus in a text block now pastes there instead of onto the canvas.

Should a second paste replace a picture Bloom has just added?

A paste with an inline picture selected now replaces that picture, as you chose. But "selected" includes pictures Bloom selects itself: a picture just added with Insert Image, just pasted, or just changed by Undo stays selected, with its handles showing, until the user clicks somewhere else on the page (typing does not deselect it). So Insert Image followed by a paste fills the new empty picture, which is handy, and pasting twice in a row replaces the first picture rather than adding a second. That is also what the canvas does: a picture pasted onto a canvas stays selected, and the next paste replaces it. To add a second picture, the user clicks in the text first. The test ideas on the card describe this.
