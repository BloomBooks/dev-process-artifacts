What this PR is about

Problem

Pasting a picture into a text block pasted the picture's file path as text instead of the picture. Ctrl+V in a text block is left to the browser and CKEditor, and most picture copies (Bloom's own Copy Image, a file copied in Explorer, a browser's "Copy image") put the path or URL on the clipboard as text beside the picture, so the text is what got pasted. The top-bar Paste button sent the picture to the page's canvas instead, or pasted the same text.

What the PR does

  • With the focus in a text block that can take inline images, pasting a picture (Ctrl+V or the Paste button) adds an inline image holding it to that block, docked right at the start of the block, where Insert Image puts one.
  • With an inline image selected, the pasted picture replaces its picture, through the image's own "Paste image" command. Bloom leaves an image it has just inserted or pasted selected, so Insert Image followed by a paste fills the new image, and a second paste right after a first replaces it, as on a canvas.
  • It reuses the canvas paste's round trip through C#. The image appears only once the picture has arrived, so a failed or cancelled paste leaves nothing, one Undo takes back the paste, and a save made in the meantime waits for the picture. The "Paste image" command now holds that wait for every picture, canvas ones too, and ignores a second paste over a picture still being replaced.
  • One small C# change: when importing a pasted picture fails, C# now tells the page, which before was left waiting.
  • A clipboard with formatted text as well as a picture still pastes as text. Blocks that can't take inline images, and a paste with a canvas picture selected, behave as before.
