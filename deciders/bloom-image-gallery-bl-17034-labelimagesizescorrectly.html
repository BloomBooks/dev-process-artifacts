What this PR is about

Problem

When you pick a Pixabay picture in the Image Chooser, the details panel shows the original's dimensions and file size, often thousands of pixels. But Bloom downloads a smaller copy, at most 1280px on its longer side. So a user who sees "5184 × 3456" expects a picture big enough for an A3 page, and gets one Bloom then has to stretch.

Cause

Pixabay only gives ordinary API keys (like the ones users paste into Bloom) its largeImageURL, which it scales down to 1280px. The full-size and 1920px versions need full API access. The provider downloads largeImageURL but reported the original's width, height and byte size.

What the PR does

  • Pixabay results now report the dimensions of the copy we download. These are worked out from the original's size, scaled down to fit within 1280px and never scaled up. The details panel and the result tiles' captions both show them.
  • The provider no longer reports the original's file size. The details panel asks the server for the size of the file we'll download, instead of the preview it used to ask about. Pixabay's image server refuses that cross-site request, so for now Pixabay pictures show no file size. That's the open decision.
  • Selecting another image clears the previous image's file size, and a late answer about an earlier image can no longer overwrite the current one.

The downloads are no bigger than before: with an ordinary key, 1280px is the most Pixabay offers.

Worth knowing

  • Nobody has run the change in the gallery or in Bloom. The scaling has unit tests, but the panel itself hasn't been seen.
  • Pixabay may round the short side differently from our Math.round, so a displayed dimension could be one pixel off. This couldn't be checked without an API key.

What should the panel show as a Pixabay picture's file size?

Bloom downloads Pixabay's 1280px copy, and Pixabay's search results don't say how many bytes that copy is. They only give the original's size, which can be several times bigger. The panel now asks Pixabay's image server for the copy's size. But that server sends no permission for cross-site requests (CORS), so the browser blocks the answer. Devin confirmed this. The result: Pixabay pictures show no File size row, and every Pixabay selection logs an error in the browser console.

The dimensions, the substance of the ticket, are correct either way.
