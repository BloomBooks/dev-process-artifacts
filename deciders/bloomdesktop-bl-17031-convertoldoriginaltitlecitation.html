What this PR is about

Problem

Some derivatives of old books, such as The Young Man and The Dragon: Parasitic Worms, show raw markup on the Credits page (<cite data-book="originalTitle">…</cite>) where the original title should appear in italics. Unlocking the sentence for editing copies that same markup into the user's editable text.

Cause

In those books the original title has a line break in it. The filter that escapes markup in the credits sentence lets one <cite> through, but the regex it uses to find that cite could not match across a line break. So the cite was escaped along with everything else.

What the PR does

  • The cite-finding regex in HtmlDom.SetElementFromUserStringSafely now matches across line breaks. Titles without a line break come out exactly as before.
  • Bloom rebuilds the sentence every time a book loads, so affected books look right as soon as they are opened. No migration is needed.
  • New unit tests cover the filter and the unlock path with a two-line title.
