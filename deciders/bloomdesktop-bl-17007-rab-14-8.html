What this PR is about

(1/2) Andika text showed in the phone's font

Problem. In apps built from Bloom, Andika text showed a two-story "a", online or offline.

Cause. RAB shipped Andika under names bloom-player never asks for, and RAB apps have no internet permission for its fallback (app-builders #2510).

Fix. RAB 14.8 fixes it, so Bloom 6.5 now installs RAB 14.8 instead of 14.0.1. Existing users are asked to update with Prepare. An app built with an older RAB then shows as needing a build, so "Try on phone" can't install the old, still-broken app.

(2/2) Every book in an app's contents menu showed the same picture

Problem. In an app with several books, every contents-menu entry showed one book's cover.

Cause. Bloom writes the menu itself and named every book's picture thumbnail.png; RAB packages pictures by name, so one won. RAB's own fix (#2529) only covers menus RAB builds.

Fix. Bloom names each book's menu picture after the book (<book id>-cover.png) and, in the step that already copied each BloomPUB's fonts into the project, now also copies its thumbnail under that name. A book with no thumbnail gets no picture, as in RAB's own menus. Bloom still writes the menu, so titles and order stay Bloom's.

  • The final picture code was checked inside a built APK (five menu pictures, each identical to its own book's thumbnail) but not on a phone; the emulator was stopped for low memory. The card's test ideas ask a tester to look at the menu on a real phone.
  • The Windows admin prompt for the RAB installer has always been part of installing RAB through Bloom (RAB installs into Program Files); what's new is that 14.0.1 users see it again for the update.

1. Two existing tests now expect each book's own picture name

SetBookEntries_ReplacesBookEntries_AndPreservesCollectionMetadata and Build_ReusedBloomPubRefreshesTrackedThumbnailFileName used to expect the shared thumbnail.png/thumbnail.jpg in the app's contents menu, which was this bug. They now expect each book's own name (book-1-cover.png, book-2-cover.jpg, book-1-cover.jpg). Changing what an existing test asserts needs your OK.

2. The message after clicking No on the installer's admin prompt

Installing or updating RAB through Bloom has always shown a Windows admin prompt: RAB's installer (Reading App Builder - Setup.iss) installs into Program Files and writes the machine-wide registry, and Bloom has installed it there since April (Hatton, 807bd4314a). I found no card about the prompt. Clicking No makes the installer exit with code 2, and Bloom says "Bloom could not update Reading App Builder. Please use Help > Report a Problem…", probably what the reporter's log shows. Every 6.5 user who builds apps sees the prompt once more for this update.
