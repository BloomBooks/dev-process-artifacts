What this PR is about

(1/2) Andika text showed in the phone's font

Problem. In apps built from Bloom, Andika text showed a two-story "a", online or offline.

Cause. RAB shipped Andika under names bloom-player never asks for, and RAB apps have no internet permission for its fallback (app-builders #2510).

Fix. RAB 14.8 fixes it, so Bloom 6.5 now installs RAB 14.8 instead of 14.0.1. Existing users are asked to update with Prepare. An app built with an older RAB then shows as needing a build, so "Try on phone" can't install the old, still-broken app.

(2/2) Every book in an app's contents menu showed the same picture

Problem. In an app with several books, every contents-menu entry showed one book's cover.

Cause. Bloom writes the menu itself and named every book's picture thumbnail.png; RAB packages pictures by name, so one won. RAB's own fix (#2529) only covers menus RAB builds.

Fix. Bloom names each book's menu picture after the book (<book id>-cover.png) and, in the step that already copied each BloomPUB's fonts into the project, now also copies its thumbnail under that name. A book with no thumbnail gets no picture, as in RAB's own menus. Bloom still writes the menu, so titles and order stay Bloom's.
