What this PR is about

Problem

Testing the new Pseudo-English UI language (BL-16748) showed that the Report button on Bloom's small problem notifications stays English in every UI language, and so does the Details button on the same notifications. The Report button on Bloom's problem dialogs ("Bloom had a problem …") has never been translated either.

Cause

The notification buttons were hard-coded English labels. The dialog's Report button did ask for a translation, but under the id ErrorReportDialog.Report, which exists in no XLF file, so there was never anything to find. It was also looked up once in C# and kept, which is why it needed a special call once localization was ready (BL-13245) and would have kept the old language after a UI language change.

What the PR does

  • The notification's Report button and the dialog's Report button both use the existing ErrorReport.Report string, already translated in many languages (Spanish "Reportar", French "Signaler"). C# sends only the English label and the id, and the front end translates it as it is shown.
  • The Details button gets a new ErrorReport.Details string in BloomLowPriority.xlf.
  • The dialog's Report button now translates itself the way its Close button always has, so it follows a UI language change, and the startup call is gone. A label a caller supplies still arrives already translated.
  • DistFiles/localization/README.md gets one list of what stays English under Pseudo-English and why (whole-file localizations, the language chooser, developer-only messages), and notes that a new book's folder takes the localized word for "Book".
