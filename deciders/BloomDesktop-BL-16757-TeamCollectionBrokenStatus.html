For your information

UserName has the same type gap, harmlessly

While widening UserId I noticed UserName beside it is also declared a plain string for a C# field that is equally nullable. I did not touch it, because you chose two specific declarations and that was not one of them.

It is worth knowing that this one cannot bite the way UserId did: a null UserName is only ever used as text in the table and as react-avatar's name, and both handle it — react-avatar's initials source tests !!(name || value || email) and simply falls through to the placeholder. So it is a type-honesty gap, not a latent crash. In the reporting collection those rows carry an empty string rather than null anyway.
