The C# suite aborts intermittently, and it is not this branch

Found by this preflight run. Pre-existing; not caused by the change.

Twice today the full C# suite did not finish. It stopped after about 350 of 3082 tests with the whole test host process dying — ObjectDisposedException on HttpRequestQueueV2Handle, thrown inside HttpListenerResponse’s asynchronous close. In plain terms: a BloomServer used by a test is disposed while a response it was still writing is completing, and the crash takes the entire run down with it, so every remaining test is simply never run.

It is a race, so it comes and goes: a third run of the identical tree finished green. That is exactly what makes it worth recording — an intermittent abort is easy to shrug off as a fluke, and the practical cost is that anyone running the suite has a real chance of getting no answer at all, and may not notice that “349 passed” is not the same as passing.

FYI: one more escaping gap, much narrower

Surfaced while refuting a Devin flag. Pre-existing, out of scope.

Devin claimed a second hand-rolled escaper in the same file fails to escape backslashes. It does escape them, and in the correct order, so I refuted that on the PR. But checking it turned up a smaller real gap: EscapeJsonValue handles the backslash, the double quote, carriage return and newline, and nothing else — so a literal tab, or any other character below U+0020, would go into the JSON unescaped, which the JSON standard does not allow.

The text going through it is book page content, so a tab is far less likely than the quote mark that caused this card, and none of it is touched by this branch. Recording it here rather than acting on it.
