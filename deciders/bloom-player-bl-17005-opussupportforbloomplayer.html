What this PR is about

Problem

Bloom is moving narration recordings from MP3 to Opus, which gives much smaller files. Bloom Player always asked for audio/<id>.mp3, so a talking book with Opus narration would play no sound at all.

Cause

The book's HTML identifies each recording only by its element's id, and the player appended .mp3 when it built the file URL.

What the PR does

  • Narration file URLs now take their extension from the nearest data-audio-ext attribute: on the sentence or text box itself, on its page, or once on <body>. Without the attribute they stay .mp3, so every existing book behaves exactly as before. One book can mix formats, which is likely during the switchover when someone re-records a few sentences in an old book (narration.ts:1090).
  • The player looks for the sentence on the current page, because the pages either side stay loaded and can reuse the same ids (narration.ts:1099).
  • A new end-to-end test plays a real Opus narration in the built player, from a small new test book (public/testBooks/opus-talking-book). The test server can now serve .opus and .ogg files.
  • A new root AGENTS.md tells agent workflows which issue tracker this repo uses.

We chose an attribute over trying one extension and falling back to the other. A fallback can't tell "wrong extension" from "never recorded", and on Bloom Library every miss costs an extra round trip, which shows up as a longer pause between sentences.

Worth knowing

  • Opus playback is tested end to end in Chrome only. Older Safari versions can't play Ogg Opus, and nothing here tests that.
  • Bloom Desktop still has to write data-audio-ext="opus". Its Talking Book tool also builds .mp3 paths of its own (audioRecording.ts). Until both are done, no real book uses the new path.
  • Prettier flags narration.ts and e2e/server.mjs for formatting that was already there on master. It was left alone to keep this diff focused.
