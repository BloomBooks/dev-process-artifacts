What this PR is about

Problem

On a Canvas page, after you choose a Layer command from one element's menu and then open the menu of a different element, the menu opens with the Layer row already highlighted and its submenu showing, covering the rows beside it. Reloading the page stops it. Colin Suggett reported this on BL-15992.

Cause

The Layer row comes from the mui-nested-menu-item library, and it keeps its submenu open until the pointer leaves the row. React counts the submenu as part of the row, so clicking a command in it shuts the whole menu while the pointer is still "inside" the row. The canvas element menu stays mounted while shut, so the row still has its submenu open the next time the menu opens.

What the PR does

  • LocalizableNestedMenuItem rebuilds its row, with the submenu closed, each time its parent menu shuts. Rows in menus that don't report whether they are open behave exactly as before.
  • A new unit test reproduces the bug and fails without the fix.
