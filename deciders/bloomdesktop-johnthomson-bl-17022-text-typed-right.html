What this PR is about

Problem

Text typed into a box in the first moment after a page opens in the Edit tab could disappear without any sign, at about the moment the page finished loading. On a fast machine the window is too short to hit by hand, but a slower machine widens it to a second or two, and the nightly CI runner repeatedly lost book titles typed on a new book's cover this way.

Cause

CKEDITOR.inline() copies each box's content when Bloom attaches it and returns before the editor is ready. When the editor finishes loading, its loaded handler writes that copy back into the box, replacing whatever was typed in the meantime.

What the PR does

  • Just before CKEditor's own loaded handler runs, Bloom refreshes the editor's copy from what the box holds by then, so the rewrite writes back the person's own text; the caret is noted first and put back once the editor is ready (keepTypingWhenCkEditorLoads.ts:90, called from bloomEditing.ts:2127).
  • A Games page's default instruction is written again on editor-ready only if the box is still blank, so it no longer replaces text typed over it (PlaceholderProvider.ts:71).
  • A new e2e test holds back CKEditor's config.js, types while the editor is still loading, then lets it load; without the fix the box comes back empty.
  • The e2e helpers no longer wait for CKEditor before typing, so every typing spec exercises the fix; the [cover-title] logging stays for a few nightlies, and AUTOMATION-DEBT.md records the fix.
