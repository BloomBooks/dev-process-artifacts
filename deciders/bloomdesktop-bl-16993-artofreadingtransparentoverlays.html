What this PR is about

Problem

An Art of Reading picture (or any black-and-white line art) placed as an image overlay on a canvas is not made transparent when the page is white. Its white rectangle covers the background picture beneath it. The same image in an ordinary picture box on a coloured page is transparent, so the "Auto" transparency setting looks broken for overlays.

Cause

Since 6.5 (BL-16336), "Auto" transparency is requested only when the page has a non-white background colour. Nothing treats an image layered over other canvas content as needing transparency, so on a white page an overlay is served as the original opaque file. The image itself is fine: Art of Reading files pass the line-art detection.

What the PR does

  • Overlays get Auto transparency on any page. Under Auto, an image in a canvas overlay (any canvas element other than the background image) is now treated as needing transparency. This applies in the edit view, thumbnails, PDF, BloomPUB and ePUB. The line-art check still decides, so photos stay opaque, and the explicit Opaque / Transparent choices still win. See bloomImages.ts:528 and HtmlDom.cs:2085.
  • Role changes keep it right. "Become Background" and duplicating the background image both recompute each image's transparency for its new role (canvasControlRegistry.ts:778).
  • PDF without background colours. These PDFs now honour overlay transparency too. That setting already removes page-colour transparency earlier in the pipeline, so the server's extra check only blocked overlays (BloomServer.cs:1023).
  • Analytics. The "Image Transparency Set" event records whether the image is an overlay.
