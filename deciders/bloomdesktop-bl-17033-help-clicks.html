What this PR is about

Problem

After about six presses of a Help button in one of Bloom's React dialogs (Book Metadata, Collection Settings, Decodable Reader setup, Team Collection), Help stopped opening. Other parts of Bloom also quietly stopped updating until a restart.

Cause

The help, externalLink and app/showDownloadsPage endpoints all finish with ExternalLinkSucceeded(). That method set a 200 status but never closed the response, so every press left one request hanging. Once the browser's connections to Bloom's server were all used up, other API calls stopped being answered.

What the PR does

  • ExternalLinkSucceeded() now sends 204 No Content and closes the response. A 204 also tells a browser following a plain <a href> to one of these endpoints to stay on the current page, which those links rely on. The tests' pretend request now matches.
  • Backports master's robustfile-hook: allow FileStream opt-out to 6.4's pre-commit check, and marks the deliberate shared-read FileStream already in RequestInfo.cs. Without it, no commit touching that file could pass the hook on 6.4.
