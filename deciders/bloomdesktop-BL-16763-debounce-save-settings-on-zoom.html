What this PR is about

Problem

While the user zooms the edit page with Ctrl+mousewheel, Bloom writes the whole user.config settings file to disk on every zoom step. A fast wheel spin makes many of those synchronous writes per second, all on the UI thread. This is not the root cause of the multi-minute freeze in BL-16762, but each write holds the UI thread longer, which widens the window in which the host-to-browser and browser-to-host calls collide.

What the PR does

EditingView.SetZoom no longer writes the settings file. It still applies the zoom to the browser at once, and it still updates the zoom value in memory at once, so nothing the user sees changes. A one-second timer now does the disk write, and each zoom step restarts that timer, so a whole wheel spin costs one write instead of one write per notch.

The pending write is also flushed at once when the user leaves the Edit tab, when the main window becomes inactive, and when the view is disposed. So a zoom made in the last second before any of those events is still saved.

Decisions

Should the browser-side throttle come into this PR too?

The multi-minute freeze this work came from has three cards. This PR is the second of them: it removes the repeated disk write. The first card, BL-16762, is the one that actually stops the flood of zoom requests, by counting wheel notches in the browser code and sending at most one request every 100 to 200 milliseconds. Until that lands, a fast wheel spin still makes one round trip to the UI thread per notch, so a user can still meet the freeze. A separate worktree already exists for it.

Is one second the right delay before the write?

The card suggested "a second or so". One second is long enough that a whole wheel spin costs one write, and short enough that the setting is on disk before a user could realistically do anything else. The cost of a longer delay is only the rare case where Bloom is killed, rather than closed, within the window; the cost of a shorter one is more writes during a slow, deliberate zoom with the buttons.
