What this PR is about

Problem

In apps built on Publish > Apps (Reading App Builder), text in Andika shows in the phone's own font, with a two-story "a" instead of Andika's single-story one. Other fonts work. A tester reported it on 6.5.101 Beta.

Cause

BloomPUBs never embed Andika, because Bloom Reader and other hosts supply it to bloom-player. A RAB app doesn't:

  • It ships Andika under names bloom-player never asks for (app-builders #2510).
  • RAB apps have no internet permission, so bloom-player's fallback (downloading Andika from bloomlibrary.org) fails even online.

What the PR does

A possible stopgap. The real fix belongs in RAB, and whether we want a Bloom-side fix at all is still undecided.

  • BloomPUBs made for an app now embed Andika like any other font, with only the faces the book uses. Other BloomPUBs are unchanged.
  • It fixes only apps built through Bloom. A BloomPUB added to RAB by hand still lacks Andika.
  • Text set in the older "Andika New Basic" isn't covered yet (decision 2).
  • A comment at the pinned RAB version says to remove this once Bloom moves to a RAB with the fix.

Andrew's phone showed Andika with an earlier version of this branch, which shipped one copy of Andika per app. The final version hasn't been on a phone. Its APK carries the faces the book uses, and the book's own Andika rules load last, so they win.

  • Two manual test cases now check Andika on an offline phone in their 6.6 runs: 831 Basic Install of RAB for Bloom and 799 Bloom Apps using stand-alone RAB. Both are manual.

1. Do we want a Bloom-side fix at all?

The real fix is RAB serving Andika under the names bloom-player asks for (app-builders #2510). We don't know when that will ship. This PR is a small stopgap. It only helps apps built from Publish > Apps, not BloomPUBs added to RAB by hand, and once RAB is fixed the app would carry Andika twice until we remove it.

2. Text set in "Andika New Basic"

Some books name "Andika New Basic", the font Andika replaced. Bloom and Bloom Reader quietly give such text Andika. A RAB app can't, so in an app that text still shows in the phone's font: the same symptom this PR fixes. Devin's thread is open on the PR.

The last report called this uncommon because "Bloom moved collections from Andika New Basic to Andika in 2022". That was wrong. Bloom never changed collections back. BL-7868 moved collections to Andika New Basic, and BL-11389 only started serving Andika when a book asks for Andika New Basic. So collections from those years probably still name it. I haven't measured how many.

3. Bring it to the release branches as well?

The tester hit this on 6.5.101 Beta. Publish > Apps is on both Version6.5 and Version6.4, and Apps fixes still go to 6.4 (BL-16959 is a [6.4] card). The BL-17007 card has no version prefix, so this PR targets master. If we merge the stopgap, users of those versions only get it through separate PRs.

4. The "installer exited with code 2" failure

The tester's log also shows Prepare failing with "Reading App Builder installer exited with code 2" (in RabProjectService.EnsureRabInstalledForPrepare), though a later build succeeded. It's unrelated to fonts and I didn't investigate it.
