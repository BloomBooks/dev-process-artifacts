What this PR is about

Problem

The nightly test of the fake fatal book titles still failed after #8774. The "Bloom encountered an error and needs to quit" dialog opened with Submit and Quit, but its message stayed empty and its details said "Loading...". A person who clicks Edit just as the Collections tab appears, on a book whose opening raises a problem, can meet the same empty dialog.

Cause

The dialog is raised inside the tab switch's API request, which holds Bloom's main API lock while the dialog shows. On the slow runner, the Collections tab was still being drawn when Edit was clicked. Every book button there asks Bloom for the editable collection's name, and that request waited for the lock. Ten of them waiting held the browser's six connections to Bloom, so the dialog's request for its message never got out.

What the PR does

  • The collection-name request no longer waits for the main API lock. It only reads a folder name, so it is answered at once even while a dialog holds the lock.
  • A new e2e test makes the slow runner's order happen every time. It holds the book buttons' questions until the dialog asks for its message, sends them on first, and checks that the dialog shows its message. Without the fix it fails just as the nightly did.
