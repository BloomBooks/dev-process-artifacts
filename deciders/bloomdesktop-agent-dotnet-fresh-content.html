What this PR is about

Purpose

The C# tests read appearance themes, appearance migrations, templates and branding from output/browser, which only a front-end build fills. A worktree moved to another release branch kept the old branch's copies there, and the full C# suite failed 18 appearance tests, with nothing pointing at the stale build output. This PR makes the agent test wrapper bring those files up to date from the current checkout before every test run.

What the PR does

  • build/agent-dotnet.sh and .ps1 run src/content/scripts/copyContentForCSharpTests.mjs before dotnet test. If it fails, including when node is missing, the wrapper prints "TEST RUN NOT STARTED" and exits 1. Other dotnet commands are unchanged.
  • The script writes the same 779 files that the four src/content copy scripts produce, but only those whose content differs, each through a temporary file and a rename. It deletes folders this checkout does not have, and in the theme and migration folders, files it does not have. It needs only node and takes under a second.
  • It is safe while other test runs (including other copies of itself) and a running Bloom read output/browser. A stale folder that something holds open is left with a warning.
  • src/BloomTests/AGENTS.md describes the step.

Worth knowing

  • A file inside output/browser/templates or branding with no source counterpart is kept, because the full build compiles CSS from LESS into those folders. A stray file like that, left from another branch, stays until the next full build. Whole folders are removed.
  • The step writes the shared output/browser that a running Bloom from the same worktree reads. It changes only files that differ from this checkout.
