What this PR is about

Problem

Bloom kept shipping bugs that appear only when Windows uses another regional format. Comma decimals left pictures uncropped in French (BL-15064), Turkish casing broke file names (BL-16754), and Thai collation broke language names, picture credits and URL handling (BL-16932, BL-16806, BL-16945, BL-16926). Each fix covered one call site, and some of the bugs were inside libpalaso and TagLib#, where Bloom can't fix the call.

Cause

.NET formats, parses and compares text using the process's culture, which by default is the user's regional format. Every call that doesn't name a culture, in Bloom or in a library running in Bloom's process, silently uses it for machine data too: CSS sizes, version numbers, file names, tool arguments.

What the PR does

  • Bloom runs in the invariant culture. The first thing Main does is save the user's regional format in UserCulture.Current and switch to invariant. BloomPdfMaker and BloomFreezeDoctor do the same. Bloom's display language is untouched.
  • What the user sees still uses their format: Bloom Library and Team Collection dates, the About dialog's build date, file sizes and the Sign Language tool's video statistics, the language list separator, and the order of book titles and fonts.
  • Guard rails. A banned-API analyzer makes it a build error in BloomExe to read or set the process culture, or to use culture-sensitive comparisons or the short-date helpers. A check on every API request reports it if a library ever changes the culture.
  • Workarounds removed: IetfLanguageTagExtra (libpalaso fixed this in BL-16947), CommandLineRunnerExtra, TagLibCultureFix, and the culture switching around starting ffmpeg. That switching never reached the child process: a test confirmed child processes always get the machine's culture.
  • Tests run as Bloom does. BLOOM_TEST_CULTURE now sets the user's culture, so the weekly culture sweep tests what users actually run.

Worth knowing

  • Nobody has yet run this build by hand with Windows set to a French, Thai or Turkish format. The unit tests cover the code paths, but the test ideas on the card are the first real check of what a user sees.
  • Numbers and dates that nobody moved to UserCulture.Current now show English-style. The one known case is line spacing in the New Collection wizard and the older font-settings dialog (1.5 rather than 1,5). It still saves correctly, and the plan accepted it.

Decisions

A card for the Bloom Harvester follow-up

Bloom Harvester (BloomBooks/bloom-harvester) runs some Bloom code inside its own process: book analysis, font checks and book download. Until its Main calls Bloom.UserCulture.UseInvariantCulture() first, that code keeps using the server's culture. Its main harvesting work runs Bloom.exe as a separate program, which already runs invariant. Nothing breaks without the change, and the details are in a comment on BL-16981. The risk is that the note gets lost once BL-16981 closes.
