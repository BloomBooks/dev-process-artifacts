What this PR is about

Problem

lameta's renderer reached into the main process through @electron/remote for its menus, right-click menus, app paths, window title, window events, the save dialog, and quitting. @electron/remote is no longer maintained, so every Electron upgrade risks breaking all of these at once.

What the PR does

  • Everything the renderer did through @electron/remote now goes over IPC, through src/mainProcess/windowIpc.ts and src/other/windowIpc.ts. The package is removed.
  • Menus. The renderer sends menu templates in which each click callback is replaced by a number, and the main process sends back the number of the item that was clicked. A click on a menu that has since been replaced does nothing.
  • Spell-check context menu. The main process forwards the right-click event, and the renderer asks it to cut, copy, paste, replace a misspelling, or add a word to the dictionary. HomePage used to register a new right-click listener on every update. There is now a single handler, so one right-click shows one menu.
  • Settings store. UserSettings reads the renderer's runtime environment instead of the main process's. Both hold the same values, and Vite's build-time replacement of NODE_ENV can't reach it there.
  • Right-click file menu. It now decides which items to show from the file that was right-clicked. Before, it used the previously selected file, so right-clicking a file while the session's .session file was selected left out Rename and "Open in program associated with this file type".
  • New E2E spec. e2e/mainProcessIntegration.e2e.ts covers each of these. It passed against the old remote-based code before the change. It replaces e2e/addToDictionary.e2e.ts, which looked for a file lameta never writes and so checked nothing.

The first commit only formats the files that the change touches, because the pre-commit hook formats every touched file. The commits after it hold the change.
