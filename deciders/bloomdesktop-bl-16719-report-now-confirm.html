What this PR is about

Problem

While testing the Freeze Doctor, holding CTRL to reveal the "Report now" button and pressing it on a Bloom that was running normally created a real tracker card at once, with no warning. The test notes promised a confirmation dialog first. The dialog appeared only when Bloom had been artificially frozen with the simulator.

Cause

The window asked for confirmation only when the Doctor had a reason of its own not to file: a developer build, an attached debugger, a simulated failure, or a recent problem report from Bloom itself. A healthy Bloom on a BetaInternal build has none of those, so the list was empty and the report was gathered and filed on the click. The simulator adds a reason, which is why the dialog did appear in the frozen case.

What the PR does

  • "Report now" now always asks before filing, with No preselected, whatever Bloom's state or channel.
  • The dialog lists everything the click overrides. A new reason is added when the Doctor sees nothing wrong with the watched Bloom, or when Bloom has only just stopped answering and is not yet judged frozen. The existing filing guards follow.
  • The dialog names the tracker project the card would land in, matching what "Send it anyway" already does.
  • After a Yes, the window checks that the Bloom it asked about is still running, by process id and start time, before gathering. A Bloom that exited while the question was open, or a replacement Bloom the Doctor has since adopted under the same id, is not reported on (StatusForm.cs).
  • The wording is composed in a new Core class, ReportNowConfirmation, covered by unit tests without a window.

The CTRL-key reveal of the button itself is unchanged; that is by design.
