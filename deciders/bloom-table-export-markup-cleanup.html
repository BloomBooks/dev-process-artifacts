What this PR is about

Problem

A host that saves the document while the user goes on editing has no safe way to clean a table’s edit-time markup out of what it saves. The exported cleanup, removeTableEditingArtifacts, also ends Paint Format and Border Brush mode, so calling it on every save would knock the user out of Paint Format after the first painted cell. Bloom now saves a copy of the page on every change (BloomDesktop#8209), so it has had to keep its own copy of bloom-table’s list of markup to strip, which will drift as bloom-table adds edit-time markup.

What the PR does
  • Exports the markup-only half of the cleanup as removeTableEditingMarkup(root). It changes nothing but root’s DOM, so it is safe on a detached copy. removeTableEditingArtifacts and Copy Table’s tableMarkupForClipboard call it as before.
  • It now also cleans root itself when that is the table or a cell. Before, it only visited descendants, so a host passing the table kept the table’s selection classes.
  • It recognises an element from another frame (an iframe’s table cleaned from its parent’s module) by node type rather than instanceof, which is false across frames.

Worth knowing

  • The cross-frame case has no test. The test DOM has one realm, so it cannot make an element from another frame; the fix is a node-type check instead of instanceof.
  • Bloom is waiting on the release. BloomDesktop#8209 will switch to removeTableEditingMarkup once dist-v0.1.2 exists, and is being held open until then.

Merge and release?

The change only adds an export and makes the cleanup cover its root; nothing stripped before is kept now. Bloom needs it released to drop its own copy of the list. Releasing is the Release workflow with a patch bump, which publishes dist-v0.1.2.
