What this PR is about

Problem

Bloom offers “Edit with AI…” on a picture, but the item was greyed out on an empty picture box. An empty box is exactly where a user most wants the AI: there is no picture yet, and the editor can make one from a description. Testing that surfaced two more problems: on a page with several pictures, an accepted image could land in the wrong box, and an accepted image could not be undone.

What the PR does

  • “Edit with AI…” is enabled on an empty picture box. A broken picture stays greyed out.
  • Each box Bloom sends carries a name for the user to read: “Page 3”, the page’s own name for front and back matter, “Page 3 - Canvas Background” for the picture behind a page, and “Page 3 - Image 2” for the pictures on top of it. Every empty box looks the same in the editor, so without a name a user with two empty boxes on one page cannot tell which is which. A page with several canvases numbers them all, so a Picture Dictionary page does not show six boxes called “Canvas Background”.
  • An accepted image now lands in the box the user chose. The page applies each replacement at the box’s position on the saved page, with the file name as a cross-check, instead of by file name alone (nine empty boxes all share placeHolder.png, so file name alone picked the first one).
  • Accepting an image is now undoable, like Paste Image. The page is no longer saved immediately after an accept, because that save discarded the undo.
  • The editor half lives in bloom-ai-image-tools, pinned as dist-v0.1.7: each dummy image now shows its box’s page label in a random high-contrast color, the launched box’s thumbnail gets a wider, brighter border, and the strip scrolls that thumbnail into view when the editor opens.

Worth knowing

  • The risky paths were exercised in a real Bloom during this run’s development: creating and accepting images on a page with six pictures (the accepted image landed in the chosen box), and undo after an accept.
  • Undo reaches back one editor session. Each “Edit with AI…” launch saves the page first, and a save ends what undo can reach. That is deliberate, matches other image operations, and is recorded in the card’s test ideas so a tester does not file it.
  • The retry path — accepting again after a partial commit failure — is covered by unit tests only; nobody has forced a partial failure in a real Bloom.
