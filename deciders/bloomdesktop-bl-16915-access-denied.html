What this PR is about

Problem

A user on Bloom 6.4 could not select a book. Writing license.png failed with "access denied", and writing the QR code picture failed with a GDI+ "generic error", which stopped book selection. The ACLs allowed the write and ReadOnly was off, so the existing diagnostic explained nothing. The card blamed antivirus, with no evidence either way.

Investigation

In one book update Bloom writes license.png twice (two calls that set the license metadata), overwriting in place each time. It deletes the file only when the license has no image. The QR code picture is only ever overwritten. So Bloom does not delete and recreate these files in one pass, and a file left "delete pending" by Bloom is not the cause. The reporter's machine had Avast with real-time protection on and Defender passive; that shows what was running, not that Avast blocked the write.

What the PR does

  • The shared file-error report (PNGs, support files, service keys, so any file-write refusal gets this) now records whether the file exists, full file and folder attributes including cloud-placeholder flags, whether a read-only open works, the innermost sync-provider folder containing the file, Defender's Controlled Folder Access setting, and each antivirus product's real-time protection state. It is read-only and never throws.
  • The PNG failure message names a suspect only when that evidence supports it: Controlled Folder Access on, or a sync provider or cloud placeholder. Otherwise it names none.
  • A failed QR code write is now a small nonfatal notice, so the book still opens. The badge then shows no QR code, rather than a broken image or an old code that leads to a different page.
