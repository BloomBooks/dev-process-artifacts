What this PR is about

Problem

Each page of the new React Collection Settings dialog took its own set of props, and the dialog held logic for particular pages: the subscription code's own state, its seeding, reset and merge into the saved values, the placeholder pages, and a table of help topics by page. Every new page added more of that to the dialog.

What the PR does

  • One contract for every page. Each page is a hook that takes an ISettingsPageContext (whether the dialog is open, the loaded settings, the values as typed and as they would be saved, and editValues for an editor that is not a Config-R control) and returns an ISettingsPage (its ConfigrPage and its help topic). The dialog builds the context once and lists the pages.
  • One generic state for values edited outside Config-R, replacing the subscription code's own state.
  • Placeholder pages and help topics move onto the pages, replacing collectionSettingsHelpTopic.ts.
  • The Subscription page's block is wrapped in ConfigrStatic, as the other pages' blocks are, ending a React warning.

No behavior change. Values whose editors are not Config-R controls stay outside Config-R: binding a full-width block to a Config-R value would need a kind of component that does not fit Config-R's row-per-setting design.
