What this PR is about

Purpose

A table's text cells show every language the toolbar has turned on, so a word list cannot have one column in the local language and the next in the national language. This lets the user choose which languages a text cell shows, for a cell, a row, a column or the whole table, using the meanings Bloom already gives a translation group's languages, with no change to the C#. It is the second of three PRs for BL-17105; the first is merged, and the third makes table cells independent of the toolbar.

What the PR does

  • A Languages item in the Cell, Row, Column and Table menus, with one check box per language, a dash where only some covered cells show it, and the last language of a cell locked.
  • The choice is stored as roles (V, N1, N2) in data-default-languages, which page load, publishing and Bloom Player already read. New cells show L1 only; older cells keep the toolbar's languages.
  • A change is one undo step. Boxes a cell gains are set up, and showing boxes re-tagged, in one pass for every cell changed; the cells a table operation announces are wired together.
  • A cell's languages travel into new rows and columns and through Paint format and Copy/Paste properties, including a copy made before the collection's languages have arrived (saving waits for it).
  • A table cell can take inline pictures wherever the table is, while a text overlay on an image cell's picture stays canvas text.
