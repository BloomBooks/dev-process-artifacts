What this PR is about

Problem

The new React Collection Settings dialog showed only a placeholder on its Team Collection page. Users still had to use the old WinForms dialog to see a Team Collection's shared folder, edit its administrators, or turn a collection into a Team Collection.

What the PR does

  • The page reuses the old tab's panel, including the experimental warning and the subscription overlay. The WinForms tab and its Create dialog keep working.
  • Administrators are edited through the dialog's page context and, in a Team Collection, checked with the front end's email check: an invalid list shows a message and the page tells the dialog it can't save, so OK is disabled. An address saved earlier under C#'s looser rule, such as admin@intranet, must be fixed first.
  • Create a Team Collection opens the existing Create dialog in the browser. Its Create & Restart saves the user's other edits, then C# creates the Team Collection and Bloom restarts. The Team Collection subscription rules apply (no Pro code), and an expired subscription's bookshelf stays in the file.
  • No create while a rename is unsaved: the Team Collection would get the old name, which is also the name the Create dialog asks the user to approve.
  • The page is hidden when the feature is off (as saved) and this is not a Team Collection, and for a Bloom Library book downloaded for editing.
