What this PR is about

Problem

The new React Collection Settings dialog showed only a placeholder on its Team Collection page. Users still had to use the old WinForms dialog to see a Team Collection's shared folder, edit its administrators, or turn a collection into a Team Collection.

What the PR does

  • The page reuses the old tab's panel, including the experimental warning and the subscription overlay. The WinForms tab and its Create dialog keep working as before.
  • Administrators are kept by the dialog (like the subscription code) and, in a Team Collection, checked in the browser with the front end's existing email check. If they are invalid, the field says so and OK is disabled. That check is a little stricter than the C# one, so an address saved earlier such as admin@intranet must be fixed before the settings can be saved. A change is saved by Apply and needs a restart.
  • Create a Team Collection opens the existing Create dialog in the browser. Its Create & Restart has the settings dialog save the user's other edits; then C# creates the Team Collection and Bloom restarts. The edits go first so they reach the shared copy, and the Team Collection subscription rules apply (no Pro code).
  • No create while a rename is unsaved. A rename only happens as Bloom restarts, so the Team Collection would get the old name, which is also the name the Create dialog asks the user to approve. Create is disabled with a note to save the rename first.
  • The page is hidden when the feature is off (as saved) and this is not a Team Collection, and for a Bloom Library book downloaded for editing.
