What this PR is about

Problem

When things added with the Canvas tool overlap on a page, whichever was added last is drawn on top, and there has been no way to change that. A user who wants a caption in front of a picture added later, or one bubble tucked behind another, has had to delete and re-create elements in the right order. Requested on the community forum; tracked as BL-15992.

What the PR does

  • Adds a Layer submenu to the canvas element menu (the "..." button and the right-click menu), in its own group just before Duplicate and Delete, with Bring Forward (Ctrl+]), Bring to Front (Ctrl+Alt+]), Send Backwards (Ctrl+[) and Send to Back (Ctrl+Alt+[). The shortcuts work whenever an element is selected and text is not being edited; they accept either the physical bracket keys or the bracket characters, so they also work on layouts where the brackets live elsewhere (an AltGr-typed bracket counts as the one-step shortcut).
  • The submenu is hidden for the background image, which always stays at the back, and disabled when the selected element is the only one that could move. Forward commands are disabled at the front of the stack, backward ones at the back.
  • Stacking order is the DOM order of the elements, while Comical draws and hit-tests bubbles by a separate stored level. A new CanvasElementZOrder module moves the element in the DOM and then renumbers every level to match, background first, before asking Comical to redraw. A parent bubble and its child bubbles move together as one unit; a family that had become scattered is gathered next to its parent first, so every move is exactly one step. On game pages, draggable pieces and fixed pieces only reorder among their own kind, matching the existing rule that draggables stay on top; a family with any draggable member counts as draggable. The game code that pushes draggables to the top now shares the level-renumbering helper.
  • Nested menu rows can now be disabled (the shared nested menu item previously ignored disabled), five localizable strings are added, and unit tests cover the moves, the menu, and the shortcuts.
  • Updates comicaljs to 0.4.2 (comical-js #121): Comical used to leak the previous generation of bubble objects each time Bloom turned editing back on, and after a level renumbering a stale family bubble threw inside Comical, which surfaced as a "JavaScript error" toast on any Layer move on a page with a child bubble.

Worth knowing

  • Text boxes, bubbles and videos are always drawn in front of pictures. That is existing, deliberate CSS (so a bubble's tail can point at something in a picture), so a Layer command on a picture that overlaps only text has no visible effect. The QA notes on the card say so explicitly.
  • Checked in a running Bloom from this branch. Menu placement and icons, greyed-out items at the top and bottom of the stack, no Layer item on the background image, the shortcuts, and a parent/child bubble family moving as one unit all behave as described. Two things seen along the way: a nested submenu stays on screen after you pick an item in it, which the existing audio submenu also does; and on a page with a child bubble, a Layer move shows a "JavaScript error" toast (the move itself completes). That toast was a latent ComicalJS bug, fixed in comical-js 0.4.2, which this PR now uses; re-checked in a restarted Bloom serving 0.4.2, the same family moves raise no error.
  • Level renumbering touches every element on the canvas. After any Layer command, and on game pages when draggables are pushed to the top, all bubble levels are rewritten to a dense 1..n in DOM order. On an old page whose stored levels disagreed with the DOM this changes which bubble outline is drawn on top the first time, which is the intended repair.
