What this PR is about

Problem

When canvas elements (pictures, speech bubbles, text boxes, videos, buttons, tables) overlap on a page, whichever one was added last is drawn on top, and there has been no way to change that. A user who wants a caption in front of a picture they added later, or one bubble tucked behind another, has had to delete and re-create elements in the right order. Requested on the community forum.

What the PR does

  • Adds a Layer submenu to the canvas element menu (the "..." button and the right-click menu), just before Duplicate and Delete: Bring Forward (Ctrl+]), Bring to Front (Ctrl+Shift+]), Send Backwards (Ctrl+[), Send to Back (Ctrl+Shift+[). The shortcuts work whenever an element is selected and you are not typing in it, also on layouts that type brackets with AltGr.
  • Hidden for the background image, which always stays at the back. Each command is greyed out when the element cannot move that way, and the whole submenu when nothing can move.
  • Moves the element in the page and renumbers the bubble drawing order (ComicalJS levels) to match, so what is drawn and what a click hits agree. A bubble and its child bubbles move as one. On game pages, draggable and fixed pieces only reorder among their own kind.
  • Updates comicaljs to 0.4.2, which stops a "JavaScript error" when moving a bubble that has a child.
  • An e2e test, canvas-layer-order.spec.ts (Notion test case 840), drives all of this in a real Bloom.
