What this PR is about

Problem

BloomPUB preview and publishing failed with "The file '…\ai-image_r.jpg' already exists" for some books. The book in the report had been through bulk AI image edits, but any book with two images whose names differ only by extension (foo.png and foo.jpg) could hit it.

Cause

When publishing resizes or converts an image, the output was named from the source's name without its extension, plus a mode suffix (_r, _t, _tf) and the new extension. A resized ai-image.jpg and an ai-image.png converted to JPEG therefore both became ai-image_r.jpg, and the second copy threw.

What the PR does

  • Output names come from the existing ImageUtils.GetUnusedFilename, which adds a counter when the name is already in the book folder (ai-image_r1.jpg). That also protects a book image that already has the output name.
  • Two end-to-end tests: a book with photo.jpg and photo.png (test), and a book whose own photo_r.jpg has the name a resized photo.jpg would get (test).
