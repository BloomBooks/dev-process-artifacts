What this PR is about

Problem

BloomPUB preview and publishing fail with "The file '…\ai-image_r.jpg' already exists" for some books. The book in the report had been through bulk AI image edits, but any book with two images whose names differ only by extension (foo.png and foo.jpg) can hit it.

Cause

A book folder can legitimately hold ai-image.png next to ai-image.jpg. When it picks a new name, Bloom checks only the full name, and the AI image editor creates exactly such pairs. When publishing resizes or converts images, each output was named from the source's basename, a mode suffix (_r, _t, _tf) and the new extension. That drops the source's extension, so a resized ai-image.jpg and an ai-image.png converted to JPEG both became ai-image_r.jpg, and the second copy threw.

What the PR does

  • Output names come from the existing ImageUtils.GetUnusedFilename, which adds a counter when the name is already in the folder (ai-image_r1.jpg). This also protects a book file that already has the output name.
  • The same image used twice in the same mode is still processed once and shares one output file.
  • Unit tests publish a book containing photo.jpg and photo.png (test), and a book whose own photo_r.jpg has the name a resized photo.jpg would get (test). Without the fix, the first fails with the reported error.
