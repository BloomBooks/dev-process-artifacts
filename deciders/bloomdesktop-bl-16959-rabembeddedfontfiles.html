What this PR is about

Problem

In Publish > Apps, Build fails inside Reading App Builder with A required file for this app is missing: CharisSIL-Regular.ttf whenever a book embeds a font other than Andika (e.g. English in Charis SIL). The font is installed and Bloom embeds it in the BloomPUB.

Cause

On every Prepare/Build, Bloom adds each font embedded in the BloomPUBs to the RAB .appDef, by bare file name. RAB looks for those files only in <project>_data\fonts, and it copies font files there only when it creates a project. Nothing put Bloom's embedded fonts there, so any embedded font added after the project existed broke the build.

What the PR does

  • After updating the .appDef fonts, Bloom extracts each embedded font file (every face — Regular, Bold, Italic… — has its own file) from the BloomPUB into <project>_data\fonts, replacing an older copy (CopyEmbeddedFontFiles).
  • If a BloomPUB's fonts.css names a file the BloomPUB doesn't contain, Build stops with a message naming it, instead of a Java stack trace from RAB.
  • Files of fonts no longer used are left in place: RAB packages only the fonts the .appDef lists, and RAB itself may have put files in that folder.
  • Unit tests cover the copy (multiple books, Bold face, overwrite, missing file) and the Build path end to end with the fake RAB.
