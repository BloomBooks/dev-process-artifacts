What this PR is about

Problem

When a book in Publish > Apps embeds a font other than Andika (e.g. English in Charis SIL), the font never reaches Reading App Builder's font folder. With the Reading App Builder for Bloom 14.0 that Bloom installs, the build succeeds but the font is silently left out of the app's font set. With RAB 14.5+ the build fails with A required file for this app is missing: CharisSIL-Regular.ttf, and Bloom then says "Build complete." and offers the previous build's APK, so "Try on phone" would install a stale app.

Cause

  • Bloom adds each embedded font to the RAB .appDef by bare file name, but never puts the file in <project>_data\fonts, the only place RAB looks at build time. RAB copies fonts there only when it creates a project. RAB 14.0–14.4 skips a font whose file is missing; since 14.5 (app-builders commit cbb19ce73) that stops the build.
  • RAB's failures never reached Bloom. rab.bat runs Java and then ends with GOTO :EOF; a batch file that ends that way under cmd /c makes cmd.exe exit 0 even when Java exited 1. Bloom then took whatever APK was in the folder as the result.

What the PR does

  • On every Prepare and Build, Bloom extracts each embedded font file (each face has its own file) from the BloomPUB into <project>_data\fonts, replacing an older copy. A BloomPUB that names a font file it doesn't contain stops Build with a message naming it. Files of fonts no longer used are left alone.
  • Bloom runs RAB as cmd /d /c ""rab.bat" -i <args> & exit /b", so RAB's exit code comes through for every RAB command (call would also work, but it doubles any ^ in a path). A failed build now shows RAB's output followed by "Build failed: cmd.exe exited with code 1."
  • Build accepts only an APK written after its build command started (with a 2-second margin for file-time precision).
  • The opt-in real RAB build test now checks that each font the .appDef lists is in the fonts folder and among the APK's app fonts, so it catches the silent 14.0 case too.

Worth knowing

  • Exit codes now come through for every RAB command, so a RAB step that used to fail silently would now stop Prepare or Build. The real RAB test (full setup and build) exits 0 at every step on 14.6.
  • On 6.4 the real RAB test fails under agent tooling with "'buildapp.bat' is not recognized", because the Claude Code CLI sets NoDefaultCurrentDirectoryInExePath. 6.5's test clears it (commit 0a0b30bbd1), but 6.4's doesn't. Run it with that variable removed. Before this PR the same failure was hidden by the lost exit code.
  • The live checks in a running Bloom were done on the 6.5 version of the fix; the 6.4 version was verified through the tests above.

RAB's lost exit code

rab.bat ends with GOTO :EOF, which hides RAB's exit code from any caller that uses cmd /c. It should end with exit /b %ERRORLEVEL%. This PR doesn't depend on that, but other callers would benefit.
