What this PR is about

Problem

Text hyperlinks vanish from books. In 6.5, opening a book in Edit mode is enough: every link the author made with "Set Up Hyperlink" turns into plain, non-clickable text, and once the page is saved the loss is permanent. Publishing from 6.5 does the same to the published copy, and because the harvester runs 6.5 code, books uploaded from any Bloom version lose their links on Bloom Library. Reported by a user whose freshly uploaded book had no working links even though they worked in the editor.

Cause

BL-16387 (6.5) added a cleanup pass to the bring-book-up-to-date code that strips every attribute from any non-span element inside an editable paragraph, to tidy stray formatting markup. A hyperlink is an <a href> inside the paragraph, so its href went with the rest.

What the PR does

  • The attribute cleanup now leaves a elements alone as well as span elements, so links keep their href while the stray-formatting cleanup still runs on the markup around and inside them (Book.cs:2774).
  • A unit test covers a paragraph containing a link that wraps styled bold text: the link survives and the bold markup is still normalized (BookTests.cs:3224). It fails against the old code.
  • Verified end to end in a dev build: set a link in Edit mode the way a user would, saved, reopened the book, restarted Bloom. The href is intact in the DOM and in the saved file, while the same pass still stripped a stray colour attribute next to it, so the cleanup provably ran.

Books already opened in a 6.5 build have lost their links in the saved HTML. This fix stops further damage but cannot restore them.

Worth knowing

  • Other attribute-bearing inline elements inside a paragraph (an img, a sup with an id) are still stripped. That is the pre-existing BL-16387 behaviour, unchanged here, and no user-made markup we know of relies on it.
  • Setting a link on text that is already a link nests a second anchor rather than replacing it. Pre-existing editor behaviour, seen while verifying, not part of this fix. It is noted in the test ideas so a tester does not file it against this PR.
