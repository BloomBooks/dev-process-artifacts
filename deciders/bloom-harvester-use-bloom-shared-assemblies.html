What this PR is about

Purpose

The harvester declared its own NuGet packages for libraries that Bloom also ships (SIL.Core, Newtonsoft.Json, AWSSDK, RestSharp, CommandLineParser and others). The build copies the harvester's packages over Bloom's copies in the output folder, so Bloom.exe ran on the harvester's versions. Every Bloom upgrade meant re-matching those pins by hand, and Bloom 6.6 (BloomDesktop master, about to go to the dev harvester) would have needed another round: SIL.Core 18.0.0, Markdig 1.4.0, System.Text.Json 10.

What the PR does

  • Both projects now compile against the copies Bloom ships in lib/dotnet, through one new src/Directory.Build.props. Their versions always follow the Bloom we build against.
  • It references every System.*.dll Bloom ships, so the compiler uses Bloom's newer copy rather than the .NET 8 framework's (that conflict was a build warning).
  • The harvester's own package list drops to two, ImageHash and ApplicationInsights, which Bloom doesn't ship. Autofac, System.CodeDom, System.Configuration.ConfigurationManager and System.Drawing.Common were never used directly and are gone.
  • AWSSDK now comes from Bloom too, at 3.5 instead of the 3.7 that the .NET 8 port picked. Nothing needed 3.7. Every AWSSDK 3.x assembly reports the same version number, which is why the mismatch never errored.
  • Adds AGENTS.md, which names the project's tracker and points to the README and ci.yml for building.
