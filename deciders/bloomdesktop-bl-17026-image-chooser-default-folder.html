What this PR is about

Problem

In the new image chooser, "Open file" always opens the Pictures folder, so every image costs extra navigation. The old image toolbox opened the folder the user last picked from. A forum user reported it (thread).

Cause

The dialog's starting folder was hard-coded to Pictures. That overrides both Bloom's memory and Windows' own memory of the last folder used.

What the PR does

The image picker now uses FilePathMemory, the same way the music and generic file choosers do:

  • After a pick, it remembers the chosen file's folder under its own tag (ChooseImage), and the next "Open file" in the same Bloom session starts there. The GIF-only picker uses the same code.
  • With nothing remembered (the first pick after starting Bloom), the starting folder is left unset, so Windows opens the last folder Bloom's file dialogs used.
