What this PR is about

Problem

Bloom could make a full-bleed PDF at only six paper sizes (A5, A4, A3, USComic, HalfFolio, Size6x9), each hard-coded in C#. The edge-to-edge theme lets a book at any size run its pictures to the paper's edge, so printing it with bleed needs every paper size to work. Page dimensions were also parsed separately by each part of the code that needed them.

What the PR does

  • One source of page sizes. The front-end build writes output/browser/pageSizesLookup.json from DistFiles/pageSizes.json: every layout's width and height in millimeters, plus base names (A4), ISO A/B sizes and square sizes. SizeAndOrientation reads it. ePUB page dimensions and PDF full-bleed sizes now come from it instead of their own parsing and the hard-coded list.
  • Full bleed at every paper size. Letter, Legal, B5, A6, Cm13 and the other paper sizes now offer full bleed. Device, Ebook and PictureStory layouts are screen shapes and still don't.
  • Explicit trim and bleed boxes. Before handing a full-bleed PDF to dotImpose, Bloom writes each page's trim and bleed boxes itself. It uses dotImpose 2.6.8 (a release from nuget.org) and its NullLayoutMethod(), which reads those boxes.
  • Booklets and crop marks. Booklet layouts keep trim-sized source pages. Crop marks turn on automatically when printing with bleed.
